# 개발과 테스트

## 헤드리스 검사

프로젝트 루트에서 실행한다. .NET 10 SDK, Python 3, 로컬 Unity 6000.3.21f1(다른 경로는 `-p:UnityEditorPath=...`)이 필요하다.

```powershell
rtk proxy dotnet run --project Tests/Defense/Defense.Check.csproj         # 전투·프로그램·캠페인·학습·Stage 1 코드
rtk proxy dotnet run --project Tests/EditorOptions/EditorOptions.Check.csproj
rtk proxy dotnet run --project Tests/BlockCoding/BlockCoding.Check.csproj  # 블록 컴파일러
python -I Tests/Defense/check_stage1_content.py                            # Stage 1 JSON ↔ Markdown, 생성 Python 실행
python -I Tests/BlockCoding/check_python.py
python -I Tests/BlockCoding/check_tree_python.py
```

- `check_stage1_content.py`는 `Defense.Check`가 임시 폴더에 쓰는 `CodingGame-StageOne-generated.py`를 읽으므로 `Defense.Check` 다음에 실행한다.
- Stage 1 콘텐츠 원본은 `Assets/!_Project/Defense/Tutorial/Stage1/*.json`이다. `Docs/stage1_flow/*.md`는 읽기용이며 검사가 두 쪽이 일치하는지 확인한다.

## Unity Play Mode 검사

`Defense.unity`를 Play Mode로 실행한 상태에서 Unity MCP로 실행한다. 실행 방식(`run_script` 진입점 / `eval_file` / `Unity_RunCommand`)은 각 파일 첫 줄 주석을 따른다. 대부분 새 Play Mode 세션이 필요하다.

| 파일 | 확인 내용 |
|---|---|
| `Tests/Unity/StageOneFlow.playmode.cs` | Stage 1 전체 흐름(`StageOneFlowCheck.Main`), 누출 실패 흐름(`StageOneFlowCheck.Failure`). 각각 새 세션 |
| `Tests/Unity/TutorialPosition.playmode.cs` | 대화창 위치 |
| `Tests/Unity/CampaignFiveStagesCheck.cs` | 25웨이브 진행·보상·스테이지 전환 |
| `Tests/Unity/RobotInteractionCheck.cs` | 행동 메뉴, 레벨업 비용, 개발·회수, 미리보기 조작, 개발자 전체 지급 |
| `Tests/Unity/PlacementFeedbackCheck.cs` | 설치 제한·실패 알림 |
| `Tests/Unity/VariableInputCheck.cs`, `CommandPaletteCheck.cs` | 변수 참조 입력, 팔레트 |
| `Tests/Unity/MeleeTargetCheck.cs`, `MeleeHitRangeCheck.cs`, `HitEffectsCheck.cs`, `PreviewEffects.playmode.cs` | 근접 판정, 피격 범위, 이펙트 |
| `Tests/Defense/Preview.playmode.cs` | 코드 미리보기 |
| `Tests/BlockCoding/Drag.playmode.cs`, `History.playmode.cs`, `Snap.playmode.cs` | 블록 드래그, Undo/Redo, 스냅 |

Stage 1은 로봇과 배치를 학습용으로 잠그므로 Stage 1 흐름 외 검사는 샌드박스로 시작한다.

```csharp
battle.EditorStartSession(stage, wave, false, new DefenseTestOptions { tutorial = false, tutorialInput = false /*, inventoryLimit = false, unlockAll = true */ });
```

## 개발 에디터

Unity 메뉴 `CodingGame > 개발 에디터`. 활성 씬의 `DefenseBattle` 하나와 연결된 캠페인 asset을 읽는다. 창을 여는 것만으로는 아무것도 수정하지 않는다.

- **Edit Mode**: 원본 asset을 Undo 가능하게 편집하고 `원본 저장`으로 저장한다.
- **Play Mode**: 복사본을 편집하고 `적용`으로 실행 중 수치를 바꾼다(체력은 최대치로 초기화, 위치·코드·인벤토리 유지). 스폰 항목 추가·삭제·경로 변경은 재시작 필요. `수치 적용 확정`은 원본 asset까지 저장한다. 확정하지 않은 값은 종료 후 `Play 변경값 비교`에서 확정·폐기한다.
- 일반 Play는 개발툴 없이 실행된다. `Play 시작 (개발툴 포함)`은 선택한 세션 조건·테스트 옵션을 적용한다.

| 탭 | 기능 |
|---|---|
| 세션 | 시작 stage-wave, 이전 스테이지까지 보상 지급, 시작·정지·한 틱·배속, 보상·다음 단계, 시나리오 저장·실행 |
| 밸런스 | 로봇·적 수치, 설치 제한, 강화, 공격 횟수 계수, 호환표, 성장 규칙, 거리별 피해·DPS |
| 캠페인 | 스테이지별 웨이브(적·수량·경로·지연·간격), 제한시간 |
| 보급·해금 | 초기 재고·코인, 준비 보급·종료 보상·드랍, 개별·전체 지급, 현재 재고 |
| 테스트 ON/OFF | 학습·입력 제한·코드·스폰·이동·공격·피해·제한·지급·표시 옵션, 정상값 복원 |
| 튜토리얼 | 시퀀스 편집·실행, 대상 연결, 입력 가림 검사 |
| 블록·미리보기 | 로봇 ID로 편집기 열기·적용·Undo/Redo, 생성 코드·실행 결과 |
| 진단·검증 | 설정 검사, 캠페인 1~5 자동 실행, 헤드리스 검사 실행, 결과 JSON(`TestResults/Editor/`) |

- `이전 스테이지까지의 보상`은 앞 스테이지의 보급·보상만 합산한다. 과거 처치 코인과 사용량은 재현하지 않는다.
- 시나리오는 stage-wave, 재고, 코인, 로봇 배치·레벨·체력·코드, 옵션을 저장한다.
- `캠페인 1~5 실행`의 자동 배치는 기능 검사용이며 최적 전략이나 실제 UI 조작 검증이 아니다.
- 계산 옵션은 다음 틱, 표시 옵션은 즉시 적용된다. 스폰 OFF는 스폰 시계를 멈춘다.

## 게임 내 개발자 모드

F1(또는 F2)로 개발자 화면(`DefenseCanvas`)을 연다. 학습 중에는 막힌다. 전체 지급 버튼(`GrantAll`)은 누를 때마다 로봇 각 10대, 블록 각 50개를 더한다.

## 알려진 공백

- 실제 사람의 마우스 플레이 테스트 기록이 없다. Play Mode 검사는 입력 주입과 고정 틱 진행이다.
- Stage 2~5 콘텐츠와 기획 의도(3스테이지, 3은 자유 플레이)가 다르다. 전사형은 어떤 단계에서도 지급되지 않는다.
- Stage 2~5의 웨이브 편성이 거의 같고(일반·속도·탱커병), 최종 난이도·아트·사운드는 미확정이다.
- 세션 간 저장/불러오기 없음.
- 레거시 줄 단위 블록 편집기 코드와 `UI/BlockCoding/` 프리팹이 남아 있다(→ [구조.md](구조.md)).
