# 개발과 테스트

## 헤드리스 검사

프로젝트 루트에서 실행한다. .NET 10 SDK, Python 3, 로컬 Unity 6000.3.21f1(다른 경로는 `-p:UnityEditorPath=...`)이 필요하다.

```powershell
rtk proxy dotnet run --project Tests/Defense/Defense.Check.csproj         # 전투·프로그램·캠페인·학습·Stage 1 코드
rtk proxy dotnet run --project Tests/EditorOptions/EditorOptions.Check.csproj
rtk proxy dotnet run --project Tests/BlockCoding/BlockCoding.Check.csproj  # 블록 컴파일러
python -I Tests/BlockCoding/check_tree_python.py
```

- Stage 1 튜토리얼 원본은 [flow_stage1/tutorial_stage1_대본.md](flow_stage1/tutorial_stage1_대본.md)이고, `Tools > Develop > Stage 1 튜토리얼 asset 다시 만들기`가 asset(`Tutorial_1-1~1-4`)으로 옮긴다([튜토리얼.md](튜토리얼.md)).
- Play 중 튜토리얼 진행 확인은 `Tests/Unity/TutorialProbe.cs`(Unity MCP `run_script`).

## Play 시작 씬

에디터의 일반 Play는 어떤 씬을 열어 두었든 항상 `Title`에서 시작한다(`DevTest.cs`가 `playModeStartScene`을 설정). Defense를 바로 테스트하려면 개발 에디터의 `▶ Defense 테스트 Play`, 메뉴 `Tools > Develop > Defense 테스트 Play`, 또는 아래 `DevTest.PlayDefense`를 쓴다.

## AI 테스트 (DevTest API)

Unity MCP `Unity_RunCommand`에서 `CodingGame.Defense.Editor.DevTest`를 호출한다. Play 진입은 비동기라 호출을 단계별로 나눈다.

```csharp
DevTest.PlayDefense(2, 1);                 // 1) Defense를 stage 2 wave 1로 시작 (튜토리얼 OFF). Play 중이면 씬 전환 또는 재시작
                                           //    1-2~1-5로 시작하면(이전 보상 지급 ON) 앞 튜토리얼에서 놓았을 전사와 완성했을 코드가 미리 들어감
DevTest.Ready                              // 2) true가 될 때까지 다음 호출에서 확인
DevTest.State()                            // 전투 상태 JSON: 단계, 기지 HP, 코인, 재고, 로봇별 코드·오류
DevTest.AutoDeploy(); DevTest.RunWave();   // 자동 배치 후 웨이브 끝까지 즉시 시뮬레이션
DevTest.RunCampaign(5)                     // 1-1부터 5스테이지까지 자동 진행, TestResults/Editor/last.json 저장
DevTest.JumpTutorial(3, 2)                 // Stage 1 튜토리얼 1-3의 3번째 단계(0부터)로 이동. 앞 단계까지 놓았을 로봇과 튜토리얼 정답 코드를 자동으로 넣음
DevTest.PlayTitle(); DevTest.PlayStageMap();
DevTest.ResetSaveData();                    // 저장 데이터(PlayerPrefs) 전부 삭제 = 처음 설치 상태
DevTest.Coins(500); DevTest.GrantAll(); DevTest.Speed(4); DevTest.SetOptions(new DefenseTestOptions{ baseDamage=false });
DevTest.Battle / DevTest.Sim               // 그 밖의 조작은 직접
DevTest.Stop();
```

- `RunWave`/`RunCampaign`은 시뮬레이션만 한 번에 진행한다. 화면은 다음 프레임에 따라온다. UI 조작 검증이 아니다.
- `AutoDeploy`는 진행 확인용 단순 전략(경로 커버리지 최대 위치, 기본 행동 반복)이다. 실패해도 밸런스 결론으로 쓰지 않는다.

## 플레이테스트 도구 (기획 피드백 확인)

`Tools/Develop/플레이테스트 실행 (기획 피드백 확인)`(코드: `Playtest.Run()`, 하나만: `Playtest.RunOne(번호)`)은 Defense 씬을 플레이어처럼 새로 열고, 기획 피드백 시나리오를 실제 포인터 드래그와 대사 넘기기로 차례로 확인한다. 결과는 `Temp/Playtest/report.md`와 시나리오별 스크린샷(`1.png`…)에 남는다. 시나리오는 `Assets/!_Project/Editor/Defense/Playtest.cs`의 `Scenarios` 목록에 추가한다.

| 번호 | 확인 내용 |
|---|---|
| 1 | 1-1 A01 경고 카드와 배너가 0.5초 간격으로 나오는지(실제 시간, 카드가 보이는 동안 멈춘 프레임) |
| 2 | 1-1 E01에서 뒤로가기 → D10, 경고 배너 다시 안 나옴 |
| 3 | 설명 대사(C11, C13) 중 팔레트 드래그가 막히는지 |
| 4 | C16에서 꺼내 둔 블록을 드래그로 연결하면 C17로 넘어가는지 |
| 5 | 1-3 B02·B02a·B02b 대사와 강조 대상 |
| 6 | 베기 이펙트가 SwordSlash_3이고 크기·방향이 맞는지 |
| 7 | 코어 피격·사망 글리치 머티리얼 |

실행 전체를 FFmpeg로 녹화해 `Temp/Playtest/playtest.mp4`에 남기고, 보고서의 각 시나리오에 영상 시작 시각을 적는다(FFmpeg가 없으면 녹화만 건너뜀).

## 플레이 녹화 (FFmpeg)

`Tools/Develop/플레이 녹화 시작·중지 (FFmpeg)`(코드: `PlayRecorder.Start(경로)` / `PlayRecorder.Stop()`)는 Play 중 Game 화면(UI 포함)을 mp4로 저장한다. 메뉴로 녹화하면 `Temp/Recordings/날짜_시각.mp4`. Play를 끝내면 자동으로 멈춘다.

- FFmpeg 설치: `winget install Gyan.FFmpeg`. 다른 위치면 EditorPrefs `CodingGame.FFmpegPath`나 환경 변수 `FFMPEG_PATH`에 `ffmpeg.exe` 경로를 넣는다.
- 1280px 폭, 30fps, H.264. 프레임이 멈추면 멈춘 시간만큼 같은 화면이 이어져 플레이어가 본 그대로 남는다.
- 인코더가 2초 넘게 밀리면 프레임을 버리고 저장 메시지에 버린 수를 적는다.
- 구현: `Editor/Defense/PlayRecorder.cs`(FFmpeg 프로세스), `Scripts/Defense/PlayRecorderHost.cs`(에디터 전용 프레임 캡처).

## Unity Play Mode 검사

`DevTest.PlayDefense(...)`로 Defense를 시작한 뒤 Unity MCP로 실행한다. 실행 방식(`run_script` 진입점 / `eval_file` / `Unity_RunCommand`)은 각 파일 첫 줄 주석을 따른다. 대부분 새 Play Mode 세션이 필요하다.

| 파일 | 확인 내용 |
|---|---|
| `Tests/Unity/TutorialPosition.playmode.cs` | 대화창 위치 |
| `Tests/Unity/CampaignFiveStagesCheck.cs` | 15웨이브 진행·보상·스테이지 전환 |
| `Tests/Unity/RobotInteractionCheck.cs` | 행동 메뉴, 1-1 레벨업 잠금, 레벨업 비용, 개발·회수, 미리보기 조작, 개발자 전체 지급 |
| `Tests/Unity/PlacementFeedbackCheck.cs` | 설치 제한·실패 알림 |
| `Tests/Unity/VariableInputCheck.cs`, `CommandPaletteCheck.cs` | 변수 참조 입력, 팔레트 |
| `Tests/Unity/MeleeTargetCheck.cs`, `MeleeHitRangeCheck.cs`, `HitEffectsCheck.cs`, `PreviewEffects.playmode.cs` | 근접 판정, 피격 범위, 이펙트 |
| `Tests/Defense/Preview.playmode.cs` | 코드 미리보기 |
| `Tests/BlockCoding/Drag.playmode.cs`, `History.playmode.cs`, `Snap.playmode.cs` | 블록 드래그, Undo/Redo, 스냅 |

Stage 1은 로봇과 배치를 학습용으로 잠그므로 Stage 1 흐름 외 검사는 샌드박스로 시작한다.

```csharp
battle.EditorStartSession(stage, wave, false, new DefenseTestOptions { tutorial = false, tutorialInput = false /*, inventoryLimit = false, unlockAll = true */ });
```

## 개발 에디터

메뉴 `Tools > Develop > 개발 에디터`. 버튼은 모두 `DevTest`를 호출하므로 AI 테스트와 같은 동작이다.

| 탭 | 기능 |
|---|---|
| 플레이 | 바로가기(Title, Stage 맵, 저장 데이터 초기화, Stage 1 튜토리얼 웨이브·구간 선택), 시작 stage-wave·이전 보상·튜토리얼 선택 후 Defense 테스트 Play / Title부터 Play. Play 중: 전투 시작·일시정지·한 틱·보상/다음, 속도 x0.5~x8, 자동 배치·웨이브 끝까지·캠페인 자동 진행·리포트 저장, 코인·전체 지급·기지 무적·게임 내 개발 패널, 튜토리얼 이전/다음/종료, 현재 상태 |
| 밸런스 | 캠페인 asset(자동 선택) 공통 규칙·보급·로봇·적·웨이브 편집, 최종 스폰 계획. Edit Mode는 원본을 직접 편집, Play 중에는 복사본을 편집해 `실행 중 적용` / `원본에 저장` |
| 테스트 옵션 | 학습·입력 제한·코드·스폰·이동·공격·피해·제한·지급·표시 옵션, 정상값 복원. 다음 테스트 Play에도 적용 |

- Play 중 편집값은 `원본에 저장`하지 않으면 Play 종료 시 사라진다.
- 블록 도감 편집은 메뉴 `Tools > Develop > blockDict`. Defense 씬의 `DefenseBlockHelp` 항목을 드래그로 순서 변경(목록 버튼 순서도 함께 이동)하고 제목·설명·예시를 고친 뒤 `씬 저장`. Play 중에는 편집 불가.
- 계산 옵션은 다음 틱, 표시 옵션은 즉시 적용된다. 스폰 OFF는 스폰 시계를 멈춘다.
- 헤드리스 검사는 위 `dotnet run` 명령으로 실행한다.

## 게임 내 개발자 모드

F1(또는 F2)로 개발자 화면(`DefenseCanvas`)을 연다. 학습 중에는 막힌다. 전체 지급 버튼(`GrantAll`)은 누를 때마다 로봇 각 10대, 블록 각 50개를 더한다.

## 알려진 공백

- 실제 사람의 마우스 플레이 테스트 기록이 없다. Play Mode 검사는 입력 주입과 고정 틱 진행이다.
- Stage 2~5 콘텐츠와 기획 의도(3스테이지, 3은 자유 플레이)가 다르다. 전사형은 어떤 단계에서도 지급되지 않는다.
- Stage 2~5의 웨이브 편성이 거의 같고(일반·속도·탱커병), 최종 난이도·아트·사운드는 미확정이다.
- 세션 간 저장/불러오기 없음.
