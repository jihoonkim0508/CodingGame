# 개발과 테스트

## 헤드리스 검사

프로젝트 루트에서 실행한다. .NET 10 SDK, Python 3, 로컬 Unity 6000.3.21f1(다른 경로는 `-p:UnityEditorPath=...`)이 필요하다.

```powershell
rtk proxy dotnet run --project Tests/Defense/Defense.Check.csproj         # 전투·프로그램·캠페인·학습·Stage 1 코드
rtk proxy dotnet run --project Tests/EditorOptions/EditorOptions.Check.csproj
rtk proxy dotnet run --project Tests/BlockCoding/BlockCoding.Check.csproj  # 블록 컴파일러
python -I Tests/BlockCoding/check_tree_python.py
```

- Stage 1 튜토리얼 원본은 [flow_stage1/tutorial_stage1_대본.md](flow_stage1/tutorial_stage1_대본.md)이고, `Tools > Develop > Stage 1 튜토리얼 asset 다시 만들기`가 asset(`Tutorial_1-1~1-4`)으로 옮긴다([튜토리얼.md](튜토리얼.md)).
- Play 중 튜토리얼 진행 확인은 `Tests/Unity/TutorialProbe.cs`(Unity MCP `run_script`).

## Play 시작 씬

에디터의 일반 Play는 어떤 씬을 열어 두었든 항상 `Title`에서 시작한다(`DevTest.cs`가 `playModeStartScene`을 설정). Defense를 바로 테스트하려면 개발 에디터의 `▶ Defense 테스트 Play`, 메뉴 `Tools > Develop > Defense 테스트 Play`, 또는 아래 `DevTest.PlayDefense`를 쓴다.

## AI 테스트 (DevTest API)

Unity MCP `Unity_RunCommand`에서 `CodingGame.Defense.Editor.DevTest`를 호출한다. Play 진입은 비동기라 호출을 단계별로 나눈다.

```csharp
DevTest.PlayDefense(2, 1);                 // 1) Defense를 stage 2 wave 1로 시작 (튜토리얼 OFF). Play 중이면 씬 전환 또는 재시작
                                           //    1-1이 아닌 곳에서 시작하면(이전 보상 지급 ON) 캐시의 웨이브 시작, 없으면 앞 수업이 놓은 로봇과 정답 코드가 미리 들어감
DevTest.Ready                              // 2) true가 될 때까지 다음 호출에서 확인
DevTest.State()                            // 전투 상태 JSON: 단계, 기지 HP, 코인, 재고, 로봇별 코드·오류
DevTest.AutoDeploy(); DevTest.RunWave();   // 자동 배치 후 웨이브 끝까지 즉시 시뮬레이션
DevTest.RunCampaign(5)                     // 1-1부터 5스테이지까지 자동 진행, TestResults/Editor/last.json 저장
DevTest.JumpTutorial(2, 3, 0)              // 2-3 튜토리얼 첫 단계(0부터)로 F1 이동. 캐시가 없으면 앞 수업의 로봇·정답 코드를 넣음. DevTest.LastJump: 어떤 경로였는지
DevTest.JumpTutorial(3, 2)                 // (Stage 1 전용, 검사 스크립트용) 1-3의 3번째 단계로 이동
DevTest.PlayTitle(); DevTest.PlayStageMap();
DevTest.ResetSaveData();                    // 저장 데이터(PlayerPrefs) 전부 삭제 = 처음 설치 상태
DevTest.Coins(500); DevTest.GrantAll(); DevTest.Speed(4); DevTest.SetOptions(new DefenseTestOptions{ baseDamage=false });
DevTest.Battle / DevTest.Sim               // 그 밖의 조작은 직접
DevTest.Stop();
```

- `RunWave`/`RunCampaign`은 시뮬레이션만 한 번에 진행한다. 화면은 다음 프레임에 따라온다. UI 조작 검증이 아니다.
- `AutoDeploy`는 진행 확인용 단순 전략(경로 커버리지 최대 위치, 기본 행동 반복)이다. 실패해도 밸런스 결론으로 쓰지 않는다.

## Play 모드 스모크 검사 (배치모드 가능)

`Tools/Develop/Play 모드 스모크 검사`(코드: `PlaySmoke.Run()`)는 실제 Defense 씬을 Play 모드로 돌려 2-5 전투(로봇 머리 위 꼬리표) → 결과 화면(브리핑·이름표) → 보상 수령·별 → 3-5를 로봇 한 대로 져서 웨이브 재도전 → Esc 메뉴 열고 닫기를 차례로 하고, 그동안 로그에 오류·예외·Assert가 하나라도 나오거나 기대한 상태가 아니면 실패한다. 결과는 `TestResults/Editor/smoke.txt`. 에디터를 닫은 상태에서 배치모드로도 돈다(`-quit` 없이, 스스로 0/1로 종료):

```powershell
& "C:\Program Files\Unity\Hub\Editor\6000.3.21f1\Editor\Unity.exe" -batchmode -nographics -projectPath . -executeMethod CodingGame.Defense.Editor.PlaySmoke.Run -logFile smoke.log
```

화면을 그리지 않으므로(-nographics) 배치·글자 크기·겹침은 확인하지 못한다. 그건 사람이 Play로 본다.

## 플레이 녹화 (FFmpeg)

`Tools/Develop/플레이 녹화 시작·중지 (FFmpeg)`(코드: `PlayRecorder.Start(경로)` / `PlayRecorder.Stop()`)는 Play 중 Game 화면(UI 포함)을 mp4로 저장한다. 메뉴로 녹화하면 `Temp/Recordings/날짜_시각.mp4`. Play를 끝내면 자동으로 멈춘다.

- FFmpeg 설치: `winget install Gyan.FFmpeg`. 다른 위치면 EditorPrefs `CodingGame.FFmpegPath`나 환경 변수 `FFMPEG_PATH`에 `ffmpeg.exe` 경로를 넣는다.
- 1280px 폭, 30fps, H.264. 프레임이 멈추면 멈춘 시간만큼 같은 화면이 이어져 플레이어가 본 그대로 남는다.
- 인코더가 2초 넘게 밀리면 프레임을 버리고 저장 메시지에 버린 수를 적는다.
- 구현: `Editor/Defense/PlayRecorder.cs`(FFmpeg 프로세스), `Scripts/Defense/PlayRecorderHost.cs`(에디터 전용 프레임 캡처).

## 개발 에디터

메뉴 `Tools > Develop > 개발 에디터`. 버튼은 모두 `DevTest`를 호출하므로 AI 테스트와 같은 동작이다.

| 탭 | 기능 |
|---|---|
| 플레이 | 바로가기(Title, Stage 맵, 저장 데이터 초기화, 스테이지·웨이브·구간 선택 후 `이 구간으로`), 시작 stage-wave·이전 보상·튜토리얼 선택 후 Defense 테스트 Play / Title부터 Play. Play 중: 전투 시작·일시정지·한 틱·보상/다음, 속도 x0.5~x8, 자동 배치·웨이브 끝까지·캠페인 자동 진행·리포트 저장, 코인·전체 지급·기지 무적·게임 내 개발 패널, 튜토리얼 이전/다음/종료, 현재 상태 |
| 밸런스 | 캠페인 asset(자동 선택) 공통 규칙·보급·로봇·적·웨이브 편집, 최종 스폰 계획. Edit Mode는 원본을 직접 편집, Play 중에는 복사본을 편집해 `실행 중 적용` / `원본에 저장` |
| 테스트 옵션 | 학습·입력 제한·코드·스폰·이동·공격·피해·제한·지급·표시 옵션, 정상값 복원. 다음 테스트 Play에도 적용 |

- 바로가기: 캠페인의 모든 스테이지(1~3)·웨이브를 고른다. 튜토리얼이 있는 웨이브는 단계 목록이, 없는 웨이브는 `웨이브 시작`이 나온다. `이 구간으로`는 게임 F1 패널과 같은 이동이다(`DevTest.JumpTutorial(stage, wave, step)` → `DefenseBattle.DeveloperJump("2-3.A01")`, 튜토리얼 없는 웨이브는 `DeveloperJumpWave("2-4")`). Play 중이 아니면 Defense 씬을 열고 이동한다.
- 시작 조건: 이전 보상 지급 ON으로 1-1이 아닌 곳에서 시작하면 플레이어가 그 웨이브에 왔을 때의 상태로 시작한다. 캐시에 그 웨이브 시작이 있으면 그 상태(`DeveloperJumpWave`), 없으면 웨이브 시작 재고(GameData/Award.md 클리어 보상) + 그 스테이지 앞 수업이 세운 로봇(역할별: 수업이 세우는 원거리형·전사형, 플레이어가 놓는 단계는 직전 단계가 가리킨 로봇 버튼의 역할) + 정답 코드(`TutorialAnswers`).
- 바로가기 아래 `시작 상태`가 어떤 경로였는지 보여 준다: `캐시로 이동` / `캐시 없음: 웨이브 시작 상태 (수업 로봇·정답 코드 복원)` / `오래된 캐시: …` / `캐시 재생이 어긋남(…)`. 캐시는 아래 `스테이지 캐시` 절.
- `DevTest.JumpTutorial(wave, step)`(인자 2개)는 Stage 1 검사 스크립트용으로 남겨 둔 것이다. 이미 그 1-x 웨이브 전투 중이면 세션을 그대로 두고 그 단계로 바로 이동하고, 아니면 위와 같은 F1 이동을 한다.
- Play 중 편집값은 `원본에 저장`하지 않으면 Play 종료 시 사라진다. 캐시로 시작한 전투는 원본 캠페인으로 재생되므로 편집값이 빠진다.
- 블록 도감 편집은 메뉴 `Tools > Develop > blockDict`. Defense 씬의 `DefenseBlockHelp` 항목을 드래그로 순서 변경(목록 버튼 순서도 함께 이동)하고 제목·설명·예시를 고친 뒤 `씬 저장`. Play 중에는 편집 불가.
- 계산 옵션은 다음 틱, 표시 옵션은 즉시 적용된다. 스폰 OFF는 스폰 시계를 멈춘다.
- 헤드리스 검사는 위 `dotnet run` 명령으로 실행한다.

## GameData (보상·밸런스 표)

보상·코인·적 웨이브·로봇 수치는 `GameData/Award.md`와 `GameData/Balance.md`의 표가 원본이다(팀원용 설명: [인수인계/GameData 사용법.md](인수인계/GameData%20사용법.md)). 메뉴 `Tools/Develop/GameData 적용`(코드: `GameDataApply`, 읽기 `GameDataTables`)이 두 표를 읽어 캠페인 asset(`StageOneCampaign.asset`의 수업별 클리어 보상·로봇 보상·시작 코인·처치당 코인, 웨이브별 적 그룹)과 전사형·원거리형·탱커형 asset(Level 1의 피해·공격 간격·사거리)에 쓴다. 씬은 저장하지 않는다. 두 파일이 마지막 적용 뒤 바뀌었으면 Play를 누를 때 자동으로 적용된다(`Library/GameDataApplied.hash`). `TutorialSequenceBuilder`의 캠페인 재구성(`ApplyAllFive` 등)도 같은 표를 쓴다.

- 보상: 웨이브 시작 지급은 없고, `start` 줄(1-1 시작 재고)만 1-1 수업의 시작 지급으로 들어간다. 다른 줄은 그 웨이브를 깼을 때 보상창에서 받는다(로봇은 블록 위 한 줄). 2-1은 빈 재고로 시작하고, 3-1은 2스테이지에서 받은 것을 이어받는다. 수업 예제 코드(`LoadLesson`)와 수업 전사형(`PlaceLessonRobot`)은 블록을 지급하지 않고, 모자라면 경고만 남긴다. 해금 열은 읽지 않는다(레벨업 1-2·회수 1-3·배속은 코드가 정한다).
- 개수의 `x`/`X`는 적용할 때 파일에서 `×`로 바뀐다. 모르는 이름·숫자 오류는 줄 번호와 함께 오류로 막고, 계산 열(DPS, Level 2·3 피해, 마지막 출현, 처치 코인)이 맞지 않으면 경고만 남긴다.
- 보스 코어 피해 12, 나머지는 적 asset 값. 길(route)은 그 그룹 자리의 기존 값(1-5 졸개는 두 번째 길). 1스테이지 웨이브 시간 120초는 코드에 있다.
- 검사: `dotnet run --project Tests/Defense/Defense.Check.csproj`의 `GameDataCheck`.

## 스테이지 캐시 (F1 대사 이동)

사람이 정답대로 플레이한 기록이다(팀원용 설명: [인수인계/스테이지 캐시 사용법.md](인수인계/스테이지%20캐시%20사용법.md)). 메뉴 `Tools/Develop/캐시 제작`(코드: `PlayCacheWindow`) 창에서 Play 중, 튜토리얼이 켜진 전투에서 **기록 시작** → 플레이 → **기록 중지**. 기록은 웨이브·스테이지·전투 세션이 바뀌어도 이어지고(`DefenseBattle.Recording`, static), 중지하면 스테이지마다 `Assets/!_Project/Resources/Dev/PlayCache_<스테이지>.json`(보기 좋게 들여쓴 JSON, 빌드에도 들어간다)에 쓴다. 파일이 있으면 이번에 기록한 ID만 바꾸고 나머지는 남긴다(`PlayLog.Merge`). 지문이 다르면 예전 것은 버리고 새것만 쓴다.

- 기록(`PlayLog.cs`): 시뮬레이션을 바꾸는 입력(배치·회수·레벨업·코드 적용·편집 중 블록·실행·전투 시작·일시정지·보상 수령·지급·코인·스테이지 진행)을 세션 시작부터의 틱 번호와 함께 `DefenseSimulation.Inputs`에 남긴다. 전투는 60Hz 고정 틱이라 배속·일시정지·튜토리얼 슬로모션은 결과를 바꾸지 않는다. 배치 입력에는 로봇 수치를 넣지 않는다(재생 때 정의의 수치).
- 파일: `steps`(ID마다 스테이지·웨이브·단계·코인·코어·처치·누수·적 수·재고·로봇(정의·역할·위치·레벨·코드 `source`와 블록 트리 `code`)·UI(선택 로봇, 열린 편집기 로봇과 그 코드, 인벤토리, 일시정지, 보상창)·튜토리얼 신호/완료 단계/시작한 시퀀스·`replay`), `runs`(세션 시작 방식: 스테이지·첫 웨이브·이전 보상·테스트 옵션·웨이브 재도전이면 그 시작 상태, 그리고 입력). ID는 대사 `"1-1.E07"`와 웨이브 시작 `"2-4"`. 같은 ID를 다른 세션(웨이브 재도전 등)에서 다시 지나가면 나중 것을 쓴다.
- 이동: F1 패널 `Dialogue ID`에 `1-1.E07`(또는 `1-3`)을 넣고 Go. 그 단계의 세션을 같은 방식으로 새로 시작해 입력을 그 틱까지 화면 없이 재생하고(전투 중이면 적·투사체까지), 상태 요약(`replay.digest`)을 기록과 비교한 뒤 화면·선택 로봇·편집기·인벤토리를 맞추고 튜토리얼을 그 단계(앞 단계 완료, 신호 그대로)에서 연다. 단계 진입 효과(편집기 열기, 예제 코드 등)는 단계가 직접 한다.
- 캠페인 asset(로봇·적 포함)이나 그 스테이지의 튜토리얼 asset이 바뀌면 지문이 달라져 캐시를 쓰지 않고, 웨이브 시작에서 그 대사를 열며 패널에 "캐시 없음/캐시 오래됨/캐시에 없는 대사: Tools/Develop/캐시 제작으로 기록하세요"가 뜬다. 재생 결과가 기록과 다르면(맵·씬·F2 수치 등 지문 밖의 변화) "캐시 재생이 어긋남"이 뜬다.
- 검사: `BeginnerLessonChecks.RecordAllFiveForCheck` / `RecordStageTwoForCheck`(배치모드 가능)가 수업 러너의 플레이를 기록해 `TestResults/Editor/PlayCacheCheck/`에 쓰고, `BattleAuditCheck` J1~J4가 그 파일로 이동한다(커밋된 캐시는 쓰지 않는다).

## 게임 내 개발자 모드

개발자 모드에서 F1로 개발자 화면(`DefenseCanvas`)을 연다. 아래쪽 줄의 `Dialogue ID`(예: `1-3.C05`)와 `S-W`(예: `2-4`, 그 웨이브 준비 단계: 기록된 플레이가 있으면 그때의 로봇·코드, 준비 단계에서 시작하는 수업이 있으면 그 첫 대사, 없으면 이전 보상 재고로) + Go로 이동한다. F2는 지금 화면의 스테이지-웨이브 밸런스 창(`밸런스 · 2-3 (F2)`): 적 그룹마다 수·출현·간격·체력·속도·코어 피해(캠페인 asset 값, 스테이지 배율 전)와 실제 체력·속도, 합계(적 수·총 체력·마지막 출현)를 보이고, Apply/Reset은 그 스테이지-웨이브에만 게임을 끌 때까지 적용된다(준비 중이면 바로, 전투 중이면 그 웨이브를 다시 시작할 때). F1·F2는 타이틀·스테이지 맵·장면 전환 중에도 된다(`DefenseDevWindow`, `GameFlow` 루트에 붙어 장면을 넘어 산다). 전투 밖 F1은 `Dialogue ID`·`S-W` 줄만 띄우고, Go는 ID 앞 숫자의 스테이지를 스테이지 맵에서 들어가듯(`StageProgress.SelectedStage`, 이기면 맵에 기록) Defense 씬으로 연 뒤 전투가 시작되면 그 이동을 한다(개발자 화면의 다른 내용은 전투에서만). 전투 밖 F2는 창 위 `스테이지 < > 웨이브 < >`로 고른 스테이지-웨이브를 캠페인 asset(`Resources/DefenseCampaign` → 전투와 같은 `StageOneCampaign.asset`)에서 읽어 같은 방식으로 고치고, 같은 저장소(`DefenseBattle.StoreWaveGroup`)에 넣어 그 웨이브를 시작할 때 들어간다. 창이 열려 있는 동안 창 위 클릭은 아래 버튼·맵에 닿지 않고(투명 판), 스테이지 맵의 Z·Q는 쉰다. 개발자 모드는 타이틀 왼쪽 위 모서리(1080p 기준 120px 안)를 1초 안 간격으로 10번 연달아 누르면 켜지고, 다시 10번이면 꺼진다(왼쪽 위에 '개발자 모드 켜짐/꺼짐'). 게임을 켜 둔 동안만 유지된다. 개발자 모드에서는 전투 배속이 1·2·3·5배, 스테이지 맵의 Z(임시 클리어)·Q(초기화)와 그 안내 줄도 켜진다. 학습 중에는 막힌다. 전체 지급 버튼(`GrantAll`)은 누를 때마다 로봇 각 10대, 블록 각 50개를 더한다.

## 알려진 공백

- 실제 사람의 마우스 플레이 테스트 기록이 없다. Play Mode 검사는 입력 주입과 고정 틱 진행이다.
- Stage 2~5 콘텐츠와 기획 의도(3스테이지, 3은 자유 플레이)가 다르다. 전사형은 어떤 단계에서도 지급되지 않는다.
- Stage 3 웨이브는 주제별로 다시 짰지만(2026-11-03) 사람이 플레이해 난이도를 맞춘 적은 없다. 최종 난이도·아트·사운드는 미확정이다.
- 세션 간 저장/불러오기 없음.
