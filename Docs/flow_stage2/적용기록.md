# Stage 2 튜토리얼 적용 기록

작성: 2026-10-29

## 적용 내용

실제 프로젝트의 Stage 1 튜토리얼 구조(TutorialDirector, TutorialSequence, TutorialInputBridge)를 확장해 Stage 2를 연결했다. 기존 Stage 1 시퀀스 5개는 유지했다.

| 웨이브 | 적용 내용 |
|---|---|
| 2-1 | 새 전사 배치, 기초 코드 준비, 한 번 실행·종료 관찰, 명령 복제/for 비교 카드, 기본 10을 3으로 변경, 몸체 조립, 예측 질문, 세 번 실행·종료 관찰, 10회 변경과 실제 대상 갱신, 실전 |
| 2-2 | 새 전사 직접 배치·반복 코드 작성, 목표 체크와 선택형 힌트, 시작 조건 검사 |
| 2-3 | 새 원거리 선택·배치, for와 탐색 준비, Shot/attack 연결, 변수 연결, 전사보다 먼 거리에서 실제 탄 명중 관찰, 실전 |
| 2-4 | 새 원거리 직접 배치·반복 코드 작성, 자유 조정, 목표 체크와 선택형 힌트 |
| 2-5 | 전사·원거리와 반복 코드 종합 활용, 일반 적과 함께 등장하는 보스, 기지 생존과 보스 처치 확인 |

- for의 생성 형태와 기본 숫자는 기존 구현을 사용한다. 숫자만 10 → 3 → 10으로 바꾼다. while True 고정 사양은 변경하지 않았고 이번 필수 학습에 넣지 않았다.
- 일반 캠페인에서는 이전 로봇·코드를 유지한다. 2-1은 새 실습 전사, 2-3은 이번에 배치한 원거리 로봇을 우선 추적한다.
- 소개용 미리보기는 프로그램 1회 실행과 장면 자동 재시작을 별도로 제어한다. 일반 미리보기는 편집기를 닫고 다시 열면 기존 방식으로 복귀한다.
- 소개 장면은 마지막 베기 피해나 발사된 탄의 명중 처리가 끝난 뒤 다음 설명으로 진행한다. 프로그램 종료 직후 시뮬레이션을 멈춰 마지막 피해가 누락되는 경우를 방지했다.
- 회차는 for 몸체 진입 횟수이며 명중·처치 수와 분리했다. 종료, 재사용 대기, 대상 없음, 사거리 밖을 구분할 수 있게 했다. 전투 중에는 선택 로봇의 상태를 기존 하단 안내 영역에 표시한다.
- 새 로봇의 반복 코드 판정은 변수 이름·정확한 횟수를 고정하지 않는다. 탐색·저장·동일 변수의 공격이 양의 정수 for 몸체 안에 있어야 한다. 코드의 들여쓰기와 순서를 무시하던 기존 비교는 for 수업에서 구조를 보존하도록 보완했다.
- Stage 2 보스를 일반 적 전멸 후 소환하던 실행기 제한에서 분리했다. 보스가 생존한 채 시간이 끝나거나 보스가 기지에 도달하면 보스 처치 성공으로 안내하지 않는다.

## 검사 결과

- 전투 검사 61개, 프로그램 검사 72개, 캠페인 검사 178개 통과. 15웨이브 보급·보상·이월 검사 통과.
- 블록 컴파일러·타입 슬롯·분기·변수·반복문 검사 통과.
- 신규 학습 검사: 한 번/세 번 실행 후 종료, 비교 적의 생존·사거리 유지, 회차 표시, 탐색의 몸체 외부 배치 거부, 다른 변수 이름·횟수 허용, 기존 로봇만으로 새 실습 통과 불가, 보스 동시 등장, 생존 보스 시간 초과 실패 확인.
- 실제 씬·캠페인·맵을 사용하는 검사에서 3가지 배치 조합 × 5웨이브를 기본 10회 코드로 통과했다. 각 경우 기지 체력 12, 시간 초과·남은 적 0. 이 검사는 모든 자유 배치의 승리를 보장하는 밸런스 검사가 아니다.
- 실제 Play Mode에서 2-1~2-5를 순서대로 진행하고 승리 도달 확인. 프로그램 종료·대상 갱신·원거리 명중 신호를 강제로 넣지 않고 실제 미리보기에서 기다렸다. 블록 조립은 테스트 도구가 편집기에 블록 데이터를 로드했으므로 사람의 마우스 드래그 사용성 검증과는 구분한다.
- 비교 카드·예측 선택지의 렌더 이미지를 확인하고 비교 카드의 열 정렬을 수정했다.

## 적용 범위와 남은 연출

- 개별 실행 줄을 따라 이동하는 화살표, 실전 실행 이력 저장, 웨이브 단위 재도전 복원은 추가하지 않았다. 회차·현재 실행 상태와 기존 스테이지 재도전 흐름을 사용한다.
- 특정 타일 강제 배치나 전사/원거리 점선 비교선은 추가하지 않았다. 실제 배치는 사거리 원으로 안내하고 원거리의 차이는 통제된 미리보기에서 확인한다.
- 조건문 응용은 필수 단계가 아니다. 자유 편집은 허용하며 기본 힌트는 조건문 없는 반복으로 유지했다.
- 실제 초보자의 읽기 속도·마우스 조작·자유 배치 전략에 대한 관찰은 별도 사용자 플레이 검증 대상이다.


### 미리보기 주기 재생 사양 수정

사용자 확인에 따라 Stage 2 설명·조립 중에도 미리보기를 계속 재생하도록 변경했다. 소개 장면은 한 차례에서 프로그램을 한 번 실행한 뒤 마지막 공격 완료를 확인하고 1초 간격으로 다시 재생한다. 대사와 상태 표시에서 이 자동 재생과 코드 안의 for 반복을 구분한다. 앞서 기록한 일시 정지·재생 보류 방식은 이 변경으로 대체한다. 기존 전체 Play Mode 통과 기록은 변경 전 결과이며 이번 변경의 검사 결과와 구분한다.

### 스테이지별 씬 분리

- `Assets/!_Project/Scenes/stage1.unity`: Stage 1로 시작하며 Stage 1 튜토리얼 5개 연결.
- `Assets/!_Project/Scenes/stage2.unity`: Stage 2로 시작하며 Stage 2 튜토리얼 5개 연결.
- 스테이지 선택 화면의 1·2번 진입 경로와 Build Settings를 새 씬에 연결했다. 기존 Defense 씬은 Stage 3과 개발 검사 용도로 유지한다.
- 일반 Play는 어떤 씬을 열어 두어도 Title에서 시작한다. 개발 도구로 씬을 직접 실행했을 때는 씬 이름에 맞는 스테이지로 시작한다.
- 전용 씬에서 다음 스테이지로 진행할 때는 다음 씬을 로드한다. 씬 사이의 런타임 배치·프로그램은 새로 시작하며, 스테이지별 보급은 기존 캠페인 정의를 사용한다.
- 구조 검사: 원본 씬의 참조를 보존하고 스테이지 번호·튜토리얼 목록만 분리했음을 확인. 런타임·에디터 C# 프로젝트 빌드 오류 0개. 분리된 두 씬의 Play Mode 검사는 이번 변경에서 실행하지 않았다.


### 기본 Play 진입 복구

사용자 요청에 따라 stage1/stage2를 포함한 모든 씬에서 기본 Play는 Title로 시작하도록 복구했다. 개발 도구의 명시적인 씬 실행 기능과 스테이지 선택 화면의 stage1/stage2 연결은 유지한다.


### 목표 UI 표시 복구

목표 HUD가 특정 튜토리얼의 B01 대사 대기 상태에만 의존하던 조건을 제거했다. 이제 스테이지와 웨이브에 맞는 목표를 정비·전투 중 계속 표시하고 결과 화면에서는 숨긴다. Stage 1·2 모두 기존 상단 위치를 사용하며 Stage 2 첫 웨이브의 전사 목표도 올바르게 표시한다. 개발창에서는 기존 전장 HUD 숨김 동작을 유지한다.

### Stage 1 보존 및 Stage 2 반복문 강조 개선

- 이번 변경 전후 Stage 1 자산·stage1 씬·목표 HUD·GameFlow·기본 Play 설정 등 24개 파일의 SHA-256이 동일함을 확인했다. Stage 1 대사·목표·일시정지·배속·기본 Title 진입 기능은 변경하지 않았다.
- 새 강조는 `2-1` 개발창에서만 생성한다. 실제 for 숫자 칸에는 노란 ①, 실제 반복 몸체에는 청록 ② 테두리와 설명 라벨을 붙인다. 편집기 좌표를 매 프레임 읽어 블록 이동·확대에 맞춰 갱신한다.
- 3회 관찰에서는 몸체 옆에 실제 프로그램의 회차를 표시한다. 아직 시작하지 않았으면 ‘반복 시작 대기’, 종료 후에는 ‘종료 · 잠시 후 다시 재생’으로 구분한다.
- 숫자·몸체·미리보기를 함께 밝히고 조립 대사를 색과 번호에 맞춰 짧게 바꿨다. 클릭을 가로채지 않는 UI이며 다른 구간으로 이동하면 제거한다.
- 대사 원본, 2-1 실행 자산, 재생성 빌더를 함께 수정했다. C# 런타임·에디터 빌드 오류 0개. 이번 강조의 실제 Play Mode 화면·조작 검사는 아직 실행하지 않았으며, 앞선 Play Mode 기록과 구분한다.
