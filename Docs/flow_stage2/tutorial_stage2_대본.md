## 영상 반영의 기준

참고: 사용자 제공 로컬 영상 ‘소개영상.mp4’(약 2분 4초). 주요 화면을 시간대별로 추출해 배치·블록 편집·전투·결과 흐름을 확인했다. 영상의 튜토리얼 대사·강조 순서·홍보 자막은 그대로 복제하지 않는다. 영상에서 확인되는 플레이 흐름을 유지하며, Stage 2의 학습 내용만 반복문과 원거리로 바꾼다.

**공통 플레이 흐름: 정비 중 로봇 배치·선택 → 개발창에서 블록 연결 → 왼쪽 미리보기 확인 → 닫기 → 전투 시작 → 작성 코드에 따른 자동 전투 관찰 → 웨이브 결과·보상 확인 → 다음 정비.**

- 전투는 플레이어가 직접 공격 버튼을 연타하는 방식으로 설명하지 않는다. 플레이어의 판단은 주로 로봇 위치와 코드 구성에 두고, 전투에서는 그 결과를 확인하게 한다.
- 개발창에서는 블록을 연결한다. Python 예시는 대본 작성자용 구조 표기이며 플레이어에게 텍스트 입력·별도 저장·별도 코드 실행을 요구하지 않는다.
- 영상의 상단 웨이브·시간·적 수, 좌측 다음 웨이브 정보, 우측 기지 체력, 하단 로봇 목록과 우측 ‘전투 시작’, 개발창 상단 ‘닫기’를 기준으로 포커스를 지정한다.
- 전투 중 편집·회수·재배치 가능 여부는 이 영상만으로 확정하지 않는다. 대본의 수정 안내는 다음 정비 또는 실패 후 재도전 준비에서 진행한다.
- 영상의 맵·로봇 수·웨이브 수치·배속은 Stage 2 확정값으로 옮기지 않는다. 사용자가 지정한 2-1~2-5 구성은 유지한다.
- 영상만으로 코드 자동 적용 시점·함수 재호출 정책·Stage 2 반복 해금 동작을 확정할 수 없다. 해당 내용은 원 대본의 적용 전 검증 조건으로 남긴다.

## 구성과 작성 기준

| 웨이브 | 주제 | 플레이어가 해 보는 일 |
|---|---|---|
| 2-1 | 반복문 소개 | 한 번 실행과 세 번 반복을 비교하고, 반복의 끝과 대상 갱신을 확인한다 |
| 2-2 | 반복문을 활용한 자유 플레이 | 새 전사를 직접 배치하고 반복 코드를 만든다 |
| 2-3 | 원거리 캐릭터 소개 및 사용 방법 | 전사보다 멀리 닿는 위치에 배치하고 반복 사격을 만든다 |
| 2-4 | 원거리를 활용한 자유 플레이 | 전사와 원거리 로봇의 위치·코드를 직접 구성한다 |
| 2-5 | 보스 | 반복문과 전사·원거리 로봇을 활용해 보스를 상대한다. 조건문은 선택 응용이다 |

- `발화자 : 대사`와 `[2-1.A01]` 형식은 Stage 1을 따른다. `시스템`은 UI 배너, `집중`·`상호작용`·`▶`는 연출·진행 메모다.
- `▶`는 이번 초안의 구현 제안이다. Stage 1 문서의 승인된 결정 번호와 같은 의미로 사용하지 않는다.
- 플레이어는 블록으로 코드를 만든다. 코드 예시는 Python 미리보기 기준이며, 별도 타이핑·저장·실행 버튼을 요구하지 않는다.
- 소개는 작은 단위로 조립하고 행동을 관찰한다. 자유 플레이는 짧은 안내 후 입력 제한을 해제하며, 목표를 화면 중앙 상단에 남기고 힌트는 선택 사항으로 제공한다.
- 새 개념은 `for i in range(n)`부터 소개한다. 실제 for 블록은 `for i in range(10):` 형태로 기본 생성되며, 이번 실습에서는 숫자 입력칸의 10만 3으로 바꾼다. for·i·in·range를 별도로 조립하도록 요구하지 않는다.
- 사용자 확인 사양: while 블록은 `while True:`로 고정되어 있다. 조건식을 바꿔 조립하는 while을 가정하지 않는다. `while`·`break`·`continue`와 반복 변수 `i`의 활용은 이번 필수 학습 범위에 넣지 않는다.
- 조건문 복습은 선택형 도움말로 분리한다. 기본 대사에서는 반복·배치·사격에 집중하며, 조건문을 쓰지 않은 플레이어에게 사용했다고 칭찬하지 않는다.
- 원거리 공격 블록은 사격용 `Shot`이며, Python 미리보기에는 `attack(enemy)`로 표시된다. `shot(enemy)`로 안내하지 않는다.
- 거리 조건은 현재 방식인 `enemy.distance(get_my_pos()) <= my_attack_range()`를 사용한다. 과거의 고정 숫자 `2.5`나 동시 명중 시연을 다시 도입하지 않는다.
- 반복 횟수 예시 `3`·`10`은 초안용이다. **반복 횟수는 안쪽 명령 묶음을 실행하는 횟수이며, 명중·처치 횟수를 보장하지 않는다.** 최종 값과 적 수·등장 간격은 실전 검증 후 맞춘다.
- 미리보기와 실전 모두 ‘지금 실행 중인 명령’과 ‘프로그램 종료’를 알아볼 수 있어야 한다. 아래의 `반복 1/3`·`프로그램 종료`는 새 상태 UI 제안이다. 기존 함수 실행 횟수와 혼동되는 표시는 사용하지 않는다.

## 2-1 — 반복문 소개

```text
[도입: 이번 구역의 목표]
[2-1.A01] 시스템 : 새로운 오류 코드 무리가 접근 중입니다!
[2-1.A02] 안내자 : 새 구역에 도착했어!\n이번에는 <b>같은 명령을 여러 번 실행하는 방법</b>을 배워 보자.
▶ Stage 2 전환에 따른 배치·코드 초기화는 실제 전환 연출로 보여 준다. 새로 배치하는 이유를 대사 없이도 알아볼 수 있게 한다.

[실습할 전사와 기초 코드]
[2-1.B01] 안내자 : 먼저 실습할 <b>새 전사형 로봇</b>을 배치해 보자.\n적이 지나가는 길에 공격 범위가 닿도록 놓아 줘.
집중 : 전사형 로봇 버튼, 배치 가능한 땅, 사거리 원
상호작용 : 전사 1대를 배치한다.
[2-1.B02] 안내자 : 방금 놓은 전사를 누르고 <b>‘개발’</b>을 열어 봐.
[2-1.B03] 안내자 : 익숙한 두 줄을 준비했어.\n<b>적을 찾아 enemy에 저장하고 → 그 적을 베기!</b>
▶ 선택한 전사에만 아래 기초 코드 두 줄을 준비한다. 편집기 진입 때부터 소개용 미리보기 재생을 보류하고 B04에서 시작한다. 새 스테이지라 이전 스테이지의 배치·코드가 유지된다고 안내하지 않는다.
코드 :
enemy = get_nearest_enemy()
slash(enemy)

[먼저 한 번 실행해 보기]
[2-1.B04] 안내자 : 왼쪽을 보자.\n<b>미리보기 한 차례에서</b> 이 두 줄이 몇 번 실행되는지 확인해 보자.
▶ 소개용 미리보기는 한 차례 실행 후 기존의 재생 간격을 두고 다시 재생한다. 한 차례 안에서는 프로그램을 한 번 실행한다. 사거리 안에 오래 머무는 실습 적 1마리를 준비한다. 한 번 베어도 살아 있고, 세 번 베기 이후에도 살아 있도록 체력·이동 경로를 맞춘다. 멈춤 원인이 적 처치·사거리 이탈이 되면 안 된다.
[2-1.B05] 안내자 : 한 차례에서는 적을 한 번 베고 프로그램이 끝나.\n<b>잠시 후 다시 시작하는 건 미리보기의 자동 재생 기능이야.</b>
▶ 실제 공격 1회와 프로그램 종료를 확인하고 다음 미리보기 재생을 보류한다. 적은 살아 있고 사거리 안에 있는 상태를 유지한다. 종료 상태와 코드 마지막 줄을 강조한다.
[2-1.B06] 안내자 : 지난 구역에서는 게임이 프로그램을 다시 실행해 줬어.\n이번 구역에서는 <b>한 프로그램 안에서 어떤 명령을 몇 번 할지</b> 직접 정해 볼 거야.
▶ 반복문 해금 후 웨이브마다 함수 실행 한도가 1회가 된다는 규칙을 관찰 뒤 연결한다. 횟수 제한이 공격 블록 자체에 붙었다고 설명하지 않는다.
[2-1.B07] 안내자 : 적 찾기와 베기를 세 번 하려면 같은 두 줄을 세 묶음 놓을 수 있어.\n<b>반복문을 쓰면 한 묶음만 만들고, 몇 번 할지 정할 수 있어!</b>
▶ 개발창 오른쪽 조립 영역 안의 읽기 전용 비교 카드: 왼쪽은 ‘적 찾기 → 베기’ 세 묶음, 오른쪽은 for 3회 안의 한 묶음. 두 카드 아래 ‘같은 일을 세 번’이라고 표시한다. 왼쪽 묶음과 오른쪽 회차를 순서대로 대응시킨다. 실제 코드에 복제 블록을 추가하지 않는다. 사용자가 확인하면 닫고 C01로 진행한다.

[반복문 바깥과 안쪽]
[2-1.C01] 안내자 : 가운데 팔레트에서 <b>파란 for 블록</b>을 오른쪽 코드의 맨 위로 옮겨 줘.\n이 블록의 안쪽에 반복할 명령을 넣을 거야.
▶ 시작 위치에 for를 삽입한다. 기존 두 줄은 보존하고, for 뒤의 바깥 연결 영역에 둔다. 조립 중에는 코드 자동 적용을 유지하되 소개용 미리보기 실행은 보류한다.
[2-1.C02] 안내자 : <b>① 노란 테두리의 숫자</b>가 반복 횟수야.\n다른 칸은 그대로 두고 <b>10을 3으로</b> 바꿔 줘.
▶ for 블록은 사진의 형태처럼 `for i in range(10):`과 빈 안쪽 연결 영역이 있는 상태로 생성된다. 새 숫자 블록을 추가하게 하지 않고, 기본 10이 표시된 숫자 입력칸만 강조해 3으로 바꾸게 한다. for·i·in·range는 별도 조립을 요구하지 않는다.
[2-1.C03] 안내자 : 이번에는 <b>② 청록 테두리의 안쪽 영역</b>을 봐.\n적 찾기 <b>enemy = get_nearest_enemy()</b>를 그 안으로 옮겨 줘.
[2-1.C04] 안내자 : <b>slash(enemy)</b>도 <b>② 안쪽</b>, 적 찾기 바로 아래에 넣어 줘.\n두 명령이 같은 테두리 안에 있어야 해.
집중 : for의 안쪽 연결 영역, 두 명령의 위아래 순서
[2-1.C05] 안내자 : <b>①은 몇 번 할지, ②는 무엇을 할지</b> 알려 줘.\n지금은 <b>‘적 찾기 → 베기’ 묶음을 세 번</b> 실행하는 코드야.
▶ 반복 몸체 전체와 되돌아가는 흐름을 강조한다. 연결된 블록을 끌면 뒤의 명령까지 함께 이동할 수 있으므로, C03에서 두 줄이 함께 들어가면 C04는 ‘적 찾기 아래에 베기도 들어왔네!’로 바꾸고 재이동을 요구하지 않는다. 바깥에 명령이 중복으로 남지 않았는지 확인한다.
코드 :
for i in range(3):
    enemy = get_nearest_enemy()
    slash(enemy)

[세 번 반복하고 끝나는 모습]
[2-1.D00] 안내자 : 실행하기 전에 맞혀 보자.\n숫자가 3이면 <b>‘적 찾기 → 베기’ 묶음을 몇 번 실행할까?</b>
상호작용 : ‘1번 / 3번 / 적이 쓰러질 때까지’ 중 선택한다. 정답은 3번이다.
▶ for와 안쪽 두 줄을 함께 보여 준다. 오답이면 ‘숫자 3이 명령 묶음을 실행할 횟수야. 직접 확인해 보자.’를 한 번 표시하고 관찰로 진행한다. 정답을 고를 때까지 입력을 반복시키지 않는다.
[2-1.D01] 안내자 : 오른쪽 <b>② 명령 묶음 옆의 회차 표시</b>와 왼쪽 로봇을 함께 봐.\n한 차례 안에서 <b>1 → 2 → 3번째</b> 실행을 확인해 보자!
▶ 같은 시작 상태로 미리보기를 1회 재생한다. 반복 진입 때마다 `반복 1/3 → 2/3 → 3/3`과 실행 줄을 표시하고, 프로그램이 끝나면 `프로그램 종료`로 바꾼다. 카운터는 내부 i의 값이 아니라 플레이어용 회차이며 공격 명중 때 증가시키지 않는다.
[2-1.D02] 안내자 : <b>②의 두 명령을 세 번 실행해서 for가 끝났어.</b>\n뒤에 명령이 없어서 프로그램도 끝나. 잠시 후 다시 시작하는 건 미리보기 기능이야.
▶ 반복 테두리를 빠져나가는 실행 화살표를 보여 준다. for 아래에 이어진 명령이 없음을 강조한 뒤 ‘프로그램 종료’를 표시한다. for 종료 자체를 프로그램 종료와 동일하게 설명하지 않는다.
```

## 선택 도움말 — 조건문을 함께 쓰고 싶은 경우

2-2·2-4·2-5에서 플레이어가 직접 열어 보는 복습 도움말이다. 새 조건문 조립을 필수로 요구하지 않으며, 다음 내용을 이해할 수 있게 설명한 뒤 응용 예시를 제공한다.

```text
도움말 : if는 조건이 참일 때 안쪽 명령을 실행해요. 거짓이면 그 명령을 건너뛰어요.
도움말 : for 안에 if를 넣을 수 있어요. 적까지의 거리를 비교한다면, 거리도 for 안에서 다시 재 주세요.
도움말 : my_attack_range()는 지금 이 로봇의 공격 사거리예요. 전사와 원거리에서 모두 쓸 수 있어요.
도움말 : 주의! 조건이 거짓이어도 그 반복은 지나가요. if는 적이 올 때까지 기다려 주는 명령이 아니에요.
```

응용 코드의 구조:

```python
for i in range(10):
    enemy = get_nearest_enemy()
    enemy_distance = enemy.distance(get_my_pos())
    if enemy_distance <= my_attack_range():
        attack(enemy)
```

- 원거리 예시다. 전사에서는 안쪽 행동을 `slash(enemy)`로 바꾼다. 10은 예시 값이다.
- **이 코드를 기본 정답·안정적인 대기 방법으로 제시하지 않는다.** 적이 멀리 있거나 다음 무리가 오기 전에는 남은 반복이 빠르게 지나갈 수 있다. 현재 실행기는 공격 없이 함수가 끝났을 때 재시도하는 동작도 있으므로, 이를 ‘if가 기다려 준다’는 학습 설명으로 사용하지 않는다.
- 해당 웨이브에서 실제로 검증한 경우에만 응용 코드 복사 힌트를 노출한다. 검증 전에는 앞의 개념 도움말만 제공하고, 기본 힌트는 조건문 없는 적 찾기·공격 반복으로 유지한다.
- 사용자가 if를 직접 조립하는 것을 막지는 않는다. 다만 자유 플레이에서 학습 목표 구조와 별도로 ‘프로그램 종료’·‘조건 거짓’·‘공격 대기’를 구분해 원인을 확인할 수 있어야 한다.

## 실행 상태와 전투 구성 — 적용에 필요한 조건

아래는 대사만으로 해결할 수 없는 부분이다. 현재 구현된 기능으로 간주하지 않고, 대본과 함께 구현·검증할 항목으로 관리한다.

| 상황 | 플레이어에게 보일 정보 | 적용 조건 |
|---|---|---|
| 코드 조립 중 | 미완성 칸과 자동 적용 여부 | 미완성 코드를 자동 완성하거나 숨겨진 명령으로 보정하지 않는다. 완료 관찰 단계에서만 유효한 코드 실행을 기다린다 |
| 2-1 한 번 실행 | 실행 줄 → 프로그램 종료 | 소개용 미리보기에서 함수 자동 재호출·장면 자동 재시작을 모두 제어한다. 적 생존·사거리 유지 상태에서 정확히 한 번의 공격 뒤 종료를 보여 준다 |
| 2-1 세 번 반복 | 반복 1/3 → 2/3 → 3/3 → 프로그램 종료 | 이전과 같은 적·시작 상태에서 비교한다. 쿨타임은 기다리되 반복이 추가되지 않게 하고, 종료 뒤 관찰 시간을 준다 |
| 첫 적 처치 뒤 | 새 대상 선택과 실제 명중 | 첫 적이 사라지기 전부터 다음 적이 사거리 안에 있도록 준비한다. 반복문 밖 적 찾기와 혼동되는 자동 대상 교체는 하지 않는다 |
| 실전 공격 중단 | 실행 중 / 공격 재사용 대기 / 대상 없음 / 사거리 밖 / 프로그램 종료 | 실제 실행 상태에서 표시한다. 마지막 공격 뒤의 대기를 모두 ‘종료’라고 표시하거나, 종료를 단순히 ‘공격 안 함’으로 숨기지 않는다. 과도한 배너 대신 로봇 선택·편집기 상태 표시를 사용한다 |
| 적 무리 사이 공백 | 다음 적 등장 정보와 프로그램 진행 상태 | 유한 반복문은 일반적인 무기한 대기 수단이 아니다. 공격 코드에 if가 없어도 대상 없음·사거리 밖 시도에서 반복이 지나갈 수 있다. 기본 코드에서도 공백이 문제인지 검증한다 |
| 보스 등장 | 초반 일반 적과 보스가 함께 진입 | 보스 출현을 일반 적 전멸 조건에 묶지 않는다. 먼저 등장하는 것만으로 해결됐다고 간주하지 않고, 합법적인 배치에서 보스를 만날 때까지의 반복 진행을 검사한다 |

현재 단계에서는 반복문 의미를 바꾸거나 새 대기 문법을 추가하는 대신 **적이 이어서 공격 범위에 들어오는 짧은 교전 구간**으로 수업을 구성한다. 기본 10회 예시는 검증 출발점이며 통과를 보장하는 확정 숫자가 아니다. 적 공백을 채우려고 숫자만 크게 올리는 조정은 하지 않는다. 적 수·간격·체력·이동 속도·길과 배치 영역을 함께 조정하고, 다양한 허용 위치에서 성립하는지 확인한다.

공백이 긴 전투나 모든 위치에서 안정적인 지속 방어가 꼭 필요하다면, 대기 행동 또는 실행 정책을 별도 설계해야 한다. 이를 해결하지 않은 상태에서 현재 for 예시가 계속 기다려 줄 것처럼 대사를 확정하지 않는다.

| 연결된 블록이 함께 이동할 수 있음 | 두 줄 동시 이동 시 안내 분기를 추가하고 중복 조작 제거 |
| 2-2가 기존 코드만으로 통과 가능 | 새 전사 배치·해당 전사의 반복 코드 완성을 목표와 시작 조건에 반영 |
| 원거리가 공격 블록만 다른 로봇으로 보임 | 같은 위치에서 사거리 차이를 보여 주고 길에서 떨어진 자리의 실제 명중을 관찰 |
| 사격과 attack의 이름 연결이 약함 | ‘attack은 이 원거리 로봇의 사격 명령’으로 직접 연결 |
| 조건문 예시를 따라 쓰면 반복이 먼저 끝날 수 있음 | 기본 힌트는 단순 반복으로 통일하고, 조건문은 동작 설명·검증 조건이 붙은 선택 도움말로 분리 |
| 보스가 늦게 나와 공격 코드가 먼저 끝남 | 보스를 초반 무리와 함께 등장시키고, 대상 공백 문제는 별도 전투 검증 항목으로 명시 |
| 실제로 하지 않은 행동을 성공 대사가 칭찬함 | 조건문 사용·두 역할의 공격을 단정하는 문구를 제거하고, 관찰 완료 신호를 구체화 |
| 재도전 안내가 실패 원인을 단정함 | 기지 파괴·시간 초과 문구를 분리하고 재도전 상태 복원안을 명시 |

## 적용 후 확인 기준

- 2-1: 동일한 적이 사거리 안에 살아 있는 상태에서 한 번 실행 후 종료, 세 번 반복 후 종료가 각각 보인다. 미리보기 재시작이나 적 처치를 반복의 끝으로 오인할 장면이 없다.
- 2-1: 적 찾기와 공격이 실제 for 몸체 안에 있으며, 첫 적 처치 후 다른 적 명중을 관찰한다. 시작 위치 밖에 떠 있는 블록으로 실습 완료를 처리하지 않는다.
- 2-2: 기존 전사만으로 전투 시작 조건을 충족하지 않는다. 새 전사에 `target` 등 다른 변수 이름과 유효한 다른 반복 횟수를 써도 목표를 달성할 수 있다. 미완성 편집기를 닫고 다시 수정할 수 있다.
- 2-3: 소개 위치에서 전사 사거리는 길에 닿지 않고 원거리 사거리는 닿는다. 발사와 명중을 구분해 보여 주며, 기존 전사 배치 때문에 소개 관찰이 막히지 않는다.
- 2-4: 새 원거리의 직접 코딩을 확인하고, 여러 배치 위치에서 실습할 수 있다. 2-3의 배치 제한이 남지 않는다.
- 2-5: 기본 반복 코드와 검증한 응용 코드로 각각 전투를 확인한다. 긴 공백·다른 로봇의 선행 처치 때문에 정상적인 코드가 설명 없이 소진되는지 살핀다. 보스 처치·기지 생존·웨이브 완료를 모두 확인한 뒤 성공 대사가 나온다.
- 공통: 현재 단계의 조작은 이전 단계에서 이미 끝났다면 반복 요구하지 않는다. 새 상태 UI는 실제 실행을 반영하며, 대화창·목표 카드가 배치 영역·공격 관찰·전투 시작 버튼을 가리지 않는다.
- 공통: 대사 넘침·블록 이름·포커스·종료 신호를 확인한 뒤, 실제 처음 배우는 플레이어가 ‘무엇을 반복했는지’와 ‘왜 멈췄는지’를 설명할 수 있는지 관찰한다.

검토 순서: 대사·학습 순서 확인 → 지급·웨이브·상태 표시 조정 → 시퀀스 연결 → 미리보기와 실전 검증 → 초보자 플레이 확인. 위 확인 기준은 아직 실행한 검사 결과가 아니다. 이번 개정에서는 대본 문서만 수정했다.


## 추가 연출 명세 — 화면 위치·진행 조건·실패 대응

이 절은 위 대본의 실행 지침이다. 구현 메모는 플레이어에게 읽어 주지 않는다. 기존 설명과 겹치는 경우 이 절의 구체화된 기준을 적용한다. 신규 UI와 재생 제어는 구현 제안이며, 현재 동작한다고 가정하지 않는다.

### 공통 화면 구성

- 전장 상단: 영상의 웨이브·정비/전투·적 수·시간·코인 정보는 유지한다. 목표는 하단 왼쪽 상태 안내 영역에 배치하고, 자유 실습의 배치·코드 완료 항목은 그 옆에 작게 추가한다. 상단 전체를 새 목표 UI로 대체하지 않는다.
- 전장: 배치 가능 영역과 선택 로봇 사거리를 강조한다. 설명 카드가 적·탄·체력 막대를 가리지 않게 한다.
- 개발창: 영상처럼 왼쪽 로봇 미리보기·상태, 그 오른쪽 블록 팔레트, 오른쪽 넓은 블록 조립 영역을 사용한다. 상단 ‘닫기’로 전장에 복귀한다. 별도 Python 코드 패널을 새로 필수화하지 않는다. 실행 강조는 실제 연결 블록 위에 표시하며, 문서의 Python 예시는 구조 설명용이다.
- 대화창: 화면 아래 전용 안내 공간에 배치한다. 전장·편집 영역을 덮으면 안내 공간을 별도로 확보한다. 공격 관찰 중에는 긴 대화창을 접고 짧은 자막만 남긴다.
- 선택 로봇 옆 또는 개발창: 실행 중 / 공격 재사용 대기 / 대상 없음 / 사거리 밖 / 프로그램 종료를 실제 상태에 맞게 표시한다. 종료는 공격 정지가 아니라 실행기의 종료 신호로 판정한다.
- 관찰 단계는 지정 이벤트를 확인한 뒤 ‘다음’을 활성화한다. 고정 시간만 지나서 성공 대사를 출력하지 않는다. 관찰 실패 시 같은 초기 상태의 다시 보기를 제공한다. 재생 불가라면 진행 오류를 표시하고 성공 대사를 출력하지 않는다.
- 한 번에 현재 조작 하나만 강조한다. 이미 완료한 조작은 다시 요구하지 않는다. 구현 조건을 플레이어 대사로 추가하지 않는다.

### 2-1: 필요성 → 조립 → 예측 → 관찰 → 실전

| 대사 위치 | 화면과 연출 | 진행 조건 |
|---|---|---|
| B01~B03 | 전장에서 배치·사거리 확인 후 개발창. 기초 두 줄을 위에서 아래로 강조. 미리보기는 정지 | 전사 선택과 기초 코드 표시 완료 |
| B04~B05 | 미리보기와 실행 줄 동기화. 한 번 공격 뒤 적은 살아 있고 사거리 안. 마지막 줄 이후 종료 표시 | 공격 1회와 프로그램 종료 확인 |
| B06~B07 | 규칙 연결은 짧게 설명. 편집기 위 비교 카드에서 복제 세 묶음과 for 한 묶음의 동일 결과를 대응 | 사용자가 카드 확인 |
| C01~C05 | for 테두리·안쪽 연결 영역 강조. 숫자 변경 후 두 줄 이동. 함께 이동하면 안내 분기 | 두 줄이 안쪽에 있고 순서가 맞으며 바깥 중복 없음 |
| D00 | 코드 옆 선택 카드. 반복 횟수 예측 후 카드 닫기 | 응답 1회. 오답은 관찰로 교정 |
| D01~D02 | 같은 초기 상태. 몸체 진입 때 회차 증가. 매회 적 찾기 → 베기 실행 줄 강조. 3회 후 테두리 밖으로 화살표 이동 | 3회 실행·적 생존·사거리 유지·프로그램 종료 확인 |
| D03~D06 | 숫자 변경 후 ‘이번에는 적 두 마리’ 장면 전환 자막. 첫 적 처치 뒤 탐색 줄과 새 대상 연결 | 새 대상 탐색과 두 번째 적 실제 명중 |
| E01~E03 | 편집기를 닫고 전투 시작. 하단 목표 유지. 완료 후 작은 반복 몸체 복습 카드 | 웨이브 성공 확인 |

숫자 10은 검증용 예시다. 실전용 확정값을 변경하면 대사·기초 코드·힌트·제공 블록 값을 함께 맞춘다. 3회 비교는 학습용으로 유지한다. 한 번/세 번 비교 장면과 대상 갱신 장면의 적 조건을 명시적으로 구분한다.

### 2-2: 반복문을 직접 구성하는 자율 실습

1. 세 줄 안내 후 새 전사를 지급하고 단계별 포커스·조작 순서 제한을 해제한다.
2. 정답 코드와 안쪽 배치 설명은 기본 화면에 펼치지 않고 선택 힌트에 둔다. 변수 이름 변경은 필수 과제로 요구하지 않는다.
3. 하단 목표는 새 전사 배치와 해당 로봇의 반복 코드 적용을 추적한다. 전투 시작 조건이 부족하면 해당 위치와 연결해 한 가지씩 안내한다. 예: ‘반복할 명령이 아직 비어 있어요.’
4. 유효한 코드지만 횟수가 짧은 경우 전투 진입을 막지 않는다. 실제 종료를 보고 수정·재도전하게 한다. 양의 정수라는 이유만으로 승리를 보장하지 않는다.
5. 실패 뒤 로봇을 선택하면 종료 회차·마지막 실행 줄·대상 상태를 확인할 수 있게 한다. 편집기 밖에서는 선택 로봇의 간단한 상태만 표시한다.

### 2-3: 원거리의 차이를 먼저 관찰

- A04: 같은 위치 기준으로 전사 비교선과 원거리 사거리 원을 보여 준다. 색 외에도 점선/실선과 ‘전사 / 원거리’ 라벨로 구분한다.
- B03: 실제 팔레트 이름을 강조하고 ‘이 사격 블록은 코드에서 attack으로 보여.’라는 보조 설명을 붙인다. Shot과 attack이 별개 명령처럼 보이지 않게 한다.
- B04~B05: 적 찾기의 저장 이름과 공격 괄호의 이름을 강조선으로 연결한다. 변수 블록 조립은 한 단계씩 진행한다.
- C01~C02: 발사 → 탄 이동 → 명중·체력 감소 순서로 관찰한다. 체력 감소 뒤 C02를 표시한다. 반복 회차와 명중 횟수를 구분한다.
- D01: 기존 전사가 공격하는 실제 전투에서도 원거리 명중 기회를 확보한다. 기존 로봇을 몰래 비활성화하거나 실전 중 적 체력을 숨겨 변경하지 않는다.

### 2-4: 위치와 코드의 자율 선택

- 새 원거리 지급 후 2-3의 위치 제한·강제 선택을 해제한다. 로봇을 선택하면 사거리를 표시한다.
- 기본 안내는 목표를 제시하고 정답 구조는 힌트로 남긴다. 새 원거리의 코드 적용을 확인하되 전사 수정·다른 변수 이름·추가 조건문을 허용한다.
- 여러 합리적 위치에서 기본 반복 코드로 공격할 기회가 있는지 검증한다. 모든 배치에서 승리할 필요는 없지만 실패 원인은 상태 표시로 확인할 수 있어야 한다.

### 2-5: 종합 활용과 재도전

- 초반에 보스와 일반 적이 함께 진입한다. 보스 체력과 기지 체력을 분리 표시한다. 위협 정보가 편집·선택을 가리지 않게 한다.
- 공격이 끊기면 상태별 힌트를 연결한다. 프로그램 종료 → 반복 횟수 확인, 사거리 밖 → 배치 확인, 대상 없음 → 적 등장과 탐색 상태 확인. 실패를 무조건 반복 횟수 탓으로 돌리지 않는다.
- 실패 시 배치와 작성 코드는 보존하는 방향으로 구현한다. 재도전에서는 적·기지 체력·시간·실행 위치·회차를 초기화한다. 미구현이면 복원 기능을 대사로 약속하지 않는다.
- 보스 처치·기지 생존·웨이브 완료를 모두 확인한 뒤 성공 대사를 출력한다. 확인하지 않은 조건문 사용이나 모든 로봇의 명중을 칭찬하지 않는다.

| 사격 블록과 attack 이름 혼동 | 2-3에서 팔레트 표시와 코드 이름을 연결하는 연출 명시 |
| 실제 행동 전에 성공 대사가 나올 가능성 | 관찰 이벤트와 진행 조건 명시. 실패 시 다시 보기 또는 오류 처리 |
| 숫자만 크게 넣는 전략 학습 | 종료·사거리·대상 상태별 피드백 분리. 숫자만 키우는 전투 보정 금지 원칙 유지 |
| 신규 기능이 구현된 것으로 오해 | UI·재생 제어는 구현 제안이며 실제 검증이 필요함을 명시 |

### 적용 전 남은 검증 조건

1. 공격 명령의 쿨타임·대상 없음·사거리 밖에서 반복이 어떻게 진행되는지 실제 실행기로 확인한다. 일반적인 for 문법과 게임 공격 명령의 시간 처리를 구분한다.
2. Stage 1의 자동 재실행과 Stage 2 전환 규칙이 실제 구현과 일치하는지 확인한다. 다르면 B06을 실제 규칙에 맞게 변경한다.
3. 기본 반복 코드·여러 합리적 배치·기존 로봇의 선행 처치를 포함해 2-1~2-5를 검증한다. 대상 공백으로 반복이 소진되는 상황을 기록한다.
4. 정상 코드가 긴 공백 때문에 학습 목표를 수행하지 못하면 전투 구성을 먼저 수정한다. 자유 배치 범위를 지나치게 제한해야만 성립한다면 대기 행동 또는 실행 정책을 별도 설계하고 대본도 재검토한다. 숨은 자동 재실행으로 통과시키지 않는다.
5. 초보자에게 ‘무엇을 몇 번 반복했는가’, ‘왜 프로그램이 끝났는가’, ‘다음 적을 다시 찾는 줄은 어디인가’를 물어 본다. 코드 완성·승리만으로 개념 이해를 판정하지 않는다.

최종 문서 판단: 제시한 스테이지 구조에서 반복문 소개·직접 적용·원거리 전이·종합 활용의 흐름은 적절하다. 발견한 설명·연출상의 문제는 위와 같이 수정했다. 실행 정책과 전투 구성의 적합성은 실제 게임 검증 전까지 미확정이다.


## 사용자 확인 블록 사양 반영

- for: `for i in range(10):` 형태로 기본 생성된다. 2-1에서는 블록 하나 배치 → 기본 숫자 10을 3으로 변경 → 안쪽에 기존 두 명령 이동 순서로 진행한다. 반복 변수나 range를 따로 끼워 넣도록 안내하지 않는다.
- while: `while True:`로 고정된다. 이 구조 자체에는 정해진 반복 횟수가 없으며, 프로그램 외부의 중단이나 별도 종료 수단이 없는 한 반복을 계속한다. 게임 공격 명령의 대기·실패 처리는 실제 실행기 검증이 필요하다.
- 이번 2-1은 정해진 횟수와 종료를 비교하는 for 수업으로 유지한다. while을 기본 힌트나 보스 정답에 추가하지 않는다. while을 허용하면 자유 실습의 for 목표와 별도로 취급하며, while만 있는 코드를 for 학습 완료로 판정하지 않는다.
- while True를 추가로 가르칠 경우에는 반복 횟수 숫자가 없다는 차이, 중단 방법, 적이 없을 때의 실행 동작을 별도 수업에서 확인해야 한다. 현재 사양만으로 break·대기 명령의 존재를 가정하지 않는다.

재검토: for의 기본 숫자 10은 기존 흐름과 일치한다. 다만 별도 숫자 블록을 추가하도록 오해할 수 있던 C02의 재고 안내는 삭제했다. while True 고정 사양은 현재 for 소개의 오류를 만들지는 않으므로 학습 범위를 확장하지 않았다.

### 기존 UI 안에서의 구체적 연출

1. **배치:** 하단 로봇 목록을 먼저 강조하고 선택 후 전장으로 포커스를 옮긴다. 길과 사거리 원이 겹치는 부분을 짧게 강조한다. 관찰 대상 위에 긴 대화창을 놓지 않는다.
2. **개발 진입:** 배치된 로봇과 개발 진입 UI를 순서대로 강조한다. 영상만으로 개발 버튼의 모든 노출 조건은 확인되지 않으므로 실제 선택 UI에 연결한다.
3. **조립:** 팔레트의 for 블록 → 조립 영역의 삽입 위치 → 기본 숫자 10 → 안쪽 연결 영역 순서로 강조한다. 드래그하는 동안 대화창이 삽입 위치를 가리지 않게 위나 아래 여유 공간으로 이동한다.
4. **관찰:** 왼쪽 미리보기를 가리지 않는 위치에 한 줄 자막을 둔다. 실제 블록의 실행 순서와 로봇 행동을 동기화한다. 1회/3회 비교에서만 재생을 통제하고, 소개가 끝나면 일반 개발창의 동작으로 복귀한다.
5. **전투 진입:** 개발창 상단 ‘닫기’를 강조한 뒤 전장으로 돌아오면 우측 하단 ‘전투 시작’을 강조한다. 두 버튼을 동시에 누르라고 안내하지 않는다.
6. **자동 전투:** 긴 설명을 접고 전장과 기지 체력을 보여 준다. 특정 행동 관찰이 필요하면 짧은 자막·대상 테두리를 사용한다. 영상에 배속 UI가 보이지만 튜토리얼을 위해 강제로 배속을 변경하는 기능은 별도 확인 없이 가정하지 않는다.
7. **결과:** 실제 웨이브 결과 창 확인 후 보상과 다음 정비로 연결한다. ‘보상 수령’은 실제 버튼 명칭과 일치할 때 사용한다. 영상에서 해당 문구의 클릭 절차가 명확히 확인되지 않으므로, 연결 시 실제 라벨을 확인하고 E03 등 종료 대사의 버튼 명칭을 일괄 맞춘다.

### 재검토에서 추가로 고친 점

- 개발창 오른쪽은 블록 조립 영역인데 별도 Python 코드 패널이 필수인 것처럼 읽힐 수 있어 수정했다. 문서의 코드 예시는 유지하되 실제 조작은 블록으로만 안내한다.
- 새 목표를 전장 중앙 상단에 고정하면 영상의 웨이브 정보와 충돌할 수 있어 하단 상태 안내 영역으로 통일했다.
- 영상의 실제 체력 표시는 ‘기지’이므로 대사의 ‘코어’를 ‘기지’로 통일했다.
- 전투 중 수정 가능 여부를 가정하지 않도록 코드·배치 조정은 정비와 재도전 준비로 연결했다.
- 영상의 홍보 자막과 튜토리얼 대화창 위치를 고정 규칙으로 복제하지 않았다. 실제로 봐야 할 로봇·탄·블록을 가리지 않도록 위치를 조정한다.
- 실행 회차·프로그램 종료·재생 보류·예측 문항·목표 체크는 영상에서 확인된 기능이 아니라 추가 제안이다. 구현 전에는 기존 기능처럼 대사를 연결하지 않는다. 특히 1회/3회 비교를 구현할 수 없다면 그 관찰에 의존하는 대사를 그대로 적용하지 않는다.

최종 판단: 영상의 ‘배치와 코드로 전략을 정하고 자동 전투로 결과를 확인하는 플레이’와 Stage 2 구조는 잘 맞는다. 필수 플레이 흐름은 유지하고 반복문 설명은 개발창 안에 넣었다. 남은 핵심 확인 사항은 실제 실행 정책과 미리보기 제어이며, 영상에서 로봇이 계속 공격하는 모습만으로 for 또는 while의 실행 방식을 추정하지 않는다.


## 실제 프로젝트 적용 시 조정

- 일반 캠페인의 스테이지 전환은 기존 배치와 코드를 유지한다. 새 스테이지를 직접 시작하면 배치가 없을 수 있다. 2-1은 새로 놓은 실습 전사를 추적하므로 기존 전사를 삭제하지 않는다. 위의 초기화 연출 제안은 적용하지 않는다.
- 2-3은 실제로 사거리가 닿는 자유 위치에 배치하고, 통제된 개발창 미리보기에서 전사보다 먼 거리의 명중을 관찰한다. 위의 특정 배치 영역 강제·점선 비교선은 이번 적용에서 사용하지 않는다.
- 2-1 한 번/세 번 비교·대상 갱신 및 2-3 원거리 관찰용 미리보기 제어를 추가한다. 실전은 기존 실행 정책을 유지한다.
- 이번 적용에서는 블록 종류와 반복 회차·종료 상태를 표시한다. 개별 실행 줄을 따라 이동하는 화살표는 별도 기능으로 남긴다.
- 실패 후에는 기존 ‘이 스테이지 재도전’ 흐름을 유지한다. 웨이브별 배치·코드 복원 기능은 추가하지 않으며 이를 보장하는 안내는 하지 않는다.


## 미리보기 반복 재생 사양 — 사용자 확인 반영

이 절은 이전의 재생 보류·자동 재시작 금지 제안보다 우선한다. 미리보기는 일정 간격으로 계속 재생되는 기존 방향을 유지한다. Stage 2 개발창에서도 설명·조립 중 재생을 막지 않는다.

- 한 차례 안의 프로그램 실행과 차례 사이의 미리보기 자동 재생을 구분한다. 전자는 코드의 의미이며 후자는 편집기의 시연 기능이다.
- 소개용 1회 실행·3회 반복은 마지막 공격의 명중까지 확인한 뒤 기존 미리보기와 같은 1초 간격으로 장면을 다시 재생한다. 상태에 ‘프로그램 종료 · …초 후 미리보기 다시 재생’을 표시한다.
- 횟수는 차례마다 초기화한다. 코드가 바뀌면 새 코드로 소개 장면을 다시 시작해 이전 실행 상태를 섞지 않는다.
- B04·B05·D02는 ‘계속 멈춰 있음’ 대신 ‘한 차례에 몇 번 실행되는가’를 설명하도록 수정했다.
- 실전 실행 횟수와 재시도 정책은 변경하지 않는다. 미리보기의 자동 재생이 실전에서도 실행되는 것으로 설명하지 않는다.


## Stage 2 반복문 소개 강조 개선

Stage 1 기능을 유지하며 2-1 개발창에서만 다음 연출을 추가한다. 노란 ①은 실제 for의 숫자 입력칸, 청록 ②는 실제 몸체 영역에 붙인다. 라벨과 테두리는 블록 이동·배율 변경에 따라 위치를 갱신하며 클릭을 가로채지 않는다.

- C01: 팔레트의 for 블록을 노란 테두리와 배치 안내로 강조한다.
- C02: 실제 숫자 칸에 ‘① 반복 횟수 · 10을 3으로’ 표시.
- C03~C04: 실제 안쪽 영역에 ‘② 반복할 명령 묶음’ 표시하고 적 찾기와 베기를 넣게 한다.
- C05·D00: 숫자 칸과 몸체를 동시에 강조해 횟수와 내용을 연결한다.
- D01~D02: 몸체 옆에서 실제 프로그램의 반복 회차를 표시하고 미리보기와 코드 영역을 함께 밝힌다. 한 차례 종료와 미리보기 자동 재생을 구분한다.
- D03: 숫자 칸만 다시 강조해 3 → 10 변경을 유도한다.
- D04~D06: 몸체를 강조해 적 찾기도 매번 실행된다는 점을 연결한다.
