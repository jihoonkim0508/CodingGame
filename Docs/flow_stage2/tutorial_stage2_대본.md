## 읽는 법과 우선순위

- `[2-1.A01] 발화자 : 대사`는 대화 한 줄의 고유 ID다. 발화자는 줄마다 저장한다. `시스템`은 대화창 대신 UI 배너에 표시한다.
- `집중`·`상호작용`·`추가 효과`·`목표 UI`는 원본의 연출·진행 요구이며 발화하지 않는다. 힌트는 버튼을 눌렀을 때만 보여 준다.
- §3은 원문을 유지하고 대사·힌트에 ID만 붙인 것이다. 구간별 A/B/C는 원본 소제목 순서다. 구현 시 대사 ID와 `TutorialStep.stepId`는 별도로 관리할 수 있다.
- `구현 제안`은 원문에서 정하지 않은 부분을 개발할 수 있도록 채운 초안이다. 기획 확정이나 사용자 승인으로 취급하지 않는다. Stage 1의 Pn 결정 번호를 새로 부여하거나 Stage 2의 확정 근거로 확장하지 않는다.
- 새 Stage 2 대본의 학습 순서를 기준으로 한다. 기존 커리큘럼의 감속·유틸형·버퍼·분기 수업을 이 대본에 섞지 않는다.
- 원본과 코드가 충돌하는 지점은 §7에 명시했다. 원문과 다른 대사를 사용할 경우 §7의 교정 제안을 적용했다는 기록을 남긴다.

## 1. 학습 구성과 진입 상태

| 구간 | 학습 목표 | 플레이 방식 | 완료에 필요한 관찰 |
|---|---|---|---|
| 2-1 | for 안의 두 명령·실행 순서·3회 반복·반복 종료 | 전사 1대 배치 → 두 줄 시연 → 플레이어가 for로 감싸기 | 1/3 → 2/3 → 3/3, 프로그램 종료, 실제 웨이브 결과 |
| 2-2 | 적 찾기와 공격을 같은 반복문 안에 직접 구성 | 전사 직접 배치·코드 조립, 선택형 힌트 | 해당 전사의 반복 코드와 전투 결과 |
| 2-3 | 원거리 배치·사거리·attack·발사와 적중의 차이 | 원거리 1대 배치, 준비된 반복문에 사격 연결 | 해당 원거리의 발사 → 탄 이동 → 적중 → 체력 변화 |
| 2-4 | 원거리의 위치와 반복 코드를 직접 구성·수정 | 원거리 직접 배치·코드 조립, 선택형 힌트 | 직접 배치·작성한 원거리의 실행과 전투 결과 |
| 2-5 | 두 직군의 반복 코드·사거리 활용 | 기존 전사·원거리 점검·수정 후 보스전 | 보스 처치와 웨이브 완료를 함께 확인 |

**기존 규칙 재사용:** 같은 스테이지에서는 맵·로봇·코드를 유지하고 다음 웨이브로 진행한다. Stage 1 → Stage 2 전환 시 배치·코드를 초기화한다. 블록은 시작 위치에 연결된 프로그램만 실행하며, 편집 내용은 자동 적용한다. 미완성 블록 초안과 마지막 컴파일 성공 프로그램을 구분한다.

**Stage 2 진입 시 필수:** Stage 2의 `For` 지급이 준비 시작 전에 반영되어야 한다. `DefenseSimulation.LoopsUnlocked`가 참이면 실제 전투의 함수 실행 한도는 1회다. for 없이 두 줄을 놓은 시연과 for 내부 3회 반복을 구분한다. 자동 공격으로 빠진 코드를 보충하지 않는다.

**구현 제안 — 지급 최소안:** 아래는 새 실습에 필요한 추가 지급량이다. 이전 스테이지 보상 복원분과 중복되는지는 실제 캠페인 asset에서 확인한다. 다른 로봇에 예약된 블록까지 고려해 부족하지 않게 지급한다.

| 준비 구간 | 추가 로봇 | 추가 블록 | 사용 목적 |
|---|---|---|---|
| 2-1 | 전사(`Warrior`) ×1 | `For`, `Number`, `DeclareVariable`, `NearestEnemy`, `Slash`, `Variable` 각 1 | 전사 두 줄 시연 후 for를 플레이어가 연결 |
| 2-2 | 전사 ×1 | 위 전사용 6종 각 1 | 기존 코드를 지우지 않고 새 전사로 독립 실습 |
| 2-3 | 원거리(`Shooter`) ×1 | `For`, `Number`, `DeclareVariable`, `NearestEnemy`, `Shot`, `Variable` 각 1 | for·적 찾기 골격을 준비하고 플레이어가 attack·대상 연결 |
| 2-4 | 원거리 ×1 | 위 원거리용 6종 각 1 | 새 원거리에 반복문 전체를 직접 구성 |
| 2-5 | 없음 | 없음 | 앞서 받은 두 직군과 코드를 재사용 |

각 구간 지급은 해당 시도에서 한 번만 한다. 편집기 재진입이나 힌트 확인으로 재지급하지 않는다. `Shot`은 내부 재고 종류이고, 플레이어에게 보여 주는 함수 이름은 `attack`이다. 보상 종류·수량은 원본에 없으므로 신규 수치를 확정하지 않는다. 보상을 사용하면 기존 결과/보상 수령 흐름을 연결하되, 학습 완료 전에 다음 웨이브로 넘어가지 않게 한다.

## 2. 실행·UI·판정 공통 규칙

| 항목 | 구현 기준 |
|---|---|
| 정답 구조 | 연결된 AST의 `For.Body` 안에 적 저장 → 해당 변수를 대상으로 한 직군 공격 순서가 있어야 한다. 팔레트나 떨어진 블록은 세지 않는다. |
| 변수 이름 | `enemy`는 예시다. 같은 반복 회차에서 저장한 이름을 공격이 참조하면 다른 유효한 변수 이름도 허용한다. |
| 반복 횟수 | 2-1만 3으로 고정. 자유 실습은 1 이상의 정수를 받는 것을 제안한다. 소수·빈 입력·0·음수는 학습 목표 미충족으로 표시한다. 런타임 자체의 range 허용 범위와 튜토리얼 목표 검사를 분리한다. |
| 회차와 공격 | 내부 회차가 시작될 때 1부터 표시한다. `i`의 0부터 시작하는 값, 함수 완료 횟수, 공격 성공 수, 처치 수를 회차로 쓰지 않는다. |
| 현재 실행 줄 | 실제 실행기의 명령 위치와 블록 ID를 연결한다. 공격 쿨다운 대기 중에는 같은 명령을 유지한다. 다음 회차 진입은 실제 `ForNext` 이후에만 표시한다. |
| 실행 종료 | `ForTest`가 거짓이 된 뒤 다음 명령으로 이동한다. 아래에 명령이 없으면 프로그램 종료 표시. 세 번째 공격 성공만으로 종료 처리하지 않는다. |
| 미리보기 | 기존 일반 미리보기는 자동 적용·무제한 재시연이다. 2-1은 단일 호출을 회차별로 자동 시연하고 대화창 다음 화살표로 넘어간다. 미리보기 내부 클릭 버튼은 없다. 실제 전투·재고·보상에는 영향을 주지 않는다. |
| 사거리 | 로봇 선택·배치 시 실제 사거리 원을 보여 준다. 길과의 겹침은 배치 힌트이며 원본상 강제 설치 제한은 아니다. 잘못 놓아도 수정할 수 있게 한다. |
| 안내 수업 | 2-1·2-3은 해당 행동에 필요한 UI를 허용하고 완료 조건을 충족하면 진행한다. 클릭만으로 코드 완성을 인정하지 않는다. |
| 자유 실습 | 2-2·2-4·2-5는 짧은 안내 뒤 대화창을 숨기고 목표 UI를 남긴다. 배치·편집·닫기·재열기·변수 이름 변경을 자유롭게 허용한다. |
| 미완성 코드 | 편집기를 닫을 수 있다. 시작 시 현재 초안과 적용 프로그램의 유효성을 확인해 목표 미충족 사유를 보여 주고 수정하게 한다. 마지막 성공 프로그램을 현재 초안의 완성으로 오인하지 않는다. |
| 힌트 | Stage 1과 같은 `hintCode` 예시 코드 팝업을 재사용한다. 2-2는 for + 적 찾기 + slash, 2-4는 for + 적 찾기 + attack, 2-5는 선택 직군에 맞는 코드다. 자동 삽입·자동 정답 연결·강제 열람을 하지 않는다. 원본 C01~C04 조언 목록은 수령 기록으로만 남긴다. |
| 시스템 알림 | 일반 구역 진입은 `Calm`(서서히 등장, 경고음·배지 없음), 로봇 해금은 `Positive`(청록·금색, 상승 음), 적·보스 접근은 `Warning`(빨간 경고)으로 지정한다. 2-1~2-4의 `EnemyWarning`과 2-5 A01 경고는 모두 웨이브 시작 전에 표시한다. |
| 관찰 완료 | 발사·적중·회차 이벤트는 대상 로봇과 현재 실행에 귀속한다. 다른 로봇, 이전 미리보기, 이전 웨이브 이벤트로 통과하지 않는다. |
| 성공 대사 | 실제 학습 조건과 전투 완료를 확인한 뒤 표시한다. 보스 성공은 보스가 누출·소멸한 상태가 아니라 실제 처치된 상태여야 한다. |
| 실패 | 성공 대사·보상·다음 웨이브를 차단한다. 2-5 패배는 원본대로 선택창을 유지하며 2-1부터 재시작하거나 기존 바탕화면 동작으로 나간다. |

아래 코드는 플레이어가 블록으로 작성할 내용의 Python 표시 예시다. 텍스트 직접 입력을 요구하지 않는다. 함수 머리줄은 편집기가 만든다.

전사 반복 코드(2-1은 `N = 3`, 나머지는 플레이어 선택):

```python
for i in range(3):
    enemy = get_nearest_enemy()
    slash(enemy)
```

원거리 반복 코드(횟수 3은 예시):

```python
for i in range(3):
    enemy = get_nearest_enemy()
    attack(enemy)
```

### [2-1 — 반복문 알아보기]

#### 게임 시작과 목표

[2-1.A01] (UI로 표시) 시스템 : 새로운 구역에 도착했습니다!

[2-1.A02] 안내자 : 이번 구역에서는 <b>반복문</b>을 배워 볼 거야.

[2-1.A03] 안내자 : 먼저 전사 로봇을 배치하고, 적을 찾고 공격하는 명령이 어떻게 실행되는지 살펴보자.

집중 : 전사 로봇 선택 UI, 배치 가능한 영역, 적이 이동하는 길

상호작용 : 플레이어가 전사 로봇을 선택하고 배치한다.

#### 반복문 없이 한 번 실행하기

[2-1.B01] 안내자 : 방금 배치한 전사를 선택하고 개발창을 열어 봐.

집중 : 배치한 전사, 개발 버튼

추가 효과 : 전사를 선택하면 개발 버튼을 알아보기 쉽게 강조한다.

상호작용 : 플레이어가 전사를 선택한 뒤 개발 버튼을 눌러 코드 편집기를 연다.

[2-1.B02] 안내자 : 코드가 위에서 아래로 실행되는 걸 확인해 보자.

[2-1.B03] 안내자 : 먼저 적을 찾고, 다음 줄에서 찾은 적을 공격해.

집중 : `enemy = get_nearest_enemy()`와 `slash(enemy)`를 순서대로 강조하고, 왼쪽 미리보기에서 대응하는 행동을 보여 준다.

상호작용 : 플레이어가 미리보기 실행을 시작한다.

[2-1.B04] 안내자 : 두 줄이 한 번씩 실행됐어. 같은 동작을 여러 번 하려면 명령을 여러 묶음 놓을 수도 있지만, 더 간단한 방법이 있어.

#### for 반복문 만들기

[2-1.C01] 안내자 : <b>for 블록</b>을 코드 시작 부분에 놓아 보자.

집중 : for 블록, 코드의 시작 위치

상호작용 : 플레이어가 for 블록을 코드 시작 위치에 연결한다.

[2-1.C02] 안내자 : for 블록 안에 들어간 명령이 되풀이할 내용이야. 적 찾기와 공격 두 줄을 안쪽에 넣어 줘.

집중 : for 블록의 안쪽 연결 영역, 적 찾기와 공격 블록

상호작용 : 플레이어가 적 찾기와 공격 블록을 for 안에 순서대로 연결한다.

[2-1.C03] 안내자 : for 옆의 숫자를 <b>3</b>으로 바꿔 보자. 이 숫자는 안쪽 명령 묶음을 실행할 횟수야.

집중 : for 블록의 반복 횟수 입력칸

상호작용 : 플레이어가 기본 숫자를 3으로 바꾼다.

집중 : 화면 중앙의 실패 선택 창과 선택 버튼

추가 효과 : 실패 시 진행 중인 전투를 종료하고 실패 선택 창을 표시한다. 선택지는 `튜토리얼 2 다시 시작`과 `바탕화면으로 나가기`로 구성한다. 플레이어가 선택할 때까지 창을 유지한다.

#### 실패 선택: 튜토리얼 2 다시 시작

상호작용 : 플레이어가 `튜토리얼 2 다시 시작` 버튼을 누른다.

추가 효과 : 2-5만 재시작하지 않고 튜토리얼 2의 첫 구간인 2-1 시작 상태로 돌아간다. 튜토리얼 2 진행도와 웨이브 상태를 초기화하고, 2-1의 안내·배치·코드 실습부터 다시 진행한다.

[2-5.C01] 안내자 : 좋아, 처음부터 다시 연습해 보자! 반복문부터 차근차근 확인하면 두 로봇을 함께 활용할 수 있을 거야.

집중 : 2-1 시작 화면, 튜토리얼 2 목표와 전사 배치 안내

#### 실패 선택: 바탕화면으로 나가기

상호작용 : 플레이어가 `바탕화면으로 나가기` 버튼을 누른다.

추가 효과 : 현재 게임의 바탕화면 이동 동작을 실행한다. 버튼 동작은 기존 게임 규칙에 연결한다.

## 4. 단계별 진행 조건과 연출 연결

이 절은 **구현 제안**이다. `다음`은 일반 대사 읽기 완료 후 다음 버튼을 뜻한다. 행동 단계는 실제 조건을 충족해야 통과한다. 아래 이름 중 신규 이벤트는 §6의 제안 계약이며 현재 API에 이미 존재한다는 뜻이 아니다.

### 4.1 2-1 — 전사와 for 소개

| 단계/대사 ID | 진입·준비 | 집중/입력 | 완료 조건·다음 동작 |
|---|---|---|---|
| A01~A03 | Stage 2 준비, 2-1 보급 반영 | 배너 → 전사 버튼·땅·길 | A03 읽은 뒤 전사 선택·배치 대기. 유효한 전사 `RobotPlaced`를 받아 그 ID를 `teachingWarriorId`로 저장 |

| B02~B03 | 두 줄 예제 `enemy = get_nearest_enemy()` / `slash(enemy)` 준비 | 현재 실행 줄과 미리보기 | 단일 실행을 자동 시연. 관찰 완료 후 대화창 다음 화살표로 진행 |

| C06 | 3회차 진입 | 3/3·마지막 명령·반복 종료 | 세 번째 Body 실행과 for 종료를 확인 |

| D01-시작 | 편집기 닫힘 | `Battle.Start`, 대화창은 버튼을 피함 | `BattleStarted` 후 전투 관찰. 두 행동을 하나의 클릭 조건으로 합치지 않음 |
| D02 | 현재 웨이브 `WaveCleared` + 학습 조건 | 결과 UI·전사·코드 | 대사 확인 → 기존 결과 수령/진행 동작 → 2-2 준비. 패배에는 표시하지 않음 |

**단계 관찰 모드:** 실제 실행기의 위치·회차를 표시하고 해당 명령 묶음을 자동 재생한다. 관찰한 회차에서 상태를 유지하고 기존 대화창의 다음 화살표로 다음 설명과 회차를 진행한다. 미리보기 내부 실행 버튼은 제공하지 않는다. 실행 중 코드가 바뀌면 관찰 기록을 버리고 새 코드로 다시 시작한다. B의 for 없는 함수는 정확히 1회, C의 함수는 정확히 1회 호출하며 내부 for만 3회 실행한다. 일반 `DefenseAttackPreview`의 무제한 함수 재호출을 이 시연에 그대로 사용하지 않는다.

현재 실행기는 공격에 성공하지 않은 함수 호출을 다시 시도할 수 있다. 따라서 B04의 “한 번씩”은 성공 공격 수나 기존 `CompletedRuns` 수가 아니라 관찰 모드에서 해당 두 명령을 한 번 실행했는지로 판정한다. 대사만 1/3 → 2/3 → 3/3으로 넘기는 가짜 타이머 시연은 사용하지 않는다.

## 5. 웨이브 전환·재도전·초기화

원본은 2-2·2-4의 수정 기회를 요구하고 2-5의 **패배**에는 2-1부터 재시작하도록 명시한다. 두 상황을 구분하기 위한 다음 동작은 구현 제안이다.

| 상황 | 처리 |
|---|---|
| 준비 중 미완성·변수 불일치·for 외부 공격 | 시작을 막고 구체적인 목표 미충족 사유 표시. 편집기 닫기·재열기·배치 수정 허용 |

Stage 2 진입 시 기준 재고/이전 스테이지 보상은 기존 규칙에 따라 복원하고, 이번 시도의 Stage 2 보상·추가 지급·예약은 제거한다. 이어 2-1 준비 보급을 한 번만 지급한다. 전투 배속·정지·선택·배치 모드·카메라·회차 UI·로봇 ID 참조·힌트·대화 완료 이력도 초기화한다. 기존 `Restart()`의 `stage`가 2인지, `InitialWave`가 첫 웨이브인지, `PreviousStageRewards` 복원이 새 지급안과 일치하는지 확인한다.

## 7. 원본과 현재 구현의 차이·교정 제안

### Q1. ‘사거리와 공격력이 반비례’의 의미

원본 `2-3.C01~C02`, `2-4.B01`, `2-4.C04`는 **로봇의 공격 사거리 스탯이 길수록 공격력이 낮아진다**고 말한다. 현재 [DefenseModels.cs](../../Assets/!_Project/Scripts/Defense/DefenseModels.cs)의 `Rules.RangedDamageFactor(range, distance)`는 `range / max(1, distance)`이고, [DefenseSimulation.cs](../../Assets/!_Project/Scripts/Defense/DefenseSimulation.cs)의 원거리 attack 피해에 적용된다. 이는 같은 원거리의 **대상까지 거리가 멀수록 피해가 낮아지는 규칙**이며, 사거리 스탯 간 반비례와 다르다.

**구현 제안:** 현 전투 규칙을 유지하고 아래 문장으로 교정한다. 원본은 §3에 보존한다. 기획이 사거리 스탯 간 반비례를 의도했다면 별도 전투 규칙·비교 UI 설계가 필요하며, 이 문서에서 임의 공식·로봇 종류·스탯 조작 실습을 추가하지 않는다. 방향이 확정되지 않은 상태에서는 모순된 설명을 게임에 연결하지 않는다.

| ID | 현 규칙 기준 교정 제안(미확정) |
|---|---|
| 2-3.C01 | 안내자 : 원거리 로봇은 같은 적이라도 거리에 따라 주는 피해가 달라져. |
| 2-3.C02 | 안내자 : <b>같은 로봇이라면, 사거리 안에서 적이 가까울수록 피해가 커지고 멀수록 작아져.</b> |
| 2-4.B01 | 안내자 : 공격 범위가 적이 지나는 길에 닿는지 확인해. 같은 원거리 로봇은 사거리 안에서 적이 가까울수록 피해가 커진다는 점도 생각해 보자. |
| 2-4.C04 | 힌트 4 : 같은 원거리 로봇도 적까지의 거리에 따라 피해가 달라져요. 배치와 공격 결과를 함께 살펴보세요. |

비교 화면은 같은 로봇·같은 스탯·같은 적 방어 조건에서 두 공격 거리를 보여 주고 실제 적용 피해를 표시하는 방식을 제안한다. 기존 HUD의 기본 피해 숫자만 강조해서 거리별 피해를 증명했다고 처리하지 않는다.

### Q2. 사거리 판정 시점

현재 `DefenseSimulation.RequestAction`의 공격 처리에서 범위를 검사하고 발사한 뒤, 탄 도착 시 `ResolveProjectiles`에서 대상에 피해를 준다. 발사 이후 대상이 사거리 밖으로 이동했을 때 재검사하는 구조와는 다르다. 원본 `2-3.B07`의 “사거리 안의 적만 맞힐 수 있어”를 도착 순간까지 보장한다고 가르치면 안 된다.

**교정 제안(미확정):** `안내자 : 원거리 로봇은 사거리 안의 적에게 탄을 쏠 수 있어. 배치할 때 사거리와 길이 겹치는지 확인하자.` 적중 때도 사거리를 검사해야 한다는 기획이라면 피해 판정 변경을 별도로 구현·검증한다.

### Q3. ‘바탕화면으로 나가기’ 목적지

원본은 기존 게임의 바탕화면 이동 동작을 호출하라고 하지만, 확인한 `GameFlow.cs`의 공개 씬 상수는 `Title`, `Stage`, `Defense`다. 이 코드만으로 원본의 ‘바탕화면’이 어떤 화면인지 확정할 수 없다. 구현은 기존 프로젝트의 실제 해당 동작을 찾아 연결하고, 없으면 목적지 확인이 필요한 항목으로 남긴다. `Application.Quit()`, 타이틀, 스테이지 선택 중 하나를 임의로 선택하지 않는다.

### Q4. 원본에서 정하지 않은 전투 데이터

적 종류·수·체력·속도·스폰 간격·보스 수치·보상 수량·2-1~2-4 패배 처리 세부값은 원본에 없다. §1의 지급 최소안과 §5의 재도전은 개발 초안이다. 기존 asset 수치를 출발점으로 사용하되, 새 코드와 지급량으로 실제 플레이 가능한지 검증해서 조정한다. 2-1은 내부 명령 3회 실행을 보여 줄 수 있게 하고 **3회 공격 = 3처치**를 통과 기준으로 두지 않는다. 2-5 보스가 강제로 코어를 무시하거나 무조건 패배하도록 만들지 않는다.
