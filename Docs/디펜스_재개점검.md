# 디펜스 재개 점검

2026-09-22 · v0.11.1

원래 요청을 현재 코드와 `Defense.unity`에 대조했다. 아래에서는 이전 구현과 이번 재개에서 수정한 내용을 구분한다.

## 이번 재개에서 수정한 사항

### 인벤토리·보상창·툴팁 표시 순서

`UpcomingCards`가 인벤토리와 툴팁보다 뒤의 형제 순서에 저장되어 적 카드가 팝업 위에 그려졌다. 툴팁과 겹치면 설명을 가릴 수 있었다. 기존 오브젝트와 참조를 유지하면서 Unity MCP로 순서만 수정했다. 전장 HUD 위에 보상창, 인벤토리, 툴팁 순서로 표시한다.

검증: 인벤토리가 열렸을 때 적 카드 좌표의 첫 Raycast 결과는 `Inventory`이며 적 툴팁이 열리지 않는다. 닫으면 같은 좌표에서 일반병 툴팁이 열린다. 인벤토리의 버프형 카드 설명도 정상 표시된다.

![수정 후 인벤토리와 배경 카드](Defense-audit-inventory-after.png)

### 35초 종료 후 남은 시간 표시

고정 틱의 누적 오차로 종료 순간 `WaveRemaining`이 약 `7.03e-13`이었다. 이를 올림한 HUD는 `01s`를 표시했다. 전투 종료 판정과 동일한 허용 오차를 적용하여 남은 시간을 정확히 0으로 반환한다.

검증: 실제 씬의 35초 종료 뒤 상단 `00s`, 보상 수령 뒤 다음 웨이브 `35s`를 확인했다. 시간 만료 뒤 정확한 0 반환과 다음 정비 단계의 35초 복구를 회귀 테스트에 추가했다.

## 검증 범위와 결과

- `rtk proxy dotnet run --project Tests/Defense/Defense.Check.csproj`: 전투 55개, 코드/호환 45개, 캠페인 83개, 총 **183개 통과**.
- Unity 재컴파일 성공, Console 오류 0개. 변경한 HUD·코드 편집기·툴팁의 필수 참조 누락 0개. 씬 저장 상태 확인.
- 이번 재개는 코드·씬 대조와 Unity MCP Play Mode 검증이다. 포인터 검증은 Raycast 및 Input System에 입력을 주입했으며 사람이 수동 플레이한 결과는 아니다.
- 5웨이브 완주·52처치·52블록 수령 기록은 이전 검증 결과이며 이번 재개에서 다시 수행했다고 주장하지 않는다.
- 이 요청에서 남은 구현 항목은 발견되지 않았다. 사용자가 나중으로 미룬 미리보기 상세 기획은 추가하지 않았다.
