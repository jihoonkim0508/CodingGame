### 최신 요구사항과 적용 정책

- v0.12.1: 로봇 설명은 마우스 좌표가 아니라 hover한 로봇 선택 버튼을 기준으로 바로 위에 표시한다. 화면 밖으로 나가면 안쪽으로 보정한다. 하단 목록과 인벤토리 모두 적용하며, 모든 로봇이 같은 한 위치를 공유하던 방식은 교체한다.
- v0.12: 기지 체력바는 기지 아래에 표시한다. 적 설명은 해당 적 이미지 바로 오른쪽에 표시한다. 미리보기는 열려 있는 동안 반복한다. 현재 반복 주기는 8초이며 시연 종료·코드 변경 시에도 새 시연을 시작하고 실제 자원은 변경하지 않는다.
- v0.11: 상단바 상태는 `정비 중 / 전투 중`으로 구분하고 텍스트를 가운데 정렬한다. 일시정지·배속은 상단바 아래 우측에 전투 중에만 표시한다. 일시정지 상태도 전투 상태로 취급한다. F 키로 배속을 전환하고 버튼 아래 F를 표시한다.
- 하단 회수 버튼·로봇 선택 안내와 인벤토리 버튼은 제거한다. Tab 인벤토리는 유지한다. 회수는 로봇 선택 시 좌측 스탯 패널 우측 하단에 둔다.
- 코드 패널 미리보기에는 선택 로봇 한 대만 생성한다. 기존 버프 시험용 추가 아군은 제거한다. 미리보기 상세는 후속 기획 대상이다.
- `다음 웨이브` 아래에 적별 임시 이미지·수량을 표시하고 hover 시 이름·설명을 제공한다. 하단 로봇 카드에도 짧은 설명을 제공한다.
- 코드 블록 우클릭은 해당 블록과 내부 인자·본문을 삭제하고 뒤 명령 연결을 유지한다. 기존 코드 묶음의 자유 이동을 허용하며, 최초 팔레트 삽입에만 첫 줄 고정 규칙을 적용한다.
- 웨이브 종료 시 공격선·공격 효과를 정리한다. 기지의 기존 체력 12에 체력바와 현재/최대 수치를 연결한다.
- v0.10 확정: 적은 일반병(기본), 속도병(빠른 이동·낮은 체력), 탱커병(느린 이동·높은 체력)이다. 현재 임시값은 각각 HP/속도 35/1.5, 28/2.8, 110/1.15이다.
- 폭탄은 투사체로 공격하며 빠른 적이 회피할 수 있다. 구현 기준은 발사 순간 위치를 향한 비유도 비행과 착탄 시 범위 판정이다. 사수형 `Attack()`·전사형 `slash()`는 실행 시 사거리 안의 유효 대상에게 확정적으로 즉시 피해를 준다.

- 개발자 모드는 로봇·블록 아이템 지급을 중심으로 구성한다. 블록 수량에 게임 규칙상 최대치는 두지 않으며 인벤토리에는 사용 가능 수만 표시한다. 코드에 예약한 수량과 보유 수량 검사는 유지한다.
- 로봇 카드는 클릭 배치와 드래그 배치를 지원한다. 실패·취소는 아이템을 소모하지 않는다.
- v0.9: 로봇 선택 시 좌측 상단 3/5는 실제 선택 로봇을 보여주는 이전 카메라 화면으로 복구한다. 하단 2/5의 스탯은 유지한다. 별도 `미리보기` 버튼으로 코드 패널 안에서 시연을 열고, 같은 버튼의 `코드로 돌아가기`로 편집 화면을 복구한다. 자동 시연·위치별 토글·우측 하단 작은 시연 방식은 교체한다.
- 사용자 추가 답변에 따라 시연은 기본 행동 강제 실행이 아니라 **작성한 코드 실행**이다. 빈 코드는 대기한다. 실제 게임 자원·적·로봇과 분리하며 임시 적을 생성해 시연한다. 미완성 수정 중에는 마지막 유효 코드가 기준이다.
- 모든 웨이브에 전투 시간 35초를 적용한다. 적이 모두 처리되거나 시간이 끝나면 종료한다. 코어 파괴 시에는 기존 패배 규칙이 우선한다.
- 종료 시 잔여 적 수를 기록하고 드랍 없이 정리한다. 다음 웨이브의 기본 편성에 잔여 수만큼 추가한다. 구현 기준안으로 미등장 예정 적도 잔여 수에 포함하고, 적 종류·경로는 유지하며 기본 체력으로 재등장시킨다. 마지막 웨이브는 기록만 남긴다.
- 다음 웨이브의 종류·수량을 표시한다. 준비 중 편성 줄은 시작할 현재 웨이브를 표시한다. 상단은 스테이지·웨이브·남은 적 수와 시간을 표시한다.
- 스테이지 번호는 현재 1이며 다중 스테이지 콘텐츠는 아직 추가하지 않는다. 시연 주기 8초·임시 적 3마리·선택 로봇 1대·이월 출현 간격 0.4초는 임시 구현값이다.

아래의 기존 항목과 충돌하면 이 절의 최신 정책을 우선한다. 구현 위치와 실행 검증은 [디펜스 구현안내](디펜스_구현안내.md)를 따른다.

## 1. 목적과 현재 기준

**킹덤러쉬의 경로·사거리 표현을 참고하여, 칸 구분 없이 실제 거리로 동작하는 로봇 디펜스를 먼저 만든다. 콘텐츠는 난이도와 추가 기획에 따라 확장한다.**

설치하는 대상은 로봇이다. 킹덤러쉬의 타워 건설·병영에서 별도 병사 생성 등까지 모두 도입하는 것은 아니다. 사용자 최신 설명 및 추가 답변과 이 기능서가 기존 [개발문서](개발문서.md)·[개발명세서](개발명세서.md)의 상충 내용보다 우선한다.

- **확정:** 사용자가 직접 명시하거나 질문에 답한 내용.
- **기준안:** 아직 확정되지 않은 내용을 구현 검토용으로 구체화한 제안.
- **미정:** 로봇 추가 기획과 후속 결정으로 채울 항목. 임의로 확정하지 않는다.
- 문서에 적힌 검수 항목은 향후 실행할 목록이며 현재 구현·검증 완료를 뜻하지 않는다.

### 이번 변경에서 확정된 사항

1. 디펜스 규칙은 킹덤러쉬의 경로·거리 방식을 참고한다. 최신 요청에 따라 **카메라 시점만 명일방주의 사선 전장 구도**를 참고한다.
2. 논리 타일·칸 수 없이 실제 위치 간 거리로 판정한다.
3. 로봇은 **허용 영역 내 자유 배치**한다. 고정 설치 지점과 격자 스냅은 사용하지 않는다.
4. **적 이동 경로 위에는 탱커만 설치**할 수 있다.
5. **탱커를 제외한 모든 로봇은 체력이 없다.** 탱커만 독립 체력이 있다.
6. 탱커는 몸으로 적을 저지하며 범위 스턴도 사용한다.
7. 연사형은 **사거리와 공격력이 반비례하고 단발로 공격**한다.
8. `block()`·`buff()`를 제외한 다른 직군 행동은 **10% 효율**로 실행한다. `block()`·`buff()`의 기존 불가 사례와 남은 미정 조합은 유지한다.
9. **폭탄형·연사형의 `block()`과 탱커형의 `buff()`는 함수에 블록을 배치할 수 있지만 실행 시 동작하지 않는다.**
10. 탱커 명령어 표기는 **`block()`**으로 통일한다. 이전 `blocks()` 표기는 폐기한다.
11. 전장의 로봇을 클릭해 블록 코드를 편집·적용하고, 해당 로봇만 적용된 코드를 실행한다.
12. 게임 흐름은 **로봇 배치 → 코드 작성·적용 → 전투 → 웨이브 보상 수령 → 코드 정비 → 다음 전투**다. 현재 플레이는 5웨이브로 구성한다.
13. 새 로봇은 내부 코드가 비어 있으며 명령을 넣기 전에는 공격·저지·버프·둔화를 실행하지 않는다.
14. 적 처치 시 랜덤 블록을 드랍하고 해당 웨이브 종료 후 수령한다.
15. 기존 개발자 화면은 F1로 열고 닫는다. 기본 진입 화면은 사용자용 전장이다.
16. 초기 제공 블록, 적 구성, 난이도·수치는 우선 구현자가 정하는 **임시 콘텐츠**이며 후속 상세 기획으로 교체한다.

### 이전 버전에서 교체·보류한 사항

| 이전 기준 | 개정 |
|---|---|
| 논리 격자·타일 점유·고지/지상 타일 | 월드 좌표와 연속적인 배치 허용 영역으로 교체 |
| 네 방향 배치·회전된 타일 공격 범위 | 거리 기반 사거리와 원형 범위 표시 기준안으로 교체 |
| 모든 아군 HP·피격·사망 | 일반 로봇에서 제거, 탱커에만 적용 |
| 일반 아군의 저지 용량 | 탱커의 거리 기반 몸 저지로 교체. 구체적 동시 저지 수는 미정 |
| 공격형/서폿형 고정 2종 | 새 로봇 6종 초안으로 교체. 최종 종류 수를 제한하지 않음 |
| 모든 비전문 명령어가 실행됨 | 실행 불가 사례와 미정 호환표를 구분 |
| 자동 회복 DP·퇴각 반환·재배치 대기 | 기존 제안으로만 남김. 유지 여부 확정 전 필수 기능으로 적용하지 않음 |
| 스테이지 수·웨이브 수·적 수·수치 공식 | 과거 콘텐츠 초안. 새 기반의 고정 조건으로 사용하지 않음 |

## 2. 시각 참고

![킹덤러쉬 전장](ReferencesImg/킹덤러쉬.png)

굽은 적 이동 경로, 경로 주변 설치물, 전장 위 선택 표시를 참고한다. 이미지에는 정해진 건설 지점이 보이지만 본 프로젝트의 배치는 사용자 답변대로 자유 좌표 방식이다. 고정 건설 지점을 그대로 가져오지 않는다.

![킹덤러쉬 사거리](ReferencesImg/킹덤러쉬_사거리.png)

선택한 로봇 주변에 연속적인 사거리 영역을 보여준다. 판정은 로봇과 대상 사이의 실제 거리를 사용한다. 카메라 시점 때문에 화면에서 원이 타원처럼 보일 수 있으며, 화면상의 픽셀 거리로 공격을 판정하지 않는다.

사용자가 첨부한 클립보드 이미지는 같은 경로형 전장의 보조 참고다. 이미지 속 업그레이드 가격·스킬·방송 자막·고유 게임 규칙은 요구사항으로 가져오지 않는다. 기존 UI 프로토타입은 후속 코딩 UI의 참고이며 타일 배치 근거로 사용하지 않는다.

## 3. 로봇 종류 초안

명령어 대소문자는 사용자 표기를 보존한다. `block()` 이외의 최종 API 이름·인자 통일은 미정이며 현재 컴파일러가 아래 명령을 이미 지원한다고 가정하지 않는다.

| 종류 | 전문 행동 | 현재 특징 | HP | 활용 시기 |
|---|---|---|---|---|
| 버프형 | `buff()` | 공격력·사거리·공격 딜레이 강화, 맵에 1대만 소환 가능 | 없음 | 중반 |
| 전사형 | `slash()` | 근거리 공격, 낮은 공격력으로 초·중반에 사용 | 없음 | 초·중반 |
| 탱커형 | `block()` | 낮은 공격력, 적 경로 설치, 몸 저지, 일정 범위 적에게 스턴, 독립 체력 | 있음 | 미정 |
| 폭탄형 | `Boom()` | 낮은 피해로 다수 적 공격, 공격 사거리는 전사의 1.5배 | 없음 | 중·후반 |
| 연사형(현재 명칭) | `Attack()` | 사거리와 공격력 반비례, 연속 발사 없이 단발 공격 | 없음 | 중·후반 |
| 유틸형 | `slow()` | 낮은 공격력, 적 이동속도 감소가 주목적 | 없음 | 중·후반 |

활용 시기는 콘텐츠 방향이며 정확한 스테이지 번호나 해당 시기 외 사용 금지 조건이 아니다. 로봇 추가 기획이 진행 중이므로 종류 수·수치·해금 순서를 하드코딩하지 않는다.

### 3.1 체력과 고유 특성

일반 로봇은 체력 시스템을 갖지 않는다. 매우 큰 HP나 무적 상태로 표현하지 않고 피해 대상에서 제외한다. 일반 로봇에는 HP 바·회복·피격 사망 상태도 표시하지 않는다. 탱커만 최대/현재 HP와 체력 소진 상태를 가진다.

다른 명령어를 넣어도 일반 로봇에 HP나 적 경로 설치 권한이 생기지 않는다. 로봇 종류에 따른 고유 특성과 행동 효과는 별개다. 버프형 1대 제한도 로봇 종류 제한이며 다른 종류가 버프 효과를 사용한다고 버프형으로 바뀌지 않는다.

탱커 HP의 감소 원인, 적 반격 방식, HP 0에서의 제거·복귀 규칙은 미정이다. 이전 문서의 ‘저지되면 적이 자동 반격한다’는 규칙을 확정된 최신 요구로 취급하지 않는다.

### 3.2 행동 명령어 호환표

**전문:** 해당 로봇의 고유 전문 행동. **불가:** 블록 배치는 가능하지만 실행 효과 없음. **미정:** 실행 허용 여부가 아직 결정되지 않았으며 자동 허용하지 않음.

| 로봇 | `buff()` | `slash()` | `block()` | `Boom()` | `Attack()` | `slow()` |
|---|---|---|---|---|---|---|
| 버프형 | 전문 | 10% | 미정 | 10% | 10% | 10% |
| 전사형 | 미정 | 전문 | 미정 | 10% | 10% | 10% |
| 탱커형 | 불가 | 10% | 전문 | 10% | 10% | 10% |
| 폭탄형 | 미정 | 10% | 불가 | 전문 | 10% | 10% |
| 연사형 | 미정 | 10% | 불가 | 10% | 전문 | 10% |
| 유틸형 | 미정 | 10% | 미정 | 10% | 10% | 전문 |

사용자의 최신 요청으로 `slash/Boom/Attack/slow` 비전문 조합을 10%로 확정했다. 전문 행동은 100%다. 제외된 `block/buff` 미정 칸은 자동 허용하지 않는다.

구현 기준: 비전문 공격 피해는 해당 행동 전문 직군의 기본 피해 × 0.1, 둔화는 속도 감소 강도 × 0.1이다. 범위·지속시간·행동 간격까지 일괄 0.1배 하지 않는다. 행동 간격과 효과 정의는 전문 행동 데이터, 사거리와 시전자 강화는 로봇 데이터를 사용한다. 상세 계산은 [구현 안내](디펜스_구현안내.md)에 기록한다. `block/buff` 미정 조합의 허용 여부와 효율은 후속 결정이다.

### 3.3 비호환 명령 처리

- 폭탄형·연사형에 `block()`을, 탱커형에 `buff()`를 넣는 편집 조작 자체는 허용한다.
- 위 조합은 실행되어도 공격·저지·스턴·버프 등 해당 명령의 효과를 발생시키지 않는다. 다른 명령으로 자동 변환하지 않는다.
- **기준안:** 편집 UI에 `이 로봇에서는 동작하지 않는 명령입니다`를 표시하고 실행 시 효과 없이 다음 명령으로 넘긴다. 구조 오류와 구분하며 단지 이 조합이라는 이유로 함수 전체를 문법 오류 처리하지 않는다.
- **기준안:** 실행 불가 명령은 자원·행동 쿨타임을 소모하지 않는다. 게임 실행기가 완성되면 프레임별 처리 예산을 적용해 무효 명령 반복으로 멈추지 않게 한다.
- 호환 ‘미정’은 게임 내 저효율이나 실행 불가와 다른 기획 상태다. 데이터 검증 시 미정 조합을 발견하면 구성 진단을 남기고 정식 콘텐츠에 넣지 않는다.

### 3.4 버프형

강화 항목은 공격력·사거리·공격 딜레이다. 딜레이 강화는 공격 사이 시간을 줄여 공격 빈도를 높인다는 해석이 자연스럽지만, 방향·최소 간격·계산 순서는 상세 기획에서 확정한다.

맵에 1대만 소환 가능하다는 요구를 따른다. 동시 존재 1대인지 맵 전체 소환 횟수 1회인지, 제거 후 재소환 가능한지는 미정이다. 버프 대상 범위, 자기 적용, 오라/일시 효과, 중첩도 미정이다. 다른 직군의 `buff()` 허용 여부는 호환표와 함께 정한다.

### 3.5 전사·탱커

전사는 근거리 공격을 하는 무체력 로봇이다. 근거리라는 이유로 적 경로에 설치하거나 몸으로 저지할 수 있다고 추가 해석하지 않는다.

탱커는 적 경로에 설치해 몸으로 적을 막으며 `block()`을 전문 행동으로 사용한다. 몸 저지와 스턴은 별도 이동 정지 원인으로 관리한다. **몸 저지는 탱커 설치에 따른 고유 기능으로, `block()`은 범위 스턴을 발생시키는 행동으로 구분하는 기준안**이다. 자동 저지 시작 시점과 스턴의 발동·주기·지속시간은 추가 기획 대상이다.

스턴이 끝나도 몸으로 저지 중이면 적은 계속 멈춘다. 탱커가 사라져 몸 저지가 풀려도 다른 출처의 스턴이 남아 있으면 정지 상태를 유지하는 기준안이다. 스턴이 적 공격도 중단시키는지, 적이 탱커에게 어떻게 피해를 주는지는 미정이다.

### 3.6 폭탄형

**공격 사거리**는 로봇에서 공격할 수 있는 거리, **폭발 반경**은 폭발 중심 주변에 피해를 주는 거리다. 사용자가 정한 전사 사거리의 1.5배는 공격 사거리이며 폭발 반경을 뜻하지 않는다.

동일 성장 단계의 기본 사거리끼리 1.5배를 적용하는 것을 기준안으로 두되, 버프 적용 후에도 최종 사거리 비율을 항상 강제할지는 미정이다. v0.10에서 폭발 중심은 발사 순간 적 위치로 고정하며, 비행 시간은 거리/투사체 속도다. 착탄 순간 폭발 범위 안의 적들에게 각각 한 번 피해를 준다. 범위 밖으로 이동한 적은 피해를 받지 않는다. 임시 속도 4, 폭발 반경 1.7이며 최종 수치와 최대 대상 수는 후속 기획에서 조정한다.

### 3.7 연사형·유틸형

연사형은 사용자 확인에 따라 사거리가 길수록 공격력이 낮아지는 단발형이다. 구체적인 역비례 산식·상하한·사거리 조절 방법·명칭 변경은 미정이다. 버프의 사거리 증가가 공격력에도 영향을 주는지, 공격력 버프와 어느 순서로 계산하는지는 자동 추론하지 않는다. 한 발씩 일정 간격으로 반복 공격하는 것과 한 명령으로 여러 발을 연속 발사하는 것은 구분한다.

유틸형은 적 이동속도 감소가 핵심이며 공격력은 낮다. `slow()` 자체에 피해가 포함되는지, 별도 일반 공격이 있는지는 미정이다. 둔화량·지속시간·중첩도 데이터 결정 사항이다.

## 5. 공간·배치·경로 계약

### 5.1 거리 판정 기준안

기존 Unity 3D 전장의 XZ 평면과 월드 단위를 사용한다. 로봇과 대상 중심의 평면 거리 `d`가 유효 사거리 `R` 이하일 때 범위 안으로 판정한다. 경계값 `d = R`은 포함한다. 화면 해상도·카메라 확대·원 표시의 픽셀 크기로 결과가 달라지지 않는다.

대상 크기를 반영한 표면 거리를 사용하려면 별도로 결정한다. 중심 거리와 Collider 표면 거리를 기능마다 혼용하지 않는다. 높이를 포함한 3D 거리와 벽 가림은 이번 요청만으로 추가하지 않는다.

| 범위 | 기준 대상 | 의미 |
|---|---|---|
| 공격 사거리 | 시전자 로봇 → 적 | 공격을 시작할 수 있는 거리 |
| 폭발 반경 | 폭발 중심 → 주변 적 | 한 번의 폭발 피해 영역 |
| 몸 저지 거리 | 탱커 → 적 | 탱커가 적 이동을 붙잡는 영역 |
| 스턴 범위 | 행동에 정의한 중심 → 적 | 스턴 적용 대상 |
| 둔화 범위 | 행동에 정의한 중심 → 적 | 이동속도 감소 대상 |
| 버프 범위 | 행동에 정의한 중심 → 아군 | 강화 대상 |

폭발·스턴·둔화·버프의 중심과 대상 선정은 별도 정의한다. 모든 효과를 로봇 주위 오라로 통일하지 않는다. 사거리·피해 반경·저지 거리를 하나의 수치로 묶지 않는다.

### 5.2 자유 설치

로봇 선택 → 후보 위치 이동 → 유효성·예상 사거리 표시 → 설치 확정/취소로 진행한다. 네 방향 확정 단계를 제거한다. 외형은 필요하면 타겟을 향해 회전하되 거리 판정은 유지한다.

맵에는 일반 배치 허용 영역과 적 경로 영역을 구분한다. 탱커는 허용된 적 경로 위에 설치할 수 있고, 일반 로봇은 적 경로 영역에 설치할 수 없다. 탱커를 경로 밖 일반 영역에도 허용할지는 상세 기획에서 결정한다.

로봇의 설치 면적/배치 반경과 최소 간격으로 겹침을 검사하는 기준안이다. 중심점만 허용 영역 안에 있고 몸체가 경로 또는 금지 지형을 침범하는 경우도 확인한다. 경로 폭과 일반 영역 경계를 시각화해 배치 가능 표시와 최종 판정을 일치시킨다. 탱커끼리 중첩 설치할 수 있다는 규칙은 추가하지 않는다.

확정할 때 허용 위치·일반 로봇의 경로 침범·다른 로봇과 겹침·종류별 제한을 다시 검사한다. 실패·취소·중복 요청은 로봇 중복 생성이나 상태 변경을 만들지 않는다. 버프형 제한의 정확한 소환 횟수 정책은 미정이다. 비용·정원·설치 가능 시간은 확정 후 검사에 추가한다.

### 5.3 이동과 몸 저지

적은 순서 있는 월드 좌표 경로를 따라 이동한다. 이동량은 유효 속도와 전투 시간으로 계산하고 한 번에 여러 지점을 지나면 남은 이동량을 다음 구간에 반영한다. 큰 시간 변화량에서도 저지 영역·목표 도착을 건너뛰지 않도록 이동 구간을 확인한다.

탱커 저지 거리 안에 진입한 적과 탱커의 관계를 등록해 적을 멈추는 기준안이다. 한 적은 동시에 한 탱커에게만 저지되며, 동시에 조건을 만족하면 먼저 접촉한 탱커·동률이면 안정적인 개체 순서를 사용하는 안이다. 저지 반경, 최대 동시 저지 수, 초과 적 통과 정책은 미정이다.

탱커를 물리 장애물로 취급해 적이 자동 우회하는 길찾기를 사용하지 않는다. 저지는 Rigidbody 충돌·밀림에 맡기지 않고 게임 규칙으로 관리하는 기준안이다. 탱커 또는 적 제거 시 관계를 해제한다. 저지·스턴 중 하나라도 남아 있으면 경로 진행을 보존하고 멈추며, 모두 해제된 뒤 유효 이동속도로 이동을 재개한다.

## 6. 행동·효과 계약

### 6.1 실행 순서 기준안

행동 요청마다 시전자 유효성 → 로봇/행동 호환 → 필요한 대상·거리 → 실행 간격 → 효과 적용 순으로 검사한다. 비호환 조합은 효과를 만들지 않으며, 미정 조합은 구성 진단으로 드러낸다. 적절한 대상이 없을 때 자동으로 다른 명령을 실행하지 않는다.

공격 간격과 재사용 시간은 전투 시간 기준이다. 호출 횟수를 늘려도 발사·효과 주기를 우회하지 않는다. 전체 게임 루프를 막지 않도록 행동 실행은 대기 상태를 반환하고 다음 프레임에 진행한다.

시험 단계의 자동 실행/테스트 입력과 후속 코드 실행은 같은 행동 기능을 호출한다. 코딩 제어를 연결할 때 로봇별 행동 생성 주체를 하나만 활성화해 중복 공격을 막는다. 인자 없는 명령 표기의 실제 대상 선정·인자는 후속 API 결정 사항이다.

### 6.2 피해·생존

적과 탱커만 HP와 피해를 처리한다. 일반 로봇에게 전달된 피해 요청은 HP·피격 사망을 발생시키지 않는다. 탱커 HP의 감소 원인은 추가 결정이 필요하며, 이전의 공통 아군 방어력·피해식·자동 반격을 그대로 가져오지 않는다.

기본 피해 산식, 적 방어력 사용, 최초 공격 지연과 타겟 우선순위는 미정이다. 검증에는 임시 피해량과 명시적 시험 타겟을 사용할 수 있다. 광역 피해는 한 번의 발동 ID에서 같은 적에게 한 번만 적용한다. 표시용 탄환·이펙트가 별도의 피해를 중복 발생시키지 않게 한다.

로봇/적 제거는 원인을 구분한다. 적 처치와 목표 돌파는 배타적이며 한 번만 종결한다. 일반 로봇 설치 해제와 탱커 HP 소진 제거를 동일한 사망 이벤트로 처리하지 않는다.

### 6.3 상태와 버프

효과는 출처·대상·시작/종료·효과량을 추적한다. 원본 공격력·사거리·간격·이동속도와 현재 유효 값을 분리한다. 버프 적용/해제 반복으로 원본 수치가 누적 변경되지 않게 한다.

- 스턴과 몸 저지는 독립적인 이동 정지 원인이다. 하나를 해제하며 다른 원인을 덮어쓰지 않는다.
- 이동이 다시 가능해졌을 때 둔화가 남아 있으면 낮아진 속도를 적용한다.
- 중첩 효과의 합산/최댓값/시간 갱신 정책은 미정이다. 임시 검증 정책과 최종 규칙을 구분한다.
- 오라는 범위를 벗어나면 종료하고, 시간제 효과는 적용 후 남은 시간에 따르는 등 방식이 다르다. 각 행동의 방식은 상세 기획에서 결정한다.
- 사거리 버프는 실제 유효 거리와 선택 UI를 함께 갱신한다. 연사형 공격력 산식과 적용 순서는 별도 결정한다.
- 로봇 제거 시 출처에 종속된 효과와 독립적으로 지속할 효과를 구분한다. 어떤 효과가 남는지는 콘텐츠 정책이다.

## 7. 흐름·UI·데이터

### 7.1 현재 전투 흐름

준비(자유 배치·로봇별 코드 적용) → 수동 전투 시작 → 적 처치·랜덤 블록 드랍 → 모든 스폰과 생존 적 처리 완료 → 보상 수령 → 다음 준비를 반복한다. 5번째 보상을 수령하면 승리한다. 적 종류·수·간격·경로·드랍 표는 데이터로 작성한다.

목표 내구도 0이면 즉시 패배한다. 같은 틱에서 피해·적 사망, 남은 적 돌파를 처리한 뒤 패배를 먼저 검사한다. 드랍은 수령 전까지 보유 수량에 합산하지 않으며 중복 수령은 불가하다. 돌파한 적은 블록을 주지 않는다.

일시정지와 1배/2배를 제공하며 이동·명령·효과는 같은 전투 시간을 사용한다. 현재 임시 정책은 준비 중에만 배치·회수·코드 변경을 허용한다. 로봇을 한 대 이상 배치하면 전투를 시작할 수 있으며 코드 없는 로봇은 행동하지 않는다. 모든 로봇의 코드 작성을 시작 조건으로 강제하지 않는다. 보상 수령 후 살아남은 탱커는 회복하고 프로그램은 처음부터 실행한다. 재시작은 로봇·코드·적·효과·HP·시간·스폰·보유 아이템·미수령 드랍을 초기화한다.

블록은 적용한 코드의 사용 수량만큼 로봇별로 예약한다. 재적용은 기존 예약을 교체하고 코드 삭제·로봇 회수/파괴는 예약을 반환한다. 수량 초과·문법 오류가 있는 적용은 이전 코드를 유지한다. 초기 블록·드랍 가중치·웨이브 수치는 [구현안내](디펜스_구현안내.md)에 기록한다.

새 탱커도 코드 적용 전에는 몸 저지를 하지 않는다. 현재 임시 구현은 `block()`을 실제 실행한 이후 해당 웨이브 동안 몸 저지를 활성화한다. 스턴 지속시간과 몸 저지는 별개이며 다음 준비 단계에서 저지 활성 상태를 초기화한다.

### 7.2 UI

적용 버튼 없이 유효한 블록 수정은 즉시 선택 로봇에 반영한다. 미완성 연결·인자 또는 재고 부족은 상태로 알리고 마지막 유효 코드를 유지한다. 전체 삭제는 빈 코드로 반영하고 블록 예약을 반환한다. 클릭 추가는 기존 명령 끝에 연결하며, 빈 작업 공간의 첫 줄에도 스냅 미리보기를 표시한다. 체력바는 탱커·적 머리 위에서 화면을 향하고 왼쪽 기준으로 HP 비율에 맞춰 줄어든다.

로봇과 모든 블록을 수량 기반 아이템으로 관리한다. 보유 로봇만 배치하고, 보유 블록만 코드에 사용할 수 있다. 숫자·변수·인자 내부 블록도 수량 제한에 포함한다. 인벤토리에 로봇 수량과 블록의 사용 가능/보유 수량을 표시한다. 현재 임시 정책은 배치 성공 시 로봇 한 개 사용, 준비 중 회수 시 로봇·블록 반환, 탱커 파괴 시 블록만 반환이다. 적용 실패는 기존 코드와 예약을 유지한다. 초기 지급 수량은 구현안내를 따른다.

F1 개발자 모드에서 종류·수량을 선택하여 로봇 또는 블록을 현재 인벤토리에 지급할 수 있다. 재시작은 지급분을 포함한 인벤토리를 초기 설정으로 되돌린다. 영구 저장은 별도 범위다.

선택 편집 화면은 `명일방주_selected.png`의 구도를 참고한다. 카메라가 이동·회전하여 왼쪽 1/4에 선택 로봇을 두고 오른쪽 3/4에 코드 작성 공간을 배치한다. 닫으면 전장 시점으로 복귀한다. Python 미리보기 UI는 숨기고 생성·검증 스크립트는 유지한다. 중복 안내문은 제거한다.

드래그 강조는 연결될 경계선이나 비어 있는 인자 슬롯에만 표시하며 함수 패널 전체를 변색하지 않는다. 인자 입력으로 인한 자동 크기 변경은 가로 방향에만 적용한다. 조건문 본문이 포함 명령 수에 따라 세로로 늘어나는 동작은 유지한다.

| 요소 | 표시/조작 |
|---|---|
| 전장 | 연속 경로·로봇·설치 후보 위치, 격자·네 방향 마커 없음 |
| 설치 미리보기 | 허용/불가 영역, 겹침·경로 침범, 예상 사거리 |
| 로봇 목록 | 종류·전문 명령·설치 제한 |
| 선택 로봇 | 유효 사거리·현재 행동·피해/효과·공격 간격 |
| 탱커 전용 | 현재/최대 HP·몸으로 저지 중인 적·스턴 상태 |
| 명령 설명 | 전문/비전문/실행 불가 구분, 호환 미정은 제작용 진단 |
| 범위 표시 | 공격 거리와 폭발·저지·버프·스턴·둔화 영역 구분 |
| 적 정보 | HP·유효 속도·몸 저지/스턴/둔화 상태 |
| 전투 HUD | 웨이브·처치/돌파·목표 상태·시간 제어·결과 |

일반 로봇은 HP 영역을 표시하지 않는다. ‘적 경로에는 탱커만 설치할 수 있습니다’, ‘다른 로봇과 겹칩니다’, ‘이 로봇에서는 block()이 동작하지 않습니다’처럼 원인을 텍스트와 색으로 함께 안내한다. 미정 효율 수치를 임의로 표시하지 않는다.

## 9. 구현 순서와 검수

### 구현 순서

1. 연속 좌표 선택·배치 허용 영역·적 경로·거리 계산·원형 범위를 만든다.
2. 자유 배치와 일반 로봇의 경로 설치 금지, 일반 로봇 무체력·탱커 생존을 연결한다.
3. 행동 호환 검사·간격·거리·단일 피해와 적 처치를 연결한다.
4. 몸 저지, block 스턴, Boom 광역, slow 둔화, buff 강화를 임시 값으로 개별 검증한다.
5. 확정된 호환표 범위에서 실행 불가 처리와 역할 성능, 버프형 제한·효과 만료·UI를 연결한다.
6. 웨이브·승패·재시작을 검증하고 콘텐츠·코딩 실행기를 후속 연결한다.

임시 값은 시험 데이터로 표시한다. 미정 비전문 조합을 시험 목적으로 사용하더라도 정식 콘텐츠로 확정하지 않는다. 명일방주형 타일·공통 HP를 먼저 구현한 뒤 교체하는 순서로 진행하지 않는다.

## 10. Unity 작업 기준

2026-09-18: 이 기능서를 바탕으로 `Assets/!_Project/Scenes/Defense.unity`에 시험 전장과 로봇별 블록 코드 편집·적용·실행을 구현했다. 실행 방법·구현 범위·임시 정책·실제 검증 결과는 [디펜스 구현 안내](디펜스_구현안내.md)를 참고한다. 지원 블록을 게임 내 실행기로 해석하며 범용 Python 문자열 실행은 포함하지 않는다. 위의 검수 목록 전체나 미정 콘텐츠가 확정·완료된 것은 아니다. 씬·프리팹·Inspector·경로·설치 영역과 필수 참조는 Unity MCP로 작성하고 확인했다.

작성된 씬 구조를 런타임 생성이나 임시 Editor 스크립트로 대체하지 않는다. 필수 참조는 직렬화 필드로 명시하고 Find·Resources.Load·자식 검색으로 누락을 덮지 않는다. 실제 게임 규칙상 필요한 로봇·적 프리팹 생성은 가능하다. 변경 후 컴파일·도메인 리로드와 Unity Console·필수 참조를 확인한다.
