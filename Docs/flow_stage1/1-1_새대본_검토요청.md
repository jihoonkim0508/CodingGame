# 1-1 새 대본 검토 요청

대상: `[1s - 1w | 변수와 플레이 방법 소개 (3분)]` 새 대본
기준: 현재 develop 브랜치의 게임 구현과 현재 1-1 대본(`tutorial_stage1_대본.md`)

아래 항목은 대본 그대로는 구현할 수 없거나, 해석이 갈려서 확인이 필요한 부분입니다.
위치는 대본의 섹션 이름과 해당 문장으로 적었습니다.

---

## 1. 한 번의 상호작용에 행동이 두 개 들어 있음

**위치**
- [변수에 저장한 적 공격하기] 섹션
  > 상호작용 : 플레이어가 slash() 블록을 첫 번째 블록 아래에 연결하고, enemy 변수를 공격 대상 위치에 연결한다.
- [코드 편집기와 변수 알아보기] 섹션
  > 상호작용 : 플레이어가 enemy = get_nearest_enemy() 블록을 실행 시작 블록에 연결한다.

**이유**
- 튜토리얼은 "대사 1개 = 플레이어 행동 1개"로 진행됩니다. 강조 표시(손가락, 테두리)도 한 번에 한 곳만 가리킵니다.
- 첫 번째 문장은 slash() 연결과 enemy 연결, 두 가지 행동입니다.
- 두 번째 문장도 실제로는 두 번 끌어야 합니다. 게임에서 `enemy = ...` 변수 블록과 `get_nearest_enemy()` 블록은 서로 다른 블록입니다.
- 한 대사로 두 행동을 시키면, 플레이어가 첫 행동만 하고 멈추거나 순서를 헷갈립니다.

**요청**
- 행동마다 대사를 나눠 주세요.
- 예: "slash() 블록을 아래에 붙여 봐" → (연결) → "이제 괄호 안에 enemy를 넣어 봐" → (연결)

## 2. enemy 변수 이름을 입력하는 단계가 없음

**위치**
- [코드 편집기와 변수 알아보기], [변수에 저장한 적 공격하기] 섹션 전체

**이유**
- 블록 목록에서 변수 블록을 꺼내면 이름이 처음에 `variable`로 되어 있습니다.
- 플레이어가 이름 칸을 눌러 `enemy`를 직접 입력해야 합니다. 지금 대본에서는 D04a "이제 변수 블록에 enemy를 입력해 보자!"가 이 단계입니다.
- 새 대본은 처음부터 enemy가 있는 것처럼 쓰여 있습니다. 입력 단계가 없으면 플레이어는 이름을 바꿔야 한다는 걸 모릅니다.

**요청**
- 이름 입력을 안내하는 대사를 넣을지, 넣는다면 어느 위치(저장하는 블록 / 공격 대상 블록)인지 정해 주세요.

## 3. "코드 실행 버튼"은 없는 기능임

**위치**
- [변수에 저장한 적 공격하기] 섹션
  > 상호작용 : 플레이어가 코드 실행 버튼을 누른다.

**이유**
- 게임에는 코드 실행 버튼이 없습니다.
- 블록을 연결했을 때 문법 오류가 없으면 코드가 자동으로 저장됩니다. 미리보기도 자동으로 다시 실행됩니다.
- 그래서 플레이어가 누를 버튼이 없고, 이 단계에서 튜토리얼이 멈춥니다.

**요청**
- 이 상호작용을 빼고 "미리보기를 확인한다"로 바꿔 주세요.
- 바로 아래 대사 "미리보기에서 로봇이 적을 공격하는지 확인해 봐."를 이 자리에서 쓰면 됩니다.

## 4. "잘못 놓은 블록은 원래 위치로 되돌림"이 지금 블록 편집기 규칙과 반대임

**위치**
- [코드 편집기와 변수 알아보기] 섹션, 추가 효과
  > 블록을 잘못된 위치에 놓으면 원래 위치로 되돌리고 연결할 위치를 다시 강조한다.

**이유**
- 지금 편집기는 블록을 빈 곳에 놓으면 **그 자리에 그대로 남습니다**. 연결되지 않은 블록이 편집기 위에 떠 있는 상태가 됩니다. 연결되지 않은 블록은 실행되지 않습니다.
- 이 규칙은 일부러 만든 것입니다. 이전 플레이테스트 피드백을 반영했습니다.
  - 블록을 잠깐 꺼내 두었다가 다시 붙일 수 있습니다.
  - 블록 여러 개를 따로 조립한 뒤 한 번에 붙일 수 있습니다.
- 1-2 이후 튜토리얼에도 "블록을 꺼내 두었다가 연결하기"가 들어가 있습니다. 1-3의 조건 블록을 따로 만들어 두는 단계도 여기에 해당합니다.
- 놓은 블록이 원래 자리로 돌아가게 바꾸면 위 기능이 모두 동작하지 않습니다.

**요청**
- 아래 중 하나를 골라 주세요.
  - A. 되돌림 문장을 삭제합니다. 지금처럼 놓은 자리에 남겨 두고, 연결할 위치만 계속 강조합니다. (추천, 추가 작업 없음)
  - B. 1-1 튜토리얼의 이 단계에서만 되돌립니다. 그 외 상황은 지금 규칙을 유지합니다.

## 5. 보상 수령 단계가 없음

**위치**
- [웨이브 종료] 섹션
  > 집중 : 전투가 끝난 화면에서 로봇과 코어 체력을 잠시 보여준 뒤 다음 웨이브 진행 UI를 표시한다.

**이유**
- 지금 게임은 웨이브를 막으면 보상 창(새 블록)이 뜹니다. 플레이어가 **보상 수령 버튼을 눌러야** 다음 웨이브로 넘어갑니다.
- 지금 대본에서는 아래 두 대사가 이 단계를 안내합니다.
  - E06a "웨이브를 막아내면 이렇게 보상으로 새 블록을 받을 수 있어!"
  - E09 "보상 수령 버튼을 눌러서 블록을 받고 다음 웨이브를 준비하자!"
- 새 대본에는 보상 이야기가 없습니다. 플레이어는 보상 창이 왜 떴는지, 무엇을 눌러야 하는지 모릅니다.

**요청**
- 보상 창을 설명하는 대사와 수령 버튼을 누르게 하는 대사를 넣어 주세요.
- 반대로 1-1에서 보상을 없애려면, 그 결정도 알려 주세요.

## 6. "지정된 오류 코드 한 마리가 코어에 도착" 방법이 없음

**위치**
- [코어 체력 감소와 노이즈 연출] 섹션
  > 1S-1W에서는 지정된 오류 코드 한 마리가 코어에 도착하도록 한다.

**이유**
- 지금은 플레이어가 로봇을 잘 배치하면 모든 적이 처치됩니다. 한 마리를 일부러 통과시키는 규칙이 없습니다.
- "어떻게" 통과시킬지에 따라 작업과 플레이어가 받는 느낌이 완전히 달라집니다.

**요청**: 아래를 정해 주세요.
- **어느 적인가**: 몇 번째로 나오는 적인지 정해 주세요. 예: 첫 번째, 마지막.
- **어떻게 통과하는가**: 아래 중에서 골라 주세요.
  - 공격을 받지 않습니다(무적).
  - 로봇 사거리 밖으로 지나갑니다.
  - 아주 빠르게 지나갑니다.
  - 다른 적과 생김새를 다르게 해서 "특별한 적"으로 보여 줍니다.
- **플레이어가 그 적을 처치해 버리면**: 그래도 체력을 강제로 깎을지, 연출을 생략할지 정해 주세요.
- **대사 흐름**: 시작할 때 "코어에 도착하기 전에 막아야 해!"라고 한 뒤 한 마리가 무조건 통과합니다. 그 직후 "막아냈어"로 끝납니다. 플레이어가 "내가 잘못했나?"라고 느낄 수 있습니다. "막을 수 없는 적"이라는 설명 대사가 필요한지 검토해 주세요.

## 7. 전투 중에는 개발툴(코드 편집기)이 없음

**위치**
- [코어 체력 감소와 노이즈 연출] 섹션
  > 같은 순간 기지 화면과 개발툴 화면에 노이즈 효과를 재생한다.
  > 안내자 : 코어 체력이 1 줄었어. 기지와 개발툴에도 오류가 번지고 있어!
  > 상호작용 : 플레이어가 기지와 개발툴에 약한 노이즈가 표시된 상태로 남은 전투를 진행한다.

**이유**
- 전투가 시작되면 코드 편집기는 닫혀 있습니다. 화면에 보이는 것은 전투 화면(기지)뿐입니다.
- 그래서 "개발툴 화면"에 노이즈를 넣으라는 문장을 구현할 대상이 없습니다.

**요청**
- "개발툴 화면"이 어느 화면인지 알려 주세요.
  - 코드 편집기라면: 다음에 편집기를 열 때 노이즈가 보이게 할지 정해 주세요. 그 노이즈를 언제 지울지도 정해 주세요.
  - 게임 화면 전체를 개발툴로 본 표현이라면: 기지 화면 하나로 합쳐서 써 주세요.

---

## 8. "체력 UI를 감소 직후 잠시 강조"가 무엇인지 불명확함

**위치**
- [코어 체력 감소와 노이즈 연출] 섹션, 집중
  > 체력 UI는 감소한 직후 잠시 강조해 플레이어가 변화를 알아차릴 수 있게 한다.

**이유**
- "강조"의 방식이 정해지지 않았습니다.
- 바로 위 문장 "코어 체력 UI가 감소한다"와 무엇이 다른지도 분명하지 않습니다.
- 지금 게임은 코어가 맞으면 코어 모델에 글리치 효과가 나옵니다. 체력 숫자는 바로 바뀝니다. 체력 UI 자체에 별도 효과는 없습니다.

**요청**: 아래를 구체적으로 적어 주세요.
- 효과 종류: 빨간색 깜빡임, 크기가 커졌다 작아짐, 흔들림 등.
- 시간: 예: 1초.
- 대상: 하트 아이콘인지 숫자인지, 패널 전체인지.

## 9. 노이즈를 "화면에 넣되 아무것도 가리지 않게" 하는 조건이 서로 충돌함

**위치**
- [코어 체력 감소와 노이즈 연출] 섹션
  > 노이즈는 화면 깨짐, 짧은 잡음선, 가벼운 화면 흔들림으로 표현한다.
  > 노이즈가 적의 이동 경로, 로봇, 코어 체력 UI를 가리지 않도록 한다.
  > 이후 약한 노이즈를 남은 전투 동안 유지하고
  > 노이즈가 남아 있는 동안에도 적, 로봇, 코어 체력 UI가 잘 보이도록 화면 효과의 강도를 낮게 유지한다.

**이유**
- 화면 깨짐, 잡음선, 화면 흔들림은 모두 **화면 전체**에 걸리는 효과입니다.
- 전투 화면은 대부분 적의 경로와 로봇으로 차 있습니다. 화면 전체 효과를 넣으면서 이것들을 가리지 않기는 어렵습니다.
- "약하게", "낮게"에 기준 수치가 없습니다. 작업자마다 결과가 달라집니다.

**요청**: 아래를 정해 주세요.
- **노이즈 영역**: 아래 중에서 골라 주세요.
  - 화면 가장자리만.
  - 배경(바닥, 하늘)만.
  - 화면 전체에 넣고 투명하게.
- **강한 노이즈**: 지속 시간을 적어 주세요. 예: 0.5초.
- **약한 노이즈**: 잡음선이 얼마나 자주 나오는지 적어 주세요. 예: 3초에 한 번. 또는 투명도를 적어 주세요. 예: 10%.
- **사라지는 시간**: 웨이브가 끝난 뒤 몇 초에 걸쳐 사라지는지 적어 주세요.
- 참고 이미지나 영상이 있으면 함께 주세요.

## 11. 대본이 크게 짧아진 이유

현재 1-1 대본은 대사가 56줄입니다. 새 대본은 약 30줄입니다. 아래 내용이 빠졌습니다.
의도적으로 뺀 것인지, 빠뜨린 것인지 알려 주세요.

| 현재 대본 | 내용 | 새 대본 |
|---|---|---|
| A04 | "잠깐, 거기 있는 너! 나 좀 도와줄 수 있어?" (플레이어 역할 소개) | 없음 |
| A04c | 체력이 다 닳으면 개발툴이 멈춘다 (패배 조건) | 없음 |
| C02a, C03 | 편집기 오른쪽은 블록 작성, 왼쪽은 미리보기 (화면 구성 설명) | "함께 보여준다"만 있음, 대사 없음 |
| C04~C06 | "로봇이 공격을 안 하네?" → 코드를 만들어야 하는 이유 | 없음 |
| C15 | 블록이 연결되어 있어야 다음 명령이 실행된다 | 없음 |
| D04a | 변수 블록에 enemy 입력 | 없음 (2번 항목) |
| D07 | 미리보기에서 공격을 확인한 뒤 칭찬 | 없음 |
| D09 | 완성한 코드를 한 줄씩 설명 | 한 문장으로 줄어듦 |
| E01 | 왼쪽 위에서 다음 오류 코드 정보 확인 | 없음 |
| E04 | 첫 처치 칭찬 | 없음 |
| E05 | 코어에 도착하면 로봇 위치와 사거리 확인하기 | 없음 (강제 통과 연출로 바뀜) |
| E06a, E09 | 보상 설명, 보상 수령 | 없음 (5번 항목) |

- 3분 분량에 맞추려고 줄인 것이라면, 위 항목 중 **꼭 남겨야 하는 것**을 표시해 주세요.
- 특히 아래 세 가지는 빠지면 플레이어가 다음 행동을 모르게 됩니다. 남기는 것을 추천합니다.
  - 패배 조건(A04c)
  - 연결해야 실행된다(C15)
  - 보상 수령(E09)
