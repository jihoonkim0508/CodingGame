# Stage 1 튜토리얼 대본 (1-1 ~ 1-4)

원본: `튜토리얼_대사목록_수정본(4w 수정본).txt`(기획, 2026-10-15 수령). 1-1~1-3은 이전본(`1s 3w~4w추가본`)과 같고 1-4가 새로 바뀌었다.
각 대사 앞의 `[ID]`와 `▶` 줄만 구현용으로 덧붙였다. 대사·연출 문장은 원본 그대로이며, 바꾼 것은 아래 코드 이름뿐이다.
`[ID] ` 접두어와 `▶` 줄을 지우고 아래 표를 거꾸로 적용하면 원본 전체(제목·작성 기준 포함)와 같다(2026-10-15 줄 단위 비교로 확인, 줄 끝 공백만 차이).
예외: 기획 확인 전 임시로 바꾼 대사는 [임시변경점.md](../임시변경점.md)에 전후를 적는다(이 경우 위 원본 비교는 그 변경만큼 다르다).
`▶` 메모 중 원본에도 없고 승인되지도 않은 결정은 적지 않고, 사용자 결정 번호(Pn)만 가리킨다. 기획 답과 결정 목록은 [튜토리얼_명세서.md](../튜토리얼_명세서.md) §9.

## 읽는 법

- `발화자 : 대사` 형식. 왼쪽이 발화자이며, 구현에서는 **대화창 하나(대사 한 줄)마다 발화자를 입력**한다(고정 이름 없음).
- 발화자가 `시스템`인 줄은 대화창이 아니라 UI(배너)로 표시한다.
- `집중`·`상호작용`·`추가 효과`·`코드`는 대사가 아니라 연출·진행 메모다.
- `▶` 줄: 구현 메모(진행 신호, 판정 조건). 기획 문장이 아니다.

## 구현 공통 규칙 (결정됨)

| 항목 | 규칙 |
|---|---|
| 거리 단위 | 1 grid = 거리 1. 맵의 한 블록(타일) = 거리 2 |
| 거리 코드 | `enemy.distance(get_my_pos())`. `get_my_pos()`는 `Vector2` 객체를 돌려준다. 기존 `get_distance(x, y)`는 이 `Vector2` 방식으로 대체 |
| 웨이브 전환 | 로봇·코드 유지. 스테이지 전환 때만 초기화. 한 스테이지 안에서는 맵 동일 |
| 웨이브 통과 | 기지(코어)가 살아 있으면 통과. 1-1~1-4는 지지 않는 것이 의도 |
| 적 수 | 1-1~1-3 각 오류 코드 2마리(5회 실행으로 처치 가능: 1마리당 베기 2번 × 2 = 4번). 1-4는 "더 많은 오류 코드"(1-4 E02)라 2마리보다 많게, 로봇 2대 × 5회로 다 막을 수 있게 맞춘다(시뮬레이션 후 데이터 수정). 코어 피해는 적 1마리당 1(원본 "체력이 1 닳도록") |
| 실행 시작 | 사거리 안에 적이 들어와야 로봇 함수 실행(5회)이 시작된다(기획 확인) |
| 프로그램 시작 | 코드 영역 왼쪽 위 시작 위치에 붙은 블록부터 실행한다. 다른 곳에 떨어져 있는 블록은 실행되지 않는다(P7) |
| '코드 :' 표기 | 플레이어가 블록으로 직접 만드는 부분(기획 확인). 1-4 B02처럼 "그대로 남아 있네"로 보여 주기만 하는 곳은 예외 |
| 미리보기 | 실행 횟수 무제한, 공격 사거리 원 표시. 적이 모두 사라지면(로봇이 더 이상 때릴 수 있는 적이 없을 때 포함) 1초 후 다시 시작 |
| 회수 | 1-1·1-2 동안 잠금(1-3부터 가능) |
| 함수 실행 횟수 | 로봇 함수 `f`는 웨이브마다 `for i in range(5): f()`처럼 5번 실행. 반복문 해금 후에는 1번만 실행(그래서 반복문을 쓰게 됨). 모든 스테이지 동일. 공격 횟수 한도는 없음 |
| 게임 시작 | 타이틀 화면부터 시작 |
| 옛 대사 | 1-1~1-5 JSON·MD 전부 삭제 |

````text
## [새로운 코드 블록 추가하기]

[1-4.C02] 안내자 : 변수 이름은 `attack_range`로 정할 거야.

[1-4.C03] 안내자 : 그리고 `my_attack_range()`의 값을 `attack_range`에 저장하는 거지!

```python
attack_range = my_attack_range()
```

집중 : 변수 블록과 공격 사거리 값 강조

추가 효과 : 변수를 추가할 위치에 화살표 표시

[1-4.C04] 안내자 : 이제 이 블록을 `enemy_distance`를 계산하는 블록 아래에 연결해 보자!

상호작용 : 플레이어가 `attack_range = my_attack_range()` 블록을 추가하고 거리 계산 블록 아래에 연결한다.
▶ 입력 허용: 블록 팔레트, 코드 영역. 화살표: enemy_distance 줄 아래 연결 지점
▶ 완료: ProgramMatches = enemy·enemy_distance·attack_range 세 줄 + if enemy_distance <= my_attack_range(): + slash(enemy)

[1-4.C05] 안내자 : 좋아! 이제 공격 사거리 정보도 변수에 저장했어!

[1-4.C06] 안내자 : 그런데 아직 `if` 조건문에서는 `my_attack_range()`를 직접 사용하고 있지?

[1-4.C07] 안내자 : 이 부분을 방금 만든 `attack_range` 변수로 바꿔 보자!

집중 : if 조건문의 `my_attack_range()` 부분 강조

상호작용 : 플레이어가 기존 `my_attack_range()` 블록을 `attack_range` 변수 블록으로 교체한다.
▶ 완료: ProgramMatches = 아래 완성 코드. 차 있는 조건 칸에는 블록을 놓을 수 없어 my_attack_range()를 먼저 빼내야 함(현재 편집기 동작)

완성 코드 :
```python
enemy = get_nearest_enemy()
enemy_distance = enemy.distance(get_my_pos())
attack_range = my_attack_range()

if enemy_distance <= attack_range:
    slash(enemy)
```

[1-4.C08] 안내자 : 잘했어! 이제 두 변수에 저장된 값을 비교해서 공격 조건을 확인할 수 있어!

[1-4.C09] 안내자 : 공격하는 방식은 이전과 같지만, 필요한 정보를 변수에 저장해서 활용하도록 수정한 거야!

[1-4.C10] 안내자 : 좋아! 첫 번째 로봇은 완벽하게 개발했어!

[1-4.C11] 안내자 : 이제 남은 로봇도 직접 코딩해서 공격할 수 있도록 만들어 보자!

- 플레이어가 코드 조립을 완료하기 전까지 개발툴 닫기 및 ESC 제한
- 60초 동안 코드 조립을 완료하지 못하면 힌트 버튼 위에 화살표 표시

```

상호작용 : 플레이어가 모든 블록을 올바르게 연결하고 게임 화면으로 돌아온다.
▶ 힌트 내용 = 위 힌트 코드. 완료: ProgramMatches(두 번째 로봇) → 닫기·ESC 해제 → EditorClosed
````
