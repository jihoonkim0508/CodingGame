## 8. 맵 교체(map_v2)

- 스테이지 1 맵을 받은 `map_v2`로 바꿨다(`Stage01_v2.prefab`). 길이 더 길어졌다(37칸, 꺾임 8번).
- 적 경로와 코어 위치는 맵 에디터에서 지정한 출발·경로·기지를 그대로 쓴다(map_v2에는 지정이 없어 맵 에디터로 출발 (-10,1)·기지 (11,-1)·경로를 넣음). 적은 맵 밖이 아니라 출발 칸에서 나온다. 로봇 배치 구역과 카메라도 새 맵에 맞췄다. 튜토리얼의 길·배치 구역·코어 체력 강조도 새 맵을 따른다.
- 씬에 맵이 하나라 현재는 2·3스테이지도 같은 맵이다.
- 길이 길어져 적이 코어에 닿기까지 시간이 늘었다. 웨이브 시간·적 수 밸런스는 다시 보지 않았다.

## 21. 1-1~1-4 실제 빌드 플레이 테스트 (마우스·키보드 조작)

빌드한 게임 창을 실제 마우스 드래그와 키보드 입력으로 1-1부터 1-4 끝까지 진행했다.

| 항목 | 처리 |
| --- | --- |
| 1-2: 변수 이름을 `enemy` 대신 `target`으로 | 통과 확인(이전 이슈 해결 상태) |
| 1-3 B02: 이름(`target`, `dist`)·줄 순서를 바꿔서 | 통과 확인 |
| 1-3 C03: 조건식을 `dist <= my_attack_range()`처럼 다른 이름으로 | 막혀 있었음 → 고침. 앞 단계에서 만든 코드의 변수 이름과 짝지어 판정한다 |
| 1-4 C04: `attack_range` 줄을 `enemy_distance`와 `if` 사이에 끼우기 | 블록이 사이에 끼워지지 않고 if 위에 겹쳐 놓였음 → 고침. 줄 사이에 놓으면 끼워진다. 안내 화살표도 if 위가 아니라 두 줄 사이를 가리킨다 |
| 1-4 전투: 3배속에서 전투 대사를 넘기기 전에 웨이브가 끝나면 | 지난 전투 대사와 사거리 강조가 보상 창 위에 늦게 떴음 → 고침. 웨이브가 끝나면 남은 전투 대사는 건너뛰고 클리어 대사로 간다 |
| 힌트 창 | 긴 줄(`enemy.distance(get_my_pos())`)이 오른쪽에서 잘렸음 → 글자 크기가 자동으로 줄어든다(18 → 최소 12) |
| 하단 오류 안내 | 전사형인데 예시가 `attack(enemy)`였음 → 해당 명령 이름(`slash(enemy)`)으로 |
| 피해 시점 변경에 맞춘 검사 | 사격형(도착 시)·전사형(검이 지날 때) 피해에 맞게 헤드리스 검사를 고쳤다 |

**확인 요청**
- 1-4에서 두 번째 전사형을 길에서 먼 곳에 놓으면 공격하지 못하고 적 1마리가 기지에 닿는다(기지 12 → 10). 배치 위치를 안내할지.

## 28. 디버 대사 전면 개정 (2026-11-04, `claude/mda-upgrade`)

**이유**: 직접 플레이한 팀원 의견. 대사 흐름이 끊기고, "일부러 보여 주는 거야"처럼 개발자 입장에서 말해 플레이어에게 친절하지 않았다. 대사 수는 늘려도 되니 다 갈아엎으라는 요청이라 한 줄씩 다듬지 않고 전부 다시 썼다. 원본 대본에 없는 문장이므로 기획 확인이 필요하다.

- 단계(ID·순서·종류·집중·진행 신호)는 그대로다. 대화창을 늘린 곳은 같은 ID를 여러 줄 썼다(빌더가 한 단계의 대화창 여러 개로 만든다, 단계당 4개 이하). 1-1~1-5에서 101단계가 바뀌었고 대화창은 107개 → 167개. 시스템 배너 6줄(1-1 A01·D10, 1-4 A01, 1-5 A01, 2-1 A01, 3-1 A01)은 그대로.
- 결과 화면 옆 디버 한마디(`DefenseDebrief.GuideSays`)도 같은 말투로 바꿨다. 별 세 개 줄의 "별 세 개"와 표정은 그대로라 헤드리스 검사가 통과한다.

쓴 원칙:
- **디버의 눈으로만 말한다.** 튜토리얼·설명·소개·실습·기능·화면 위·단계 번호를 쓰지 않는다. 게임이 하는 일에는 게임 안의 이유를 준다. 0.2배속은 디버가 켠 '디버깅 모드', 일시정지는 디버거의 특기인 '시간 세우기'다. 1-1에서 강한 적이 코어에 닿는 장면은 연출이 아니라 진짜 위기("지금 우리 로봇으로는 무리야")로 받고, 코어가 버텼다고 안심시킨다.
- **반응하고, 잇고, 지시한다.** 대화창 하나에 생각 하나. 방금 일어난 일에 먼저 반응하고("세웠다!", "들어갔다!", "봤지?") 연결어로 다음 할 일을 꺼낸다. 행동을 기다리는 단계는 마지막 대화창이 지시이고, 전투 사건으로 시작하는 단계는 첫 대화창이 그 사건에 대한 반응이다.
- **비유 하나를 끝까지 이어 쓴다.** 코드 영역은 로봇의 '머릿속', 변수는 이름표 붙은 '상자'(담고 꺼내기), 사거리 조건은 1-1에서 본 공격 범위 '원', 조건은 '비가 오면 우산'. 1-2 이후 대사도 같은 말로 앞의 내용을 불러온다.
- **작은 이야기 줄기를 깐다.** 작업실을 지키는 디버의 자기소개와 도움 요청, 1-4 끝의 '큰 오류 신호' 복선, 1-5 보스, 남은 오류 코드가 데이터 분기 구역으로 몰려가며 Stage 2로 넘어간다. 장소 이름(개발자의 작업실·데이터 분기 구역·자동화 생산 공장)을 대사에 넣었다.
- **음성(TTS)으로 읽기 좋게 쓴다.** ~·…·①②·→·≤ 같은 기호와 괄호 속 덧말을 뺐다. `<=`는 굵게 태그 밖에 둔다: `GuideSpeech.Speakable`이 `<b><=</b>`를 태그로 보고 지워서, 예전 1-3 C04 음성은 기호를 건너뛰었다. 1-4·1-5의 백틱을 빼서 빌더가 코드 이름에 색을 입힌다.

## 30. 1-1 반복 해금과 대상 없는 slash() (2026-11-05, `claude/mda-upgrade`)

**이유**: 직접 플레이한 팀원 요청. "근거리 로봇의 매개변수 enemy를 없애고 slash()로", "공격범위를 360으로", "사거리 조금 더", "1-1에서 반복을 해금하고 로봇의 5회 반복 동작을 1회로". 기획 확인 전이다.

규칙:
- `slash()`는 인자가 없다. 사거리 안의 적을 모두 360도로 벤다(전엔 앞쪽 반원). 반복 안에서는 사거리에 적이 들어올 때까지 그 줄에서 기다린다. 로봇은 한 바퀴 도는 동작과 둥근 칼 궤적을 보인다.
- 전사 사거리 3.2 → 3.6, 폭탄형 4.8 → 5.4(전사의 1.5배 규칙).
- 1-1부터 `for`와 숫자 블록을 주고, 로봇 함수는 웨이브마다 1번 실행된다(전엔 반복 해금 전 5번, Stage 1 전체가 해당).
- 그래서 `for` 한 바퀴에서 if가 거짓이라 아무 명령도 하지 않았으면 그 바퀴는 세지 않고 다시 해 본다. `for i in range(10): if 적이 사거리 안: slash()`가 '열 번 벤다'가 된다. 대상이 사라져 건너뛴 명령(`attack(enemy)`의 오래된 변수)은 지금처럼 한 바퀴로 친다.

수업 흐름 (단계 ID 유지, 없앤 단계는 1-1 D01·D03·D04·D05·D07, 1-3 D04·D05):
| 웨이브 | 전 | 후 |

| 1-1 | 변수: `enemy = get_nearest_enemy()` / `slash(enemy)` | 반복: `for i in range(10):` / `slash()`. C05 for 놓기, C06 횟수 10, C08 반복 안에 slash(), C09 '한 바퀴 돌며 원 안 전부', C10·C11 반복문, D06 '원 밖이면 기다렸다 벤다' |

**확인 필요**: 로봇 사이·맵 가장자리 여유가 커져 Stage 2·3에서 같은 자리에 놓을 수 있는 로봇 수가 줄어든다. 사람 플레이로 빽빽한 배치가 막히는지 확인.

## 34. 실행 버튼과 동기 실행, Stage 1 진행 순서 (2026-11-05, `claude/mda-upgrade`)

**이유**: 플레이 피드백 4(8차 95~97). '농부는 대체되었다'처럼 함수를 부를 때만 실행하고, 진행을 1-1 slash → 1-3 반복문 → 2-1 변수 → 2-3 조건문 순으로.

| 항목 | 전 | 후 |
|---|---|---|
| 함수 실행 | 웨이브마다 저절로(반복 해금 전 5번, 후 1번), 사거리에 적이 와야 시작 | 전투 시작 때 모든 로봇 1번, 로봇 아래 '실행'으로 다시. 도는 동안 '실행 중' 잠금 |
| slash() | 사거리에 적이 올 때까지 그 줄에서 기다림 | 바로 휘두름(재사용 대기는 씀), 그 순간 사거리 안만 맞음 |
| 사거리 밖 attack(적) | 적이 올 때까지 기다림 | 빗나가고 다음 줄 |
| 거짓 if만 있는 반복 바퀴 | 0.25초 뒤 다시(바퀴를 안 씀) | 한 바퀴로 셈 |
| 원거리 피해 배수 | 사거리 ÷ max(1, 거리) | 사거리 ÷ max(사거리/3, 거리), 최대 3배 |
| 1-1 | for·range(10)·slash, 기본 적 체력 20 | slash() 한 줄과 '실행' 버튼, 기본 적 체력 14(한 번 베기) |
| 1-2 | 반복 자유, for·숫자 지급 | slash 자유, slash 2 지급 |
| 1-3 | 원거리 + 변수·조건문, 적 4마리(체력 64) | 반복문(for 2·숫자 2), 기본 적 8마리 1.2초 간격, 로봇 지급 없음 |
| 1-4 | 원거리 + 변수·조건문 블록 | 원거리 + for·숫자·attack·get_nearest_enemy() |
| 1-5 | 변수·조건문·my_attack_range 지급 | for·숫자·slash 지급 |

**확인 필요**: 사람 플레이로 1-1 E03b(적이 원에 들어오는 때 '실행')가 자연스러운지, 1-5 보스를 반복문과 '실행'만으로 잡을 수 있는지. Stage 2(2-1 변수, 2-3 조건문)는 아직 옛 지급·도입 대사.
