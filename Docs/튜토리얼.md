# 튜토리얼

Stage 1·Stage 2 튜토리얼의 구성과 대사·진행 단계 수정 방법을 정리한 안내서다. Stage 1 사양은 [튜토리얼_명세서.md](튜토리얼_명세서.md), 구조는 [튜토리얼_아키텍처.md](튜토리얼_아키텍처.md), 대사 원본은 [flow_stage1/tutorial_stage1_대본.md](flow_stage1/tutorial_stage1_대본.md)다. Stage 2 대본과 진행 조건은 [flow_stage2/tutorial_stage2_대본.md](flow_stage2/tutorial_stage2_대본.md)를 따른다.

## 구성

현재 Stage 1은 **1-1 변수·게임 플레이 소개 → 1-2 변수 자유 플레이 → 1-3 조건문 소개 → 1-4 조건문 자유 플레이 → 1-5 변수·조건문 보스 실습**으로 이어진다.

- 1-1은 첫 적을 처치한 뒤 일시정지·계속·2배속 버튼을 직접 사용한다. 배속 버튼은 해당 안내 단계가 시작되기 전까지 잠긴다. 마지막에는 강한 적 한 마리가 지나가 코어가 12에서 11로 줄어드는 모습을 보여 준다.
- 1-1의 세 적은 모두 기존 기본 잡몹 외형을 사용하며, 마지막 한 마리의 등장 수치만 강화한다. 1-2 자유 플레이 중에는 화면 중앙 상단에 목표를 계속 표시한다.
- 1-2는 짧은 안내 뒤 대화창과 입력 제한을 해제한다. 기존 코드를 지우지 않고, 새 전사·변수 기본 블록을 지급한다. 새 전사를 배치하고 적 찾기·변수·베기 코드를 적용해야 전투를 시작할 수 있다. 변수 이름과 배치 위치는 자유롭고 힌트는 선택 사항이다.
- 1-3은 조건 없는 베기를 먼저 보여 준다. 적 출현 지점에서 가장 가까운 로봇에 적 찾기·거리 저장 두 줄을 제공한 뒤 `적까지의 거리 <= my_attack_range()`와 if 안쪽 베기를 직접 조립한다. `my_attack_range()`는 현재 로봇의 실제 공격 사거리를 반환한다. 다른 로봇의 코드는 유지한다.

| 대상 | 역할 |
|---|---|
| `TutorialDirector` | 지금 스테이지·웨이브에 맞는 `TutorialSequence`를 준비 단계에서 시작하고, 단계마다 대사·입력 제한·진입 효과를 적용한다. 신호가 오면 다음 단계로 간다 |
| `TutorialSequence` asset | 웨이브 하나의 단계 목록(`Defense/Tutorial/Stage1/Tutorial_1-1.asset` ~ `Tutorial_1-5.asset`) |
| `TutorialWatcher` | 시뮬레이션에서 첫 처치·첫 공격·누출·웨이브 종료·코드 일치 신호를 만든다 |
| `TutorialInputBridge` | 대상 키(버튼·로봇·코드 영역 위치)를 화면 영역으로 바꾸고, 허용된 대상만 누를 수 있게 한다. 집중 테두리도 그린다 |
| `TutorialPointer`, `TutorialSystemAlert` | 화살표, `시스템` 대사 배너 |
| `DefenseCodeEditor` | 힌트 버튼·팝업, 코드 영역 안 위치(`Editor.Code.*`)와 팔레트 블록(`Editor.Palette.*`) 영역 |

블록 삽입 안내는 기준 코드와 연결 위치를 함께 말한다. 2-3 B03은 `for` 안의 적 찾기 줄 **바로 아래**에 빈 연결 칸을 보여 준다. `Editor.Code.BodyEnd.N`을 화살표·집중·드래그 예시의 목적지로 지정하면 N번째 블록의 기존 몸체 끝에 한 줄 공간을 확보한다. `autoSelectSlot`에도 같은 키를 넣으면 팔레트 클릭으로도 그 몸체에 추가한다. 안내가 끝나면 공간을 없애며 코드·재고에는 영향을 주지 않는다.

`After.N`은 복합 블록 높이와 관계없이 다음 명령 한 줄만 가리키고, 빈 `Body.N`은 안쪽 연결 칸의 너비를 사용한다. 편집기 강조는 스크롤 뷰포트에 보이는 영역으로 제한하고, 미리보기는 실제 영상 영역에 맞춘다. 등장할 때도 네모의 위치와 크기를 유지하며 어두워짐과 선 두께만 애니메이션한다. Play 검사는 `Tests/Unity/TutorialInsertion.playmode.cs`의 `TutorialInsertionCheck.Run`으로 실행한다.

## 대사·단계 고치기

1. [대본 문서](flow_stage1/tutorial_stage1_대본.md)의 해당 `[ID]` 줄을 고친다. 승인된 대사를 사용한다. 1-1은 2026-10-25 초보자용 개정안이며, 설치 전 A01~B02는 기존 대사를 유지한다.
2. 단계 구성(행동, 완료 신호, 집중, 화살표)을 바꿀 때는 `Assets/!_Project/Editor/Defense/TutorialSequenceBuilder.cs`의 해당 웨이브 목록을 고친다.
3. Defense 씬을 연 채로 Unity 메뉴 **Tools > Develop > Stage 1 튜토리얼 asset 다시 만들기**를 실행한다. 4개 asset, 캠페인 지급·주제·1-4 적 수, 씬의 시퀀스 연결을 다시 만든다(여러 번 실행해도 결과가 같다).

### 1-1만 적용하기

Play를 종료한 뒤 **Tools > Develop > Apply Beginner Tutorial 1-1**을 실행한다. 현재 씬과 관계없이 1-1 튜토리얼 asset과 캠페인의 1-1 전투 구성(강한 적·제한 시간)을 갱신한다. 다른 웨이브와 씬은 저장하지 않는다. 전체 재생성 메뉴도 같은 1-1 대본과 단계 구성을 사용한다.

### 1-1~1-3 적용·검사

**Tools > Develop > Apply Beginner Lessons 1-1 to 1-3**은 세 시퀀스와 해당 세 웨이브의 주제·보급만 갱신한다. 씬과 1-4 이후 데이터는 저장하지 않는다.

**Tools > Develop > Verify Beginner Lessons 1-1 to 1-3**은 위 적용 후 Play에서 게임의 편집기·보급·튜토리얼 판정·전투 진입점을 사용해 통합 검사를 실행한다. 결과는 `TestResults/Editor/beginner-lessons.log`에 남긴다. 이 검사는 실제 마우스·키보드 조작 검증과 구별한다.

## 확인하기

### Stage 2 (2026-11-04)

**2-1 반복문 소개 → 2-2 전사 자유 실습 → 2-3 원거리 소개 → 2-4 원거리 자유 실습 → 2-5 두 로봇 보스전**을 구성했다. Stage 1과 같은 `TutorialDirector`·대화창·화살표·강조·힌트·결과 수령 UI를 사용한다. 씬의 Director에는 두 스테이지의 시퀀스를 함께 등록한다.

- `Assets/!_Project/Defense/Tutorial/Stage2/Tutorial_2-1.asset` ~ `Tutorial_2-5.asset`가 단계 데이터다. `StageOneCampaign.asset` 이름은 유지하고 그 안의 Stage 2 보급·웨이브만 갱신한다.
- 2-1은 전사 두 줄을 준비한 뒤 플레이어가 for를 시작 위치에 넣고 내부 명령을 구성한다. 기존 for 팔레트의 초기 횟수는 10이며, 안내에서 3으로 바꾼다. 실행 시연은 자동 재생하고, 해당 회차의 관찰이 끝나면 기존 대화창의 다음 화살표로 설명을 넘긴다. 미리보기 안에는 별도 실행/다음 명령 버튼이 없다. 현재 줄·회차·공격 실행 수·처치 수와 종료 상태를 표시하며 자동으로 네 번째 회차를 시작하지 않는다.
- 2-2·2-4는 이번 웨이브에 새로 배치한 해당 직군의 반복 코드가 필요하다. `StageTwoLearning`이 연결된 AST의 for 본문·순서·같은 변수 참조·양의 정수 횟수를 검사한다. 변수 이름은 자유다. 미완성 편집 내용은 기존 편집기 초안으로 보존되며 유효한 프로그램이 없으면 전투 시작을 막는다.
- 2-3은 사격을 직접 연결한 뒤 실제 `shot`과 유효 피해가 있는 `projectile-hit`을 따로 관찰한다. 원문의 ‘사거리 스탯과 공격력이 반비례’와 ‘도착 시점에도 사거리 검사’는 현재 전투 코드와 달라 대본 §7의 교정 제안을 적용했다. 실제 규칙은 같은 로봇의 대상까지 거리에 따른 피해 변화와 발사 시 사거리 검사다.
- 힌트는 Stage 1과 같은 짧은 예시 코드 팝업을 사용한다. 2-2는 전사, 2-4는 원거리 반복 코드이며 2-5는 선택한 직군에 맞춘다. 버튼은 `힌트`/`힌트 닫기`로 전환하며 Escape는 힌트부터 닫는다. 코드를 자동 입력하지 않는다.
- 일반 구역 진입은 `systemTone=Calm`으로 서서히 나타나며 경고음·해금 배지 없이 표시한다. 원거리 해금은 `Positive`의 청록·금색 배너와 짧은 상승 음을 사용한다. 적·보스는 `Warning`의 빨간 경고로 웨이브 시작 전에 알린다. Stage 2의 2-1~2-4는 `EnemyWarning` 뒤에 전투 시작/자유 실습을 열고, 2-5는 A01에서 보스 경고 후 준비 설명으로 이어진다.
- 처음 안내자가 주의를 끄는 1-1 A02~A04는 `attentionEntrance`로 이름과 강조선을 빨갛게 표시한다. 이후 일반적인 진입 설명은 흔들거나 크게 튀어나오지 않고 부드럽게 이동·확대한다. `Tests/Unity/TutorialNotice.playmode.cs`의 `TutorialNoticeCheck.Run`으로 실제 경고 타이밍·입력 제한·진입 연출을 검사한다.
- 2-5는 전사·원거리의 유효 반복 코드가 모두 필요하고, 보스 실제 처치 후에만 성공 처리한다. 보스가 남은 채 시간 종료하거나 코어가 파괴되면 실패 선택창에 `튜토리얼 2 다시 시작`·`바탕화면으로 나가기`가 표시된다. 재시작은 배치·코드를 초기화하고 2-1 안내부터 시작한다. 바탕화면 버튼은 기존 타이틀 종료 버튼의 `GameFlow.QuitGame()`을 사용한다(에디터에서는 Play 종료, 빌드에서는 앱 종료).
- 2-1~2-4 패배 후 기존 결과 버튼은 해당 웨이브 전투 시작 직전의 준비 상태로 복원한다. 코어·코인·재고·코드를 복원하고 드롭·적·탄·실행 상태를 비우며 보급을 중복 지급하지 않는다.

대본/단계를 바꾸면 Play 종료 후 **Tools > Develop > Stage 2 튜토리얼 asset 다시 만들기** (`StageTwoTutorialBuilder.Apply`)를 실행한다. Stage 1 재생성 메뉴도 Stage 2 등록을 보존한다. 자유 실습 텍스트 힌트는 대본의 C01~C03/C04에서 읽는다.

헤드리스 검사는 `dotnet run --project Tests/Defense/Defense.Check.csproj`에 포함되어 있다. `StageTwoCheck.cs`는 구조 오답·자유 변수·횟수·직접 배치·실제 단일 실행·준비 상태 복원·보스 실패/성공을 검사한다. Unity 도구가 응답하면 `DevTest.PlayDefense(2, 1, true, false)`로 시작해 실제 블록 조작과 표시를 확인한다. 이번 적용의 검증 범위와 남은 화면 검증은 [Stage 2 개발 기록](flow_stage2/개발_기록.md)에 적는다.

실제 스테이지 선택 경로는 새 Title Play에서 `Tests/Unity/StageTwoEntry.playmode.cs`의 `StageTwoEntryCheck.Run`(Unity MCP `run_script`)으로 검사한다. `임시 클리어 → 2번 섬 → 2-1 반복문 안내`와 다섯 시퀀스의 실제 로드를 확인하고 `Temp/Stage2Play`에 로그/화면을 남긴다. Stage 2 asset은 Unity 빌더로 생성·저장해야 하며, 텍스트상 GUID 존재만으로 정상 로드를 판정하지 않는다.

## 개발 에디터에서 Stage 2 편집하기 (2026-11-05)

1. **Tools > Develop > 개발 에디터 → 플레이 → 튜토리얼 구간**에서 스테이지를 `Stage 2`로 고른다.
2. `2-1`~`2-5` 웨이브와 세부 구간을 선택하고 **이 구간으로**를 누른다. Edit Mode에서도 해당 조건으로 테스트 Play를 시작한다.
3. **선택 구간 편집 · 대사 / 강조 / 진행 조건**을 펼치면 대사 출력 속도, 해당 단계의 대사·집중·화살표·입력 대상·완료 신호 등을 편집할 수 있다. **asset 선택**은 원본 튜토리얼을 Inspector에 표시한다.
4. Play 중 편집 대상은 복사본이다. **이 구간으로**를 다시 누르면 편집한 내용을 미리보고, **튜토리얼 원본 저장**을 누를 때만 원본 asset에 저장한다. 저장하지 않은 Play 편집은 Play 종료 시 사라진다. Edit Mode에서는 원본을 편집하고 같은 저장 버튼으로 보관한다.

대본에서 빌더로 asset을 재생성하면 직접 편집한 단계 데이터가 덮어써진다. 지속할 대사 변경은 대본에도 반영한다. 웨이브별 적·지급·로봇 수치는 기존 **밸런스** 탭에서 Stage 2 항목을 편집한다.

Stage 2의 구간 이동은 이전 실습의 전사·원거리·반복 코드와 현재 단계의 편집기 상태를 준비한다. 예를 들어 2-3 B04는 공격 대상 칸이 비어 있는 원거리 코드를 연다. 2-1 관찰 구간은 for(3)와 단일 실행 미리보기를 준비한다. 결과 구간은 실제 전투를 시뮬레이션해서 완료 상태를 만든다. Stage 1의 기존 두 인자 API `DevTest.JumpTutorial(wave, step)`도 유지한다.

Stage 2 API 예: `DevTest.TutorialSections(2, 3)`, `DevTest.JumpTutorial(2, 3, 7)`(2-3의 8번째 단계, B04). `Tests/Unity/StageTwoEditor.playmode.cs`의 `StageTwoEditorCheck.Run`은 Play에서 실제 개발 에디터 컨트롤, 복사본 미리보기·명시적 저장·5개 웨이브 이동·기존 Stage 1 API를 검사한다. 결과는 `Temp/Stage2EditorCheck/result.log`에 남는다.
