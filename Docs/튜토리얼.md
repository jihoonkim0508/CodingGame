# 튜토리얼

Stage 1의 1-1~1-4 튜토리얼이 어떻게 돌아가고, 대사를 어떻게 고치는지 정리한 안내서다. 사양은 [튜토리얼_명세서.md](튜토리얼_명세서.md), 구조는 [튜토리얼_아키텍처.md](튜토리얼_아키텍처.md), 대사 원본은 [flow_stage1/tutorial_stage1_대본.md](flow_stage1/tutorial_stage1_대본.md)다.

## 구성

| 대상 | 역할 |
|---|---|
| `TutorialDirector` | 지금 스테이지·웨이브에 맞는 `TutorialSequence`를 준비 단계에서 시작하고, 단계마다 대사·입력 제한·진입 효과를 적용한다. 신호가 오면 다음 단계로 간다 |
| `TutorialSequence` asset | 웨이브 하나의 단계 목록(`Defense/Tutorial/Stage1/Tutorial_1-1.asset` ~ `Tutorial_1-4.asset`) |
| `TutorialWatcher` | 시뮬레이션에서 첫 처치·첫 공격·누출·웨이브 종료·코드 일치 신호를 만든다 |
| `TutorialInputBridge` | 대상 키(버튼·로봇·코드 영역 위치)를 화면 영역으로 바꾸고, 허용된 대상만 누를 수 있게 한다. 집중 테두리도 그린다 |
| `TutorialPointer`, `TutorialSystemAlert` | 화살표, `시스템` 대사 배너 |
| `DefenseCodeEditor` | 힌트 버튼·팝업, 코드 영역 안 위치(`Editor.Code.*`)와 팔레트 블록(`Editor.Palette.*`) 영역 |

## 대사·단계 고치기

1. [대본 문서](flow_stage1/tutorial_stage1_대본.md)의 해당 `[ID]` 줄을 고친다. 대사는 기획 원본과 같아야 한다(대본 문서 맨 위 규칙).
2. 단계 구성(행동, 완료 신호, 집중, 화살표)을 바꿀 때는 `Assets/!_Project/Editor/Defense/TutorialSequenceBuilder.cs`의 해당 웨이브 목록을 고친다.
3. Defense 씬을 연 채로 Unity 메뉴 **Tools > Develop > Stage 1 튜토리얼 asset 다시 만들기**를 실행한다. 4개 asset, 캠페인 지급·주제·1-4 적 수, 씬의 시퀀스 연결을 다시 만든다(여러 번 실행해도 결과가 같다).

## 확인하기

- 개발 에디터(Tools/Develop)의 플레이 탭에서 Stage 1 튜토리얼 웨이브·단계를 골라 바로 이동할 수 있다(`DevTest.JumpTutorial`). 앞 단계에서 놓았을 로봇은 자동으로 놓지만, 앞 단계에서 만들었을 코드는 넣지 않는다.
- `Tests/Unity/TutorialProbe.cs`는 Play 중 Unity MCP `run_script`로 튜토리얼을 플레이어처럼 진행하는 도구다(`State`, `Skip`, `ClickRobotButton`, `PlaceBest`, `SelectUnit`, `Develop`, `Load`, `StartBattle`, `Claim` 등).
