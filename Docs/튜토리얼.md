# 튜토리얼

> **현재 연결 해제됨 (시나리오 재작성 준비).** Defense 씬의 `DefenseBattle.tutorial` 참조를 비우고 `TutorialSystem`·`TutorialOverlay` 오브젝트를 비활성화했다. 게임은 튜토리얼이 없는 것처럼 동작한다(Stage 1 학습 규칙도 꺼짐). 대화창·입력 제한·스포트라이트 UI와 `StageOneTutorial` 코드는 그대로 남아 있어, 새 시나리오에서 다시 연결해 쓸 수 있다. 아래 내용은 이전 시나리오 기록이며 암묵 `enemy`/`enemyDistance`가 없어진 지금 규칙과 맞지 않는다.

Stage 1(1-1~1-5)은 변수와 조건을 가르치는 학습 스테이지다. 플레이어는 **전사형** 로봇을 배치하고, 실제 블록 코드 편집기에서 전사의 코드를 고치며 배우고, 편집기의 미리보기로 공격을 확인한다. `StageOneTutorial`이 실제 전투 세션 위에서 대사·입력 제한·진행 조건을 관리한다. Stage 2부터는 학습 규칙이 꺼지고 일반 캠페인이 된다.

## 단계별 학습

| 단계 | 섹션 | 배우는 것 | 통과 조건 |
|---|---|---|---|
| 1-1 변수 | 게임 시작 / 로봇 배치 / 변수와 값 / 값 바꾸기 / 첫 웨이브 | 변수 `damage` | 전사형 배치 → `damage = 20` → 웨이브 클리어 |
| 1-2 여러 변수 | 복습 / 두 변수 / 사거리 변화 / 직접 설정 / 배치 전략과 웨이브 | `damage`, `range` | `range = 8` → `damage`·`range` 둘 다 양수 → 웨이브 클리어 |
| 1-3 조건 | 무조건 공격의 문제 / if / 참·거짓 / 직접 만들기 / 웨이브 | `if enemyDistance <= 10:` | 조건 안에 `Attack()`, 기준 10 → 웨이브 클리어 |
| 1-4 조건 활용 | 조건값 / 5와 10 비교 / 조건값 선택 / 실패 보고 수정 / 실전 | 조건값 조정 | 아무 양수 기준 → 기준 8로 수정 → 빠른 적 섞인 웨이브 클리어 |
| 1-5 변수 + 조건 | 보스 등장 / `attackDistance` / 조건에서 변수 / 결과 확인 / 값만 바꾸기 / 보스 실습 / 전투 중 힌트 / 클리어 | 조건에 변수 사용 | `attackDistance = 15` → 변수 조건 자유 설정 → 보스 웨이브 클리어 → Stage 2 |

1-5 보스 웨이브: 보스 1마리는 `Route01`, 일반 오류 코드 3마리는 `TutorialRoute02`(북쪽 진입, 1-5에서만 도로 표시)로 온다.

## 진행 조건(게이트)

- **배치**(1-1 두 번째 섹션): 전사형 버튼과 배치 구역만 입력 가능(화면을 어둡게 하고 전사형 버튼 → 배치 구역 순서로 한 곳만 테두리 표시). 로봇이 1대 이상 배치되면 통과. 배치 후 사거리 원 안쪽이 채워져 공격 범위를 보여준다.
- **블록 코드**: 배치 이후 대사 섹션부터는 전사의 코드 편집기와 미리보기가 자동으로 열린다. 각 섹션에 필요한 시작 블록(예: `damage = 10` + `slash(enemy)`, 1-3부터 `if enemyDistance <= 5:`)을 플레이어가 이미 가진 값으로 채워 넣고, 플레이어가 블록을 직접 바꾸면 자동 적용 후 검사한다. 시작 블록 그대로는 통과하지 않는다.
  - 검사는 생성된 Python을 학습 표기로 바꿔 `StageOneCode.Validate`로 확인한다(`slash(enemy)` 등 → `Attack()`).
  - 숫자는 0 초과 100 이하. 미완성·목표 불일치는 대사가 아니라 편집기 상태 줄에 이유와 힌트를 표시한다. 1-3부터 조건 밖 공격 블록은 거부.
  - 미리보기에서 적이 맞으면 피해 숫자(`-20` 등)가 떠올라 `damage` 값이 실제 피해임을 보여준다.
- **실제 웨이브 클리어**: 남은 적 0, 이번 웨이브 누출 0일 때만 통과. 누출·시간 종료는 실패로 보고 재시작을 안내한다. 재시작은 로봇과 학습 진행을 함께 초기화한다.
- 학습 중에는 로봇 종류·배치·단축키가 잠긴다. 대사 섹션에서는 전투가 일시정지된다.
- Stage 1 학습 규칙: 반복·공격 횟수 제한 없음, `damage`·`range`가 실제 피해·사거리. 전사는 기본 사거리 3.2라 1-1에서는 길 가까이 배치해야 한다.

## 콘텐츠 로딩

1. 대사 원본은 `Docs/flow_stage1/stage1_*.json`이다. Unity 에디터가 켜질 때·Play 직전·메뉴 `CodingGame > Stage 1 대사 JSON 동기화`에서 `Assets/!_Project/Defense/Tutorial/Stage1/`의 같은 이름 TextAsset으로 복사하고(`StageOneContentSync`), `StageOneTutorial.stages`가 그 TextAsset 5개를 읽는다.
2. `StageOneContent.Read`가 형식을 검사한다: `format_version` 1.0, `stage_id` 1-N, `locale` ko-KR, 섹션 수(1-1~1-4는 5개, 1-5는 8개), 모든 대사에 화자·본문.
3. 섹션의 `dialogues`는 대화창, `interaction`의 `prompt`는 보스 웨이브 안내, `retry_hint`는 누출·코드 힌트, `success_feedback`은 코드 통과 시 편집기 상태 줄 문구로 쓰인다. `code_examples`는 원문 기록용이며 화면에는 실제 블록이 대신 나온다. `direction`은 제작 지시라 출력하지 않는다.

JSON 필드 상세는 [flow_stage1/stage1_tutorial_implementation_guide.md](flow_stage1/stage1_tutorial_implementation_guide.md).

## 대사 수정 방법

- `Docs/flow_stage1/`의 JSON(원본)과 같은 이름의 `.md`(읽기용)를 **같이** 고친다. `check_stage1_content.py`가 JSON 내용이 Markdown에 그대로 있는지, Unity 복사본이 최신인지 검사한다.
- 문장 수정은 자유. 섹션 추가·삭제·순서 변경, 행동 섹션의 대사 줄 수 변경은 `StageOneTutorial.cs`가 섹션 번호와 대사 위치(행동 전 끊는 줄, 첫 처치·누출·보스 힌트 대사)를 직접 쓰므로 코드도 함께 바꿔야 한다.
- 대사·피드백 안의 `` `code` ``는 강조색(#6FFFD2)으로 표시된다(대화창 rich text).
- `preserve_terms`(`damage`, `range`, `enemyDistance`, `attackDistance`, `if`, `<=`, `Attack()`)는 바꾸지 않는다. 코드 검사가 이 표기를 기준으로 한다.

## 화면 결정

- 대화창은 작게 유지한다. 위쪽 위치에서는 HUD 헤더를 가리지 않도록 `TutorialDialogueView.topInset`(96px)만큼 내려온다.
- 대화창에는 화자와 대사만 표시한다(스테이지 번호 표시 없음). 별도 학습 카드·시연 패널은 없다.
- 배치 중에는 대화창이 위, 편집기가 열려 있거나 대사 섹션이면 아래(편집기 상태 줄이 보이도록 44px 올림).
- 웨이브가 진행 중(전투·일시정지)이면 대화창은 아래로 가고 안내 테두리를 모두 끈다. 웨이브가 끝나면 원래 위치로 돌아간다.
- 행동을 기다릴 때만 테두리를 표시하고, 항상 다음에 누를 한 곳만 표시한다(`TutorialStep.highlightKeys`). 화면을 어둡게 하는 것은 배치 단계뿐이다(`TutorialStep.dim`).
- 학습이 개발·레벨업·회수를 막는 동안 로봇 행동 메뉴를 숨긴다(`DefenseBattle.CanShowRobotActions`).
- 1-1 시작 시 부팅 화면, 1-5 시작 시 경고 문구·경고음, 클리어 시 `WAVE CLEAR` / `STAGE CLEAR`.

## 범용 튜토리얼 시퀀스

Stage 1 외 튜토리얼은 `TutorialSequence` asset으로 만든다(현재 `SequenceTest.asset`만 있고 비활성).

1. `Create > CodingGame > Tutorial > Sequence`로 만들고 stage·wave·진입 시점(준비/전투/보상)을 지정한다.
2. 단계별 대사를 쓰고, 행동이 필요한 단계만 `ActionGuide`로 지정한다.
3. `TutorialInputBridge`에 강조할 UI·월드 대상과 대상 키(예: `Battle.Start`, `Battle.Robot.4`, `Editor.ProgramDropZone`)를 연결한다.
4. 단계에 대상 키·완료 방식(클릭/드래그/외부 신호)·성공 신호를 지정한다.
5. `enabled`를 켜고 `TutorialDirector.sequences`에 넣는다. 같은 stage·wave·시점에 시퀀스는 하나만 허용된다.

대상이 사라지거나 참조가 빠지면 튜토리얼은 오류를 남기고 종료하며 입력 제한을 해제한다.
