# 스테이지 캐시 사용법


## 캐시 만들기

아래를 고쳤다면 녹화본이 옛날 것이 되므로 **다시 만들어야** 합니다.

- 튜토리얼 대사·단계 (대본 문서를 고치고 튜토리얼을 다시 만든 경우)
- 웨이브 수치 (몬스터 수, 체력, 속도 등)
- 로봇·몬스터 데이터

### 만드는 법

1. Unity에서 **Play를 멈춘 상태**로 둡니다.
2. 메뉴바 **Tools → Develop → 스테이지 캐시** 클릭.
3. 1~3스테이지를 자동으로 플레이합니다. **약 7분** 걸리고, 그동안 Unity를 만지지 마세요. Play가 몇 번 켜졌다 꺼지는 게 정상입니다.
4. 끝나면 Console 창에 스테이지별 요약이 나옵니다.
   예: `Stage 1: 입력 78개, 표시 70개 …`
5. 아래 파일 3개가 새로 만들어집니다.
   - `Assets/!_Project/Resources/Dev/StageCache_1.json`
   - `Assets/!_Project/Resources/Dev/StageCache_2.json`
   - `Assets/!_Project/Resources/Dev/StageCache_3.json`

### 깃에 올리기

**캐시 파일 3개와 `.meta`만** 커밋하세요.

```powershell
git add "Assets/!_Project/Resources/Dev/"
```

(이 폴더에는 캐시 파일 3개와 `.meta` 파일만 있습니다.)

```powershell
git commit -m "스테이지 캐시 갱신"
```

⚠️ **`Defense.unity`(씬 파일)는 같이 올리지 마세요.** 캐시를 만드는 도중 Unity가 씬을 저장해서 변경된 것으로 보이지만, 캐시와는 관계없는 변경입니다. `git add .`나 "전체 선택 커밋"은 쓰지 마세요.

## 3. 패널에 이런 문구가 뜨면

| 문구 | 뜻 | 할 일 |
|---|---|---|
| **캐시 없음** | 녹화본 파일이 없음 | 2번(캐시 만들기) 실행 |
| **캐시 오래됨** | 녹화한 뒤 대사·웨이브·데이터가 바뀜 | 2번 다시 실행 |
| **캐시에 없는 대사** | 녹화본에 그 ID가 없음 | ID 오타 확인. 3스테이지는 3-1만 있음 |
| **캐시 재생이 어긋남** | 다시 돌린 결과가 녹화와 다름 (맵을 고친 경우 등) | 2번 다시 실행 |

이 문구가 떠도 이동은 됩니다. 다만 그 웨이브의 **처음 상태**(로봇·코드 없음)로 이동합니다.

---

## 4. 알아둘 점

- 녹화본은 **정답 코드로 자동 플레이한 기록**입니다. 그래서 코어 체력이나 남은 블록 수가 실제 사람이 플레이했을 때와 조금 다를 수 있습니다.
- 코드 편집기에서 **시작 줄에 붙지 않고 떠 있는 블록**은 복원되지 않습니다.
- "몇 초 뒤에 나오는" 대사는 이동한 시점부터 시간을 다시 세서 조금 늦게 뜰 수 있습니다.
- 3스테이지는 튜토리얼이 3-1뿐이라 3-1 대사만 이동할 수 있습니다.

---

## 5. 문제가 생기면

- 캐시를 만드는 중 멈추거나 Console에 빨간 오류가 나오면, 오류 문장을 복사해서 공유해 주세요.
- 이동했는데 상태가 이상하면, 입력한 대사 ID와 화면 캡처를 공유해 주세요.
