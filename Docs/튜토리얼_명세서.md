이 문서는 "무엇이 어떻게 동작해야 하는가"를 정한다. 대사 문장은 대본 문서가 원본이다.

**이번 범위**: 기획 답(P1·P2·P3·P19)과 1-4 수정본(`튜토리얼_대사목록_수정본(4w 수정본).txt`)을 반영했다. 기획자에게 물을 질문은 남아 있지 않다. 2026-10-15 사용자 지시로 집중·화살표 대응(§10), 두 단계 행동, 1-4 두 번째 로봇, 커리큘럼(지급 블록·주제·적 수)을 정했다. 남은 사용자 결정(§9)에 달린 칸은 `사용자 결정(Pn)`으로 표시한다.

## 1. 목표

| 단계 | 플레이어가 배우는 것 | 완성 코드 |
|---|---|---|
| 1-1 | 변수에 적 정보를 저장하고, 그 변수를 공격 명령에 넘긴다 | `enemy = get_nearest_enemy()`<br>`slash(enemy)` |
| 1-2 | 점(`.`)으로 변수에 담긴 대상의 정보(`distance`, `hp`)를 꺼낸다. 1-1 코드를 스스로 다시 만든다 | 1-1과 같음 |
| 1-3 | 적과의 거리를 변수에 저장하고, 공격 사거리와 비교하는 조건과 `if`로 공격 시점을 정한다 | `enemy = get_nearest_enemy()`<br>`enemy_distance = enemy.distance(get_my_pos())`<br>`if enemy_distance <= my_attack_range():`<br>`    slash(enemy)` |
| 1-4 | 사거리 값을 새 변수 `attack_range`에 저장하고 조건에 쓴다. 두 번째 로봇은 힌트를 보며 혼자 같은 코드를 만든다 | `enemy = get_nearest_enemy()`<br>`enemy_distance = enemy.distance(get_my_pos())`<br>`attack_range = my_attack_range()`<br>`if enemy_distance <= attack_range:`<br>`    slash(enemy)`<br>(두 로봇 모두) |

## 2. 게임 규칙

| # | 규칙 | 상태 |
|---|---|---|
| R1 | 플레이어는 블록 편집기로 코드를 만든다. 변수 이름은 지금처럼 변수 블록 입력칸에 친다(원본 의도는 "타이핑 없음". 이름이 정해진 블록으로 바꿀지는 사용자 결정(P20)) | 기존 |
| R2 | 로봇 함수 `f`는 웨이브마다 `for i in range(5): f()`처럼 5번 실행된다. 반복문(`for`/`while`) 해금 후에는 1번만 실행된다. 모든 스테이지 동일 | 완료 |
| R3 | 공격 횟수 한도는 없다. 함수 안에 공격 명령을 몇 개든 넣을 수 있다 | 완료 |
| R4 | 사거리 안에 적이 들어와야 함수 실행(5회)이 시작된다. 그전에는 로봇이 기다린다(기획 확인, P1) | 기존. 옛 Stage 1 학습 모드의 예외는 레거시 삭제 때 없어짐 |
| R5 | 웨이브가 바뀌어도 로봇·코드는 유지된다. 스테이지가 바뀔 때만 초기화된다. 한 스테이지 안에서 맵은 같다 | 기존 |
| R6 | 웨이브 통과 = 기지가 살아 있음. 1-1~1-4는 지지 않도록 설계(의도) | 기존 |
| R7 | 1-1~1-3 적: 오류 코드 각 2마리(기지 도달 시 기지 -1, 기지 체력 12). 1-4는 "더 많은 오류 코드"(1-4 E02)라 4마리. 모두 정답 코드로 다 막을 수 있게 맞춤 | 완료 |
| R8 | 거리 단위: 1 grid = 1, 맵 한 블록 = 2. 시뮬레이션 좌표 = 월드 XZ | 기존 |
| R9 | 거리 코드: `enemy.distance(get_my_pos())`. `get_my_pos()`는 `Vector2` 객체, `distance`는 float. 기존 `get_distance(x, y)`는 이 방식으로 대체 | 완료 |
| R10 | `enemy.hp`는 읽기 전용 프로퍼티(괄호 없음) | 기존 |
| R11 | 1-1·1-2 동안 로봇 회수 불가(버튼 비활성, "회수는 1-3부터 열립니다"). 1-3·1-4까지 넓힐지는 사용자 결정 대기 | 완료 |
| R12 | 레벨업은 1-2부터 가능. 튜토리얼 중에도 따로 잠그지 않는다(P18) | 기존 |
| R13 | 미리보기: 실행 횟수 무제한, 로봇 공격 사거리 원 표시, 적이 모두 사라지거나 로봇이 더 이상 때릴 수 있는 적이 없으면 1초 후 재시작 | 완료 |
| R14 | 게임은 타이틀 화면부터 시작 | 기존 |
| R15 | 코드 이름은 Python 규칙(소문자 snake_case): `get_nearest_enemy`, `enemy_distance`, `my_attack_range()`, `attack_range` | 대본 반영 |
| R16 | 사거리 값은 함수 블록 `my_attack_range()`로 읽는다. 버프를 포함한 현재 사거리(float)이고 바꿀 수 없다(P10) | 완료 |
| R17 | 프로그램은 코드 영역 왼쪽 위 시작 위치에 붙은 블록부터 실행된다. 시작 위치 가까이 놓으면 붙는다. 다른 곳에 떨어진 블록 묶음은 실행되지 않는다("첫 블록을 왼쪽 위 시작 위치에 붙여 주세요"). 첫 블록을 지우면 다음 블록이 시작 위치로 올라온다(P7) | 완료 |
| R18 | 대본의 '코드 :'는 플레이어가 블록으로 직접 만드는 부분이다(기획 확인, P3). 보여 주기만 하는 곳(1-4 B02 "그대로 남아 있네")은 예외 | 대본 반영 |
| R19 | 1-4에는 전사형 로봇이 2대 있다. 첫 번째(교육 로봇, 1-3 코드 그대로)는 안내자와 함께 고치고, 두 번째는 1-4 시작 때 지급되어 플레이어가 원하는 곳에 배치하고 혼자 코드를 만든다(P25) | 완료 |
| R20 | 지급 블록(누적 재고)은 각 웨이브의 정답 코드를 만들 만큼만 준다. 옛 커리큘럼의 숫자 블록 지급은 뺀다. 표는 §2-1 | 완료 |

R7 근거: 전사 피해 14, 적 체력 18~27 → 1마리에 베기 2번, 2마리 = 4번 ≤ 함수 5회. 시뮬레이션(정답 코드, 길에서 거리 1.6~2.8)으로 1-3까지 전사 1대가 2마리 처치 확인. 1-4(적 체력 26.4)는 전사 2대가 길 옆 어디에 있어도(서로 3~6칸 떨어짐) 4마리·5마리 모두 처치, 6마리는 1마리 누출. 4마리면 실행 2회가 남고, 두 번째 로봇이 닿지 않는 곳에 있어도 2마리만 새서 기지가 버틴다. 빠른 오류 코드는 로봇이 길에서 멀면 놓쳐 쓰지 않는다.

블록 재고는 스테이지 안에서 누적되고, 코드에서 블록을 빼면 재고로 돌아온다. 아래는 각 웨이브 준비 단계에 더해 주는 양이다(보상 블록은 그대로 둔다).

|---|---|---|---|
| 1-1 | 전사 1 | 변수 선언 1, `get_nearest_enemy()` 1, 변수 1, `slash()` 1 | 완성 코드 2줄 |
| 1-2 | — | — | 1-1 코드를 지웠다 다시 만들 뿐이라 추가 없음 |
| 1-3 | — | 변수 선언 1, 변수 2, `get_my_pos()` 1, `if` 1, 비교 1, `my_attack_range()` 1 | 거리 줄(변수 선언, `enemy.` 메서드 변수, `get_my_pos()`), 조건(비교, 변수, `my_attack_range()`), `if` |
| 1-4 | 전사 1 | 변수 선언 4, `get_nearest_enemy()` 1, 변수 5, `slash()` 1, `get_my_pos()` 1, `if` 1, 비교 1, `my_attack_range()` 2 | 첫 번째 로봇: `attack_range` 줄(변수 선언 1, `my_attack_range()` 1. C04 순간에는 조건에 하나 더 있음)과 조건의 변수 1. 두 번째 로봇: 완성 코드 전체 |

## 3. 대사 표시

| 항목 | 사양 |
|---|---|
| 형식 | `발화자 : 대사`. 발화자는 대화창 하나(대사 한 줄)마다 데이터에 입력 |
| 시스템 대사 | 발화자가 `시스템`이면 대화창 대신 UI(화면 배너)로 표시. 경고음과 자동 넘김은 사용자 결정 대기 → 지금은 경고음 없이(소리 파일 비움), 배너가 사라지면 다음으로 넘어감 |
| 코드 강조 | 대사 안 함수·변수 이름은 강조색 |
| 줄바꿈 | 대사의 `\n`은 대화창 줄바꿈 |
| 넘기기 | 이전/다음 버튼. 행동을 기다리는 대사에서는 행동을 마칠 때까지 다음 잠금 |
| 타이핑 | 처음 보는 대사만 타이핑 연출, 다시 볼 때는 즉시 표시. 다음 버튼으로 타이핑 건너뛰기 |
| 전투 일시정지 | 단계마다 데이터(`pauseBattle`)로 정한다. 전투 중 대사에서 전투를 계속할지는 사용자 결정 대기 → 지금은 전투 중 대사만 `pauseBattle = false` |

## 4. 화면 안내 요소

| 요소 | 사양 |
|---|---|
| 어둡게 | 배치 단계(1-1 B01·B02)에서만 대상 밖을 어둡게 |
| 테두리 | 다음에 누를 곳 한 군데만 |
| 집중 | 대본의 '집중' 줄 = 해당 대화창이 떠 있는 동안 스포트라이트(나머지 화면을 어둡게, 대상만 밝게 + 테두리, 누를 수는 없음). 행동 단계도 같은 스포트라이트를 쓰고, 집중이 있으면 테두리는 집중 대상에만 그린다. 모양은 대상에 맞춘다: 길은 도로를 따라 조각으로, 사거리는 타원, 코드 영역은 보이는 편집 화면. 배치 영역(맵 전체)은 누를 수만 있고 그리지 않는다. 이벤트성 대상(적 처치 장면, 공격 동작)과 화면 전체(개발툴 화면)는 표시하지 않음. 대응표 §10 |
| 화살표 | 대본의 '화살표' 메모 위치(대응표 §10). 대상 위에서 위아래로 움직임. 지연 시간(`pointerDelay`)을 둘 수 있음. 코드 영역 안 위치(시작 위치, N번째 줄 아래, `if` 안쪽, 조건 칸)도 가리킬 수 있음 |
| 입력 제한 | 행동 단계에서는 지정 대상만 클릭 가능. 대화창은 항상 사용 가능 |
| 힌트 버튼 | 코드 편집기 '비우기' 오른쪽. 힌트를 안내하는 구간(1-2 C05~, 1-4 D01~)에서만 보임. 누르면 힌트 코드 표시 |
| 사거리 값 표시 | 1-3 원본: "오른쪽 UI"에 `my_attack_range()`의 이름과 값. 위치는 사용자 결정(P9). 1-4 수정본은 "로봇의 공격 범위"(사거리 원)를 씀 |
| 조건 결과 `True`/`False` 표시 | 1-3 원본: 조건 결과를 표시(집중 대상은 조건 블록). 위치는 사용자 결정(P11) |
| 로봇 확대 | 원본의 "확대"는 카메라 줌인(다른 곳은 "강조"로 씀). 만들지는 사용자 결정(P5). 지금은 테두리·화살표만 |
| 두 단계 행동 | 대사 한 줄에 행동이 둘(로봇 클릭 → '개발' 클릭)이면 같은 대사로 단계를 둘로 나눈다. 두 번째 단계에서는 타이핑을 다시 하지 않는다 |

## 6. 판정

**프로그램 일치**: 대상 로봇 프로그램의 Python 미리보기에서 함수 머리줄을 빼고, 각 줄의 들여쓰기·앞뒤 공백·빈 줄을 무시한 결과가 정답과 같으면 일치. 변수 이름이 대본과 다르면 불일치. 시작 위치에 붙지 않은 블록은 프로그램에 들어가지 않는다(R17).

**대상 로봇**: 기본은 교육 로봇(이 스테이지에서 처음 배치한 전사형 로봇). 1-4 두 번째 로봇 단계는 두 번째로 배치된 전사형 로봇.

**조건식 일치**(1-3 C03): 코드 영역에 따로 놓인 조건 블록 중 식이 정답(`enemy_distance <= my_attack_range()`)과 같은 것이 있으면 일치. 이 블록은 아직 프로그램에 연결되지 않은 상태라 프로그램 일치로는 볼 수 없다.

## 10. 집중·화살표 대응표

"대상"은 아키텍처 §5의 대상 키다. `Robot.Unit.N`·`Robot.Range.N`은 N번째로 배치된 로봇(0부터)과 그 사거리, `Editor.Code.*`는 코드 영역 안 위치(줄 번호는 시작 위치 줄부터 1), `Editor.Palette.*`는 팔레트의 블록이다. 표시할 대상이 없으면(편집기가 닫혀 있음, 블록이 아직 없음) 그리지 않는다. 행동 단계의 클릭 대상은 늘 테두리가 있으므로 따로 적지 않는다.
