# 원거리형 집중 공격 코드: 할 일과 구조

2026-11-16. 원거리형이 아래 코드로 움직이게 만드는 데 필요한 일, 팀 피드백(미룬이), 미리보기 점검 결과를 한곳에 모은다.

## 1. 목표 코드

이 브랜치(`claude/ranged-falloff`)는 **거리 반비례 피해를 살린다.** 원거리형 피해는 `사거리 ÷ max(사거리/3, 거리)`배라서 사거리의 1/3 안에서 최대 3배, 사거리 끝에서 1배다. 그래서 탱커가 사거리의 0.3배 안에 들어왔을 때만 쏜다(0.3 < 1/3이라 쏜 발은 모두 3배).

```python
while True:
    enemy = get_nearest_enemy()
    if enemy.type != Enemy.Tank:
        continue
    while True:
        if enemy.is_dead():
            break
        dist = enemy.distance(get_my_pos())
        if dist > my_attack_range():
            break
        if dist < my_attack_range() * 0.3:
            shoot(enemy)
```

- 원거리형 사거리 7이면 2.1 안에서만 쏜다. 길에서 2.1보다 멀리 세운 원거리형은 한 발도 쏘지 않는다. 길 바로 옆에 세워야 한다.
- 탱커가 0.3배 밖·사거리 안에 있는 동안 안쪽 반복은 쏘지 않고 돈다(틱마다 64명령에서 멈춤, 멈춤 없음).
- 반비례를 버린 판은 `claude/ranged-flat` 브랜치다. 거기서는 0.3 줄 없이 사거리 안이면 바로 쏜다.
- 검사: `RangedFocusCheck`가 이 글을 그대로 읽어 돌린다. 모든 발이 사거리의 0.3배 안에서 나가고, 한 발 피해가 기본의 3배인지 본다.

### 실제 3-3 웨이브에서 잰 결과

원거리형 Lv1 하나(사거리 7, 피해 32, 재장전 6초), 탱커 3(체력 152, 속도 1.78)과 일반병 6. 에디터에서 그 웨이브의 실제 수치를 복사해 돌렸다.

| 코드 | 길에서 1.9 (가장 가까운 자리) | 길에서 3.9 |
|---|---|---|
| 0.3배 안에서만 쏘기 (이 코드) | 1발, 탱커 피해 96 | 0발 |
| 사거리 안이면 쏘기 (처음 코드) | 4발, 탱커 피해 150 | 3발, 142 |

일반병은 두 코드 모두 한 번도 맞지 않았다.

**이 코드가 덜 쏘는 이유:**

- 0.3배 구역(반지름 2.1)은 가장 가까운 자리에서도 길을 1.8쯤만 덮는다. 탱커는 그곳을 1초 만에 지나가는데, 재장전은 6초다.
- `shoot()`은 재장전이 끝날 때까지 그 줄에서 기다리고, 거리를 다시 보지 않는다. 그래서 첫 발 뒤의 `shoot`은 6초 뒤에 이미 사거리 밖으로 나간 적을 노려 빗나간다.
- 헤드리스 검사(재장전 0.5초)에서도 3.0 기준으로 결정한 발이 3.2에서 나갔다.

**이 코드가 제값을 하려면** 다음 중 하나가 필요하다(정하지 않음):

- 원거리형 재장전 줄이기.
- 재장전 중이면 `shoot`이 기다리지 않고 다음 줄로 넘어가기. 그러면 거리를 다시 보게 된다. 다른 로봇의 명령에도 같은 규칙인지 정해야 한다.
- 재장전이 끝났는지 알려 주는 함수(예: `can_shoot()`).

반비례 없이 쓰던 처음 코드(지금도 동작한다):

```python
while True:
    enemy = get_nearest_enemy()
    if enemy.type != Enemy.Tank:
        continue
    while True:
        if enemy.is_dead():
            break
        if enemy.distance(get_my_pos()) > my_attack_range():
            break
        shoot(enemy)
```

받은 코드의 이름 세 개는 이미 게임에 있는 이름으로 바꿔 적었다. 튜토리얼·블록·답 해석기가 이미 이 이름을 쓴다.

| 받은 코드 | 게임의 이름 |
|---|---|
| `enemy.is_die()` | `enemy.is_dead()` |
| `get_my_arrange()` | `my_attack_range()` |
| `get_my_pos` (괄호 없음) | `get_my_pos()` |
| `attack(enemy)` | `shoot(enemy)` (2026-11-16 이름 바꿈: 블록·컴파일러·튜토리얼·도감) |

## 2. 줄마다 지금 되는지

| 줄 | 상태 | 근거 |
|---|---|---|
| `while True:` 두 겹 | 됨 | `DefenseProgram.EmitSuite`가 반복문마다 break·continue 목록을 따로 가진다. 안쪽 `break`는 안쪽 반복만 끝낸다. `WhileTrueCheck` |
| `enemy = get_nearest_enemy()` | 됨 | 적이 없으면 id 0(없는 적) |
| `!=` | 됨 | a660eb8. 숫자·참거짓·적·위치를 비교한다(종류가 다른 값끼리는 늘 "다름") |
| `enemy.type`, `Enemy.Tank` | 됨 | 3절. `enemy.` 뒤 메뉴의 `type`, 값 탭의 `Enemy. [Tank]` 블록 |
| `continue` | 됨 | |
| `enemy.is_dead()` | 됨 | 없는 적·죽은 적 모두 True |
| `enemy.distance(get_my_pos()) > my_attack_range()` | 됨 | 죽은 적의 거리는 무한대라서 break로 빠진다. `my_attack_range()`는 버프까지 반영한 사거리 |
| `shoot(enemy)` | 됨 | 재장전(원거리형 6초) 동안 이 줄에서 기다린다. 대상이 죽었으면 바로 다음 줄로, 사거리 밖이면 빗나감 처리 후 다음 줄로 간다 |

**결론:** 목표 코드 전체가 동작한다. 헤드리스 `RangedFocusCheck`가 이 Python 글을 그대로 읽어(`TutorialAnswers.Parse`) 시뮬레이션에서 일반병은 한 번도 맞지 않고 탱커만 맞는 것을 확인한다.

### 실행할 때 주의할 점

1. **가장 가까운 적만 본다.** `get_nearest_enemy()`는 사거리와 상관없이 전체에서 가장 가까운 적을 준다. 그 적이 탱커가 아니면 `continue`로 같은 적을 다시 고른다. 그래서 탱커가 *가장 가까운 적*이 되기 전에는 한 발도 쏘지 않는다. 지나간 일반병도 코어에 닿기 전까지는 계속 가장 가까운 적일 수 있다.
   - 권장: 코드는 그대로 두고 웨이브로 푼다(2-8에서 탱커를 따로 늦게 보내거나, 앞의 일반병은 전사형이 잡게 한다).
   - 대안: `get_nearest_enemy(Enemy.Tank)`처럼 종류를 받는 버전, 또는 적 목록 `for e in get_enemies():`. 목록 쪽은 리스트 타입이 필요해서 일이 크다.
2. **재장전 중에는 검사하지 않는다.** `attack`이 6초를 기다리는 동안 `is_dead()`·거리 검사는 돌지 않는다. 재장전이 끝나야 다음 줄로 넘어간다. 동작은 맞지만 미리보기 상태 줄에 "재사용 대기"가 오래 보인다.
3. **적이 없을 때 계속 돈다.** `wait`이 없으니 바깥 반복이 틱마다 64명령(`InstructionBudget`)까지 돌고 멈춘다. 멈춤은 없지만 낭비다. 문제가 되면 적이 없을 때 `continue` 전에 짧은 대기를 넣는 것을 답으로 안내한다.
4. ~~잘못된 경고~~ 고침: 반복 안에서 `enemy.is_dead()`를 보는 변수는 `HasStaleEnemyLoop`가 경고하지 않는다. 다시 보지 않는 반복(`enemy = …` 뒤 `while True: shoot(enemy)`)은 그대로 경고한다.

## 3. 적 종류 값 (만듦)

Python으로 읽으면 `enemy.type`은 적의 종류, `Enemy.Tank`는 종류 상수다. 게임 안의 종류는 이미 `EnemyType { Normal, Fast, Tank }`(일반병·속도병·탱커병)로 있다.

| 층 | 파일 | 할 일 |
|---|---|---|
| 블록 종류 | `BlockCoding/BlockProgram.cs` | `BlockKind` **맨 끝에** `EnemyTypeOf`(받는 쪽 1칸, `enemy.type`), `EnemyTypeName`(`Value`가 `Normal`/`Fast`/`Tank`, `Enemy.Tank`) 추가. 중간에 넣으면 저장된 튜토리얼·프리팹의 번호가 밀린다 |
| 컴파일러 | `BlockCoding/PythonTreeCompiler.cs` | `ValueType`에 `EnemyType` 플래그. `OutputSlot` = Value, `ArgumentCount(EnemyTypeOf)` = 1, `TypeOf`, `Expression`(`enemy.type`, `Enemy.Tank`), `ExpressionText`. 이름 목록 `EnemyTypes = { "Normal", "Fast", "Tank" }`(비교 기호 목록처럼). `==`/`!=`는 지금 아무 값이나 받는데, 종류와 숫자를 비교하면(`enemy.type != 3`) 컴파일 오류로 막는다 |
| 실행 | `Defense/DefenseProgram.cs` | `ValueKind`에 `Type`. `EnemyTypeOf` = 살아 있는 적의 `Spec.type`, 없는 적이면 None(어떤 종류와도 다름: `!=`가 True라서 `continue`). 비교의 `equal` 계산에 종류끼리 추가 |
| 블록 화면 | `BlockCoding/CommandBlockView.cs` | `EnemyTypeName`의 드롭다운을 비교 블록처럼 `EnemyTypes`로 채운다. `EnemyTypeOf`는 `hp`처럼 받는 쪽 칸 + `.type` |
| 팔레트 | `Editor/Defense/PaletteBlocks.cs` | 값 탭에 두 블록 추가(attack·비교 블록을 복사하던 방식) |
| 재고 | `Defense/DefenseProgression.cs`, `DefenseInventoryUI` | 소모 아이템이면 이름표(`Label`)와 인벤토리 칸을 늘린다(8차 142: 종류가 늘 때 칸이 모자라 예외가 났다) |
| 블록 도움말 | `Defense/DefenseBlockHelp.cs` | 두 블록 설명 |
| 답 해석기 | `Editor/Defense/TutorialAnswers.cs` | `enemy.type`, `Enemy.Tank` 읽기 |
| 검사 | `Tests/BlockCoding/TreeCheck.cs`, `Tests/Defense/WhileTrueCheck.cs` | 목표 코드 컴파일, 종류·숫자 비교 거부, 시뮬레이션에서 탱커만 쏘는지 |

만든 방식(위 계획과 다른 점):

- `enemy.type`은 따로 블록을 두지 않고 변수 블록의 `enemy.` 뒤 메뉴(`distance( / hp / is_dead() / type`)에서 고른다. 재고는 `hp`처럼 변수 블록 하나로 센다. `type`은 `Enemy.Tank` 블록을 받은 뒤에만 메뉴에 나온다(비교할 상대가 없으면 쓸 데가 없다). 메뉴는 이름으로 읽어서, 아직 안 받은 멤버가 빠져도 번호가 밀리지 않는다.
- `Enemy. [Tank]`는 값 탭의 새 블록(`BlockKind.EnemyTypeName`)이다. 비교 블록의 고르개만 남긴 복사본이고, 처음 고른 값은 `Tank`다(`PaletteBlocks.Add`). 인벤토리 칸도 하나 늘었다(`UIRequests9.InventorySlots`).
- 실행: 종류는 숫자(`EnemyType` 순서)로 비교하고, 없는 적의 종류는 -1이라 어떤 종류와도 다르다. 그래서 적이 없으면 `!=`가 참이 되어 `continue`한다.
- 블록 도감 항목은 없다(`is_dead()`·계산 블록도 아직 없다).

## 4. 팀 피드백

### 4-1. `Enemy . is_dead()` 블록을 점(.)으로 고르게

지금은 `+ Enemy .is_dead()`라는 논리 블록이 따로 있다. 팀 의견은 값 탭의 `enemy` 블록에서 점을 찍고 `is_dead()`를 고르면 논리 블록이 되게 하자는 것이다.

**권장 구조:** 변수 블록에 멤버 드롭다운(`없음 / .hp / .type / .is_dead() / .distance(…)`)을 단다. 무엇을 고르면 화면에서만 감싼다. 예를 들어 `is_dead()`를 고르면 코드 트리는 지금처럼 `IsDead(Variable)`이 된다. 컴파일러·실행·답 해석기는 그대로 둔다.

- 고른 멤버의 출력에 따라 모양과 색이 바뀐다. `is_dead()`는 논리, `hp`·`type`·`distance`는 값이다.
- 이미 칸에 꽂힌 블록은 그 칸에 맞는 멤버만 보여 준다. `if` 칸이면 `is_dead()`만 고를 수 있다.
- 받는 쪽은 변수만 된다. `get_nearest_enemy().is_dead()`는 막는다. 대상을 변수에 저장하고 그 상태를 본다는 2-5의 학습 목표와 맞는다.
- 재고: `is_dead()`가 재고에 있을 때만 그 멤버가 보인다.
- 고칠 곳:
  - `CommandBlockView`: 변수 블록의 드롭다운
  - `CommandDropZone`: 꽂힌 칸에 맞는지 검사
  - `TutorialSequenceBuilder`: `Editor.Palette.IsDead` 같은 포커스 키

### 4-2. 탭 색과 블록 색 통일

| 탭 | 탭 점 색 (`UITheme.BlockCategories`) | 블록 면 색 (`CommandBlockView.RefreshShape`) |
|---|---|---|
| 제어 | 파랑 `#2F7FD3` | 하늘 `#45B8E6`. 단, `break`·`continue`는 명령 분홍 |
| 명령 | **보라** `#8A5CE6` | **분홍** `#F76E91` |
| 값 | 주황 `#D9650B` | 노랑 `#FFC24D`. 단, `enemy = value`는 명령 분홍 |
| 논리 | **초록** `#2F9A57` | **보라** `#BA87F0` |

- **원인:** 탭 점은 탭 번호로 색을 고르고, 블록 면은 블록 모양(몸통·조건·값·명령)으로 색을 고른다.
- **고칠 방법:** 블록 종류에서 탭을 정하는 함수 하나(`BlockColors.Category(kind)`)를 두고, 탭 점과 블록 면이 같은 표를 쓰게 한다. 모양은 지금처럼 출력 칸 기준으로 둔다.
- **결정할 것:** `break`·`continue`는 제어 색으로, 변수 선언은 값 색으로 할지.

### 4-5. 2-5 `is_dead()` 소개 연출

미룬이 제안: A를 계속 쏴야 하는데, 쏘는 도중 B가 더 가까워져 과녁이 B로 바뀐다. 그래서 A를 못 잡고 코어 체력이 닳는다. 이 장면으로 `is_dead()`를 소개한다.

1. **실패 코드:** 매 발 가장 가까운 적을 쏜다.
   ```python
   while True:
       shoot(get_nearest_enemy())
   ```
2. **웨이브:**
   - A: 탱커병, 체력이 커서 한 발로 안 죽는다.
   - B: 속도병, A보다 조금 늦게 나와 로봇 가까이로 지나간다.
   - 미리보기가 이제 그 웨이브의 실제 적을 쓰므로(5절) 미리보기에서도 같은 장면이 나온다.
3. **고친 코드:** 저장한 대상이 죽을 때까지 쏜다.
   ```python
   enemy = get_nearest_enemy()
   while True:
       if enemy.is_dead():
           enemy = get_nearest_enemy()
       shoot(enemy)
   ```
4. 대사·녹음, 튜토리얼 시퀀스는 2-1·2-3처럼 `TutorialSequenceBuilder`에서 만든다.

| 적 종류·모습 | 항상 `enemies[0]`(일반병)과 그 프리팹 | 실제 웨이브의 적(정비 중이면 곧 싸울 웨이브, 전투 중이면 지금 웨이브: `CurrentWave`). 웨이브의 무리마다 한 마리씩 돌아가며 3마리를 고르고(무리가 더 많으면 무리 수만큼), 프리팹도 그 종류의 것 |
| 적 체력·속도 | 원본 asset 수치. 스테이지·웨이브 보정, 웨이브별 덮어쓰기, F2 창 값이 모두 빠짐 | 실제 웨이브와 같은 수치(`CurrentWave`의 보정된 값을 복사) |
| 적 공격력 | 0(무해) | 실제 값. 탱커형은 미리보기에서도 맞고, 버티지 못하면 쓰러진다 |
| 로봇 수치·레벨 | 실제 로봇의 `Spec`·레벨 | 그대로 |
| 로봇 체력 | 항상 최대 체력 | 실제 로봇의 지금 체력(지난 웨이브에서 다친 탱커형은 다친 채로) |
| 거리 수업 미리보기 | `Stage 1, 3번째 웨이브`(1-3)에 걸려 있었다. 거리 수업이 2-3으로 옮겨진 뒤로는(541ace7) 1-3 반복문 수업에 잘못 걸리고, 정작 2-3에는 없었다 | 2-3에 걸리게 고침. 적 한 마리가 사거리 밖에서 걸어 들어온다 |

고친 파일:

- `DefenseAttackPreview.ResetPreview`
- `DefenseSimulation.PreviewWave`(새 함수, 헤드리스 검사 `ProgramCheck.CheckPreviewWave`)
- `DefenseBattle.PreviewEnemy`(지움)

미리보기에서 그대로 남긴 것(연출이라 실제와 다르다):

- 일자 길과 로봇 위치. 원거리형 피해는 거리에 따라 달라지므로, 실제 맵과 거리가 다르면 피해 숫자도 다르다.
- 적 간격 1.4초.
- 보스 대기 없음: 앞의 적이 지나가면 보스가 영영 안 나와 시연이 멈추기 때문이다. 보스의 수치는 실제 값 그대로다.

이미 실제와 같던 것: 다음 웨이브 카드의 체력·속도(`group.Enemy`), 로봇 정보 카드(실제 로봇의 값).

## 6. 지금 원거리형 코드 쓰는 법

2-1·2-3 튜토리얼의 정답이다. 실제로 동작한다.

```python
while True:
    enemy = get_nearest_enemy()
    shoot(enemy)
```

가까이 왔을 때만 쏘기(2-3, 거리 3 안에서 최대 피해):

```python
while True:
    enemy = get_nearest_enemy()
    enemy_distance = enemy.distance(get_my_pos())
    if enemy_distance <= 3:
        shoot(enemy)
```

- 원거리형 수치: 사거리 7, 피해 32, 재장전 6초, 탄속 15.
- 피해는 사거리의 1/3(약 2.3) 안에서 최대 3배이고, 사거리 끝에서 1배다.
- 정보창 설명(`Defense/Data/Shooter.asset`)과 블록 도감의 shoot 설명을 실제 규칙(사거리의 1/3 안에서 최대 3배)으로 고쳤다. 도감의 "빈 대상 슬롯은 함수의 enemy를 사용" 줄(지금은 대상이 꼭 있어야 한다)은 "사거리 밖의 적은 빗나간다"로 바꿨다.
