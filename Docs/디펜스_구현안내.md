# 디펜스 구현안내

2026-09-22 · v0.12.1 · 로봇 버튼 기준 설명 위치

현재 요구사항은 [디펜스 기능서](디펜스_기능서.md)를 기준으로 한다. 과거 개발문서의 자동 행동·3웨이브·전투 중 편집 규칙은 아래 흐름으로 교체했다. 아래 수치는 상세 콘텐츠 기획 전의 플레이 검증용 임시 정책이다.

## 실행과 조작

1. Unity에서 `Assets/!_Project/Scenes/Defense.unity`를 열고 Play한다.
2. 하단 또는 `인벤토리`에서 보유 로봇을 선택하고 전장에 배치한다. 배치 성공 시 해당 로봇 아이템 한 개를 사용한다. 탱커는 적 경로 안, 나머지는 경로 밖의 허용 영역을 사용한다. 초록 사거리 표시는 배치 가능, 빨강은 불가다. 우클릭/ESC로 취소한다.
3. 설치한 로봇을 클릭한다. **새 로봇의 편집기는 비어 있다.** 블록을 추가·수정하면 문법과 재고 검사를 통과한 코드가 즉시 해당 로봇에 적용된다. 별도 적용 버튼은 없다. 최초에는 사수형에 `Attack()` 또는 전사형에 `slash()` 한 개를 연결하면 시작하기 쉽다.
4. `닫기` 또는 ESC로 닫는다. 인자가 비어 있거나 연결이 미완성인 수정은 마지막 유효 코드를 유지하며 상태에 표시한다. `비우기` 또는 마지막 블록 삭제는 빈 코드로 즉시 반영하고 예약을 해제한다.
5. `전투 시작` 또는 SPACE를 누른다. 로봇을 한 대 이상 배치하면 시작할 수 있다. 코드 없는 로봇도 전투 시작을 막지 않으며 전투 중 행동하지 않는다.
6. 전투 중 적 처치마다 랜덤 블록 한 개가 떨어진다. 보상 수량은 전투가 끝날 때까지 미수령 상태다. 일시정지/계속과 1x/2x를 사용할 수 있다. 전투 중에는 배치·회수·코드 편집을 잠근다.
7. 웨이브가 끝나면 보상을 수령한다. 다시 배치와 코드를 정비하고 직접 다음 전투를 시작한다. 5번째 보상 수령 후 승리하며 코어 HP 0이면 패배한다.
8. **F1**은 아이템 지급 화면을 연다. 로봇 6종·블록 전체 목록에서 항목을 클릭하고 양수 수량을 입력해 지급한다. 분류/이전/다음 버튼도 사용할 수 있다. 게임 규칙상 수량 상한과 기존 999개 지급 제한은 없으며, 저장형은 32비트 정수다. 정수 범위 초과 지급은 변경 없이 거부한다. 보상은 F1로 사용자 화면에 돌아와 수령한다.

로봇 카드는 클릭 후 전장 클릭 또는 전장으로 드래그해서 배치한다. 인벤토리에서 드래그하면 인벤토리가 닫힌다. UI 위·허용 영역 밖·겹치는 위치에 놓으면 수량을 사용하지 않고 취소한다. 드래그 뒤 클릭 이벤트가 중복 배치 모드를 시작하지 않도록 차단한다.

카메라는 명일방주 참고 이미지의 사선 구도를 반영한 원근 투영(48도 기울기)이다. 게임 규칙은 킹덤러쉬 참고의 거리 기반 XZ 자유 배치이며 타일 스냅을 사용하지 않는다.

전장에서는 **Tab**으로 인벤토리를 열고 닫는다. 인벤토리 버튼은 제거했다. 인벤토리가 열려 있는 동안 전장 배치와 SPACE 입력을 차단한다. 코드 편집 중에는 Tab으로 초안을 닫지 않는다. 개발자 모드에서 Tab을 누르면 사용자 인벤토리로 전환한다. 개발자 화면의 행동 선택·사거리 조절 버튼은 초기 시험용으로, 관련 UI 연결과 함께 제거했다.

상단바는 스테이지·`정비 중 / 전투 중`·웨이브·남은 적·시간을 가운데 정렬한다. 일시정지/계속과 배속 버튼은 상단바 아래 우측에 전투 중에만 표시한다. 일시정지 상태에서도 버튼을 유지한다. **F**는 1x/2x 배속을 전환하며 배속 버튼 아래에도 키를 표시한다. 좌측 상단 `다음 웨이브` 아래에는 등장할 적의 임시 이미지와 수량을 표시한다. 적 이미지 및 하단 로봇 카드에 포인터를 올리면 이름과 짧은 설명을 보여준다. 설명은 각 Definition 에셋에서 수정한다.

전장 하단의 회수 버튼과 선택 안내는 제거했다. 로봇을 선택하면 좌측 스탯 패널 우측 하단의 `회수` 버튼으로 로봇과 예약 블록을 반환한다. 회수 후 편집기를 닫고 전장 시점으로 돌아온다.

적 설명은 가리킨 적 이미지의 오른쪽에 상단을 맞춰 표시한다. v0.12.1부터 로봇 설명은 가리킨 선택 버튼의 위쪽 중앙에 12 UI 단위 간격으로 표시한다. 하단 목록과 인벤토리 모두 각 버튼의 RectTransform을 `DefenseHoverInfo.descriptionAnchor`에 연결한다. 마우스 좌표는 사용하지 않는다. 설명 패널이 화면 밖으로 나가면 화면 가장자리에서 12 UI 단위 여백을 남기도록 안쪽으로 보정한다. 이전 공통 위치용 `RobotDescriptionAnchor`는 제거했다.

보유 블록은 `while`, `get_pos_x()`, `get_pos_y()`, `get_nearest_enemy()` 등 코드 표기를 사용한다. 인벤토리 수량은 별도 오른쪽 열로, 편집기 팔레트 수량은 블록 폭과 무관한 공통 오른쪽 열로 정렬한다. 빈 조건·반복문 본문의 ‘명령을 넣으세요’ 안내문은 제거했다.

로봇 선택 시 왼쪽 1/4 영역의 상단 3/5는 실제 전장의 선택 로봇을 기존 사선 카메라로 보여준다. 하단 2/5의 스탯은 유지한다. 선택만 해서는 시험 적을 생성하거나 코드를 시연하지 않는다. 오른쪽 3/4는 블록 인벤토리와 코드 작업 공간이다. 상단 `미리보기` 버튼을 누르면 코드 패널 내부에 시연을 띄우고, `코드로 돌아가기`를 누르면 시연을 정리한 뒤 편집 내용을 그대로 보여준다. 이전 위치별 토글과 우측 하단 작은 시연은 숨겼다. 편집기를 닫으면 전장 시점으로 복귀한다. Python 미리보기 UI는 숨기고 생성·검증 스크립트는 유지한다.

시연은 **마지막으로 유효하게 적용된 코드**를 별도 `DefenseSimulation`으로 복사해 실행한다. 코드가 없으면 대기한다. 선택한 로봇 한 대와 임시 적 3마리로 최대 8초마다 반복한다. 중복으로 보이던 버프 확인용 아군은 제거했으므로 현재 버프 대상은 없다. 미리보기 상세 동작은 후속 기획에서 정한다. 임시 적은 실제 전장에 피해를 주지 않으며 실제 인벤토리·로봇 체력·쿨타임·드랍을 변경하지 않는다. 시연 카메라·UI·바닥은 씬에 저장되고, 시험 로봇/적만 연결된 기존 프리팹에서 생성한다. 렌더 텍스처는 첫 미리보기 때 할당하고 종료 때 해제한다.

블록을 끌 때 실제로 연결될 경계선 또는 비어 있는 매개변수 슬롯만 강조한다. 함수 패널 전체는 색을 바꾸지 않는다. 스냅 후보가 없거나 이미 채워진 슬롯에는 표시하지 않는다. 매개변수 입력은 가로 폭만 확장하고 명령 헤더와 인자 슬롯의 높이는 유지한다. 조건문 본문은 명령 수에 따라 세로로 늘어날 수 있다.

빈 작업 공간으로 명령을 끌면 첫 줄 연결선을 표시하며 그 위치에 배치한다. 기존 첫 줄 앞에 삽입하면 아래 흐름을 밀어내어 위쪽에서 잘리지 않게 한다. 팔레트 클릭은 기존 명령 끝에 실제 높이만큼 이어 붙인다. 값 블록은 먼저 빈 인자 슬롯을 선택해서 넣는다.

기존 코드 묶음은 함수 작업 공간 안에서 자유롭게 옮긴다. 전체 묶음을 옮길 때 빈 편집기의 최초 배치 규칙이 잘못 적용되어 첫 위치로 돌아가던 문제를 수정했다. 코드 블록을 우클릭하면 해당 블록과 내부 인자·본문을 삭제하고 뒤의 명령 연결은 유지한다. 입력칸·드롭다운 위에서도 우클릭 삭제를 전달한다. 수정 코드가 유효하면 즉시 적용하고 예약 수량을 반환하며, 미완성 코드는 기존 자동 적용 정책을 따른다.

탱커와 적의 체력바는 머리 위에 고정하고 카메라 회전을 따라 화면을 향한다. 채움은 왼쪽을 기준으로 HP 비율만큼 가로로 줄어든다. 일반 로봇에는 체력바를 표시하지 않는다.

기지에는 기존 체력 12를 연결한 체력바와 현재/최대 수치를 표시한다. 적 돌파 시 줄고 재시작하면 회복한다. 웨이브 종료 시 공격선·효과 원을 즉시 끄며, 전투 시간이 멈춰 이전 공격 표시가 남던 문제를 수정했다. 선택 사거리는 코드 편집 중에만 보이고 전장 정비 화면에는 남지 않는다.

v0.12에서는 기지 체력바를 기지 아래쪽으로 옮겼다. 씬의 `DefenseWorld/CoreHealth` 위치 `(11, 0.35, -8.5)`에서 전장 카메라를 향해 표시한다.

## 빈 로봇과 코드

- 배치 시 `Program=null`, 자동 실행 꺼짐, 몸 저지 꺼짐이다. 체력·배치 권한은 역할에 따라 유지하지만 능력은 코드로 실행해야 한다.
- 탱커는 `block()`을 실제로 실행하면 해당 웨이브의 몸 저지를 활성화한다. 범위 스턴은 시간제로 별도 관리한다. 코드 교체와 웨이브 준비 전환 때 저지 활성 상태를 해제한다.
- 전문 행동은 100%, 다른 직군의 `slash/Boom/Attack/slow`는 해당 전문 프로필 기준 효율 10%다. 피해와 둔화 강도를 줄이며, 행동 간격을 줄여 성능 감소를 상쇄하지 않는다.
- `slash()`와 `Attack()`은 호출이 실제 실행될 때 사거리 안의 유효 대상에게 즉시 피해를 준다. 이동 속도에 따른 회피·투사체 비행 판정이 없다.
- `Boom()`은 발사 순간의 적 위치를 향해 날아가는 비유도 투사체다. 발사 즉시 피해를 주지 않고, 도착 시 그 위치의 폭발 반경 안에 있는 적에게 각각 한 번 피해를 준다. 빠른 적이 반경 밖으로 이동하면 빗나가며 속도만으로 무조건 면역이 되는 것은 아니다. 비행 시간은 발사 거리 / `RobotSpec.projectileSpeed`이며 현재 속도는 4 월드 단위/초다. 폭탄형 폭발 반경은 기존 1.7이다. 피해·목적지·폭발 반경은 발사 시 확정한다. 다른 직군의 `Boom()`도 같은 투사체를 사용하며 피해는 10%다.
- 투사체는 전투 시간에 따라 움직이며 일시정지·배속을 따른다. 발사 로봇이 제거돼도 날아가던 투사체는 유지한다. 웨이브 종료·패배·재시작 시 남은 투사체는 제거한다. 제한 시간에 도달한 틱에서는 미착탄 투사체를 취소해 정리 중 드랍이 생기지 않는다.
- 폭탄형·사수형의 `block()`과 탱커의 `buff()`는 실행 불가다. 나머지 비전문 `block/buff` 조합은 승인되지 않은 상태라 효과를 내지 않는다. 블록 자체는 넣을 수 있다.
- 일반 로봇은 체력이 없고 탱커만 체력·피해·파괴를 사용한다. 버프형은 동시에 한 대만 배치할 수 있다.
- 코드는 끝까지 실행하면 다음 틱에 처음부터 반복한다. 변수는 호출마다 초기화하며 wait·반복문의 진행 상태는 틱 사이에 유지한다. 쿨타임 중에는 행동 명령에서 기다리고 대상 없음·불가·미정은 다음 명령으로 넘어간다.
- 로봇당 틱당 최대 64명령으로 무한 루프를 제한한다. 실행 오류는 해당 로봇만 정지시키며 상태에 오류를 표시한다.
- 숨겨진 Python 생성기와 실행은 같은 블록 트리를 사용한다. 임의 Python 문자열이나 외부 Python 프로세스 실행은 지원하지 않는다.

## 인벤토리·초기 아이템과 보상

로봇과 모든 종류의 블록은 수량을 가진 아이템이다. 인벤토리는 로봇의 배치 가능 수량과 블록의 사용 가능 수만 오른쪽에 표시한다. 최대 수량처럼 보이는 분모는 제거했다. 블록은 코드에 사용한 수량만 예약하며 보유 수량 검사 자체는 유지한다. 준비 중 로봇을 회수하면 로봇 아이템과 사용 블록이 반환된다. 탱커가 전투에서 파괴되면 로봇 아이템은 반환하지 않고 사용 블록만 반환한다. 배치 실패·취소는 수량을 변경하지 않는다.

초기 로봇: 버프형 1, 전사형 2, 탱커형 2, 폭탄형 2, 사수형 3, 유틸형 2로 총 12개다. 동시에 배치할 수 있는 상한은 기존 6대다.

| `slash()` | 2 |
| `block()` | 1 |
| `slow()` | 1 |
| `if`, `else` | 각 1 |
| `wait` | 6 |

| 변수 참조·거리 메서드 | 8 |
| 가까운 적, X 좌표, Y 좌표 | 각 4 |

초기 블록은 총 61개다. 행동·조건/반복뿐 아니라 숫자·값·변수·매개변수 내부 블록도 적용한 코드의 등장 횟수만큼 예약한다. 반복 실행마다 소모하지 않는다. 기존 `attack(enemy)`는 `Attack()` 재고를, 거리 메서드 모드는 변수 참조 재고를 공유한다. 거리 메서드의 암시적 수신자는 별도 블록으로 중복 차감하지 않는다. 편집기 배지는 현재 초안에서 추가로 쓸 수 있는 수량이며 0이면 새 블록을 꺼낼 수 없다.

코드 적용 시 다른 로봇이 예약한 블록을 제외하고 수량을 확인한다. 자기 기존 코드는 교체할 수 있다. 수량 부족·문법 오류는 적용 전 차단하므로 기존 적용본과 예약을 유지한다. 회수/파괴된 로봇의 예약은 보유함으로 돌아온다. 같은 유형 드랍은 수량으로 합산한다.

| 후보 추가 시점 | 종류와 상대 가중치 |
|---|---|
| 1웨이브부터 | Boom 3, slow 2, Attack 2, slash 1, if 1, else 1 |
| 2웨이브부터 | buff 2, block 1, for 1 추가 |
| 3웨이브부터 | while 1, elif 1, break 1, continue 1 추가 |

매 처치에서 현재 후보의 가중치 합을 기준으로 하나를 무작위 선택한다. 돌파는 드랍하지 않는다. 수령 전에는 편집에 사용할 수 없다. 버프/폭탄 등 초기 전문 블록이 없는 로봇은 보상을 얻거나 비전문 명령을 넣어 운용할 수 있다. 드랍 결과에 따라 특정 명령 획득 시점은 달라진다.

## 임시 난이도

코어 HP 12, 로봇 최대 6대, 전장 1개다. 배치 비용·재배치 대기는 없다. 준비 중 시간 제한은 없고 다음 전투는 자동 시작하지 않는다. 살아남은 탱커는 웨이브 보상 수령 후 최대 체력으로 회복한다. 파괴된 탱커는 자동 복구하지 않는다.

| 적 | HP | 이동 속도 | 탱커 공격 피해 | 외형 구분 |
|---|---:|---:|---:|---|
| 일반병 | 35 | 1.5 | 8 | 기본 외형 |
| 속도병 | 28 | 2.8 | 6 | 작은 보라색 몸체 |
| 탱커병 | 110 | 1.15 | 16 | 큰 파란색 몸체 |

기존 `Enemy.asset`·`Runner.asset`·`Heavy.asset`를 각각 위 명칭으로 사용한다. 속도병은 일반병보다 빠르고 체력이 낮으며, 탱커병은 느리고 체력이 높다. 수치는 상세 밸런스 기획 전 임시값이다.

| 웨이브 | 구성 | 수량 |
|---|---|---:|
| 1 | 기본 5 (2초 간격) | 5 |
| 2 | 기본 8 (1.7초 간격) | 8 |
| 3 | 질주 5 + 기본 4 | 9 |
| 4 | 중장 4 + 질주 6 | 10 |
| 5 | 중장 6 + 질주 8 + 기본 6 | 20 |

여러 그룹은 시간차를 두고 겹쳐 출현한다. 정확한 시작 지연·간격은 씬의 `DefenseBattle.waves`에서 조정한다. 기본 편성은 총 52마리이며 이월된 적은 별도로 추가된다. 적은 저지 중 탱커를 공격하고 스턴 중에는 이동과 공격을 멈춘다. 탱커 동시 저지 상한은 3이며 초과 적은 통과한다.

각 웨이브는 전투 시간 35초다. 일시정지하면 시간이 멈추고 2x에서는 실제 시간 17.5초가 된다. 예정된 적까지 모두 처리하거나 시간이 끝나면 보상 단계로 이동한다. 시간 종료 때 살아 있는 적과 미등장 예정 적을 기록하고, 처치·돌파·드랍 없이 제거한다. 다음 웨이브에는 그 수만큼 원래 적 종류·경로를 유지한 추가 그룹으로 등장한다. 추가 그룹 간격은 임시값 0.4초, 체력은 해당 적의 기본 체력이다. `WaveSurvivors`에 웨이브별 잔여 수를 보관한다. 5웨이브 종료 후에는 이월 없이 마지막 수만 기록한다. 코어 파괴는 시간 종료보다 우선한다.

상단에는 스테이지·웨이브·미등장 포함 남은 적·남은 시간·코어를 표시한다. 별도 편성 줄은 준비 중에는 이번 웨이브, 전투/보상 중에는 다음 웨이브를 종류별 수량으로 표시한다. 시간 종료 후 다음 편성에는 이월 수가 포함된다.

- v0.7의 시간 제한 도입 전 검증: 실제 씬 정의로 초기 블록만 사용한 6대 배치에서 5웨이브 총 52마리 처치·돌파 0 확인. 마지막 웨이브에서 탱커 1대 파괴, 최종 보상 수령 후 승리. 현재 20초 규칙의 밸런스 검증 결과는 아니다.
- 이전 5웨이브 검증에서 사용자 전투 시작·보상 수령 버튼 이벤트로 준비→전투→보상→다음 준비와 미수령 수량 0 전환을 확인했다. 당시 초기 블록 9개였으며 현재 초기 수량은 매개변수 아이템을 포함한 61개다.
- 스크립트 컴파일 성공, 필수 Inspector 참조 연결, Play Mode Console 오류 0건.
- v0.6: 실제 Tab 키 상태 입력으로 인벤토리 열기·닫기 확인. 사용자 전투 버튼 중앙의 Raycast 대상에 클릭 이벤트를 보내 코드 없는 로봇으로 Running 진입, 적 5마리 출현, 로봇 행동 0회 확인. 코드 적용 후 개발자 전투 버튼도 Running 진입 확인.
- 팔레트의 폭이 다른 6개 명령 블록 수량 오른쪽 좌표가 동일함을 확인했다. 빈 본문 안내문 0개, 삭제 대상 버튼 5개 제거, 필수 Inspector 참조 누락 0개를 확인했다.
- v0.7: Play Mode에서 빈 작업 공간 첫 줄 스냅 표시, 두 번 클릭한 명령의 즉시 연결·자동 적용·예약, 미완성 wait의 이전 코드 유지와 숫자 삽입 후 자동 적용, 조건문 뒤 추가와 첫 줄 앞 삽입을 확인했다. 체력 50%에서 채움 X 배율 0.5, 머리 위 높이 1.65, 카메라와 체력바 회전 차이 0도를 확인했다. 핵심 테스트 161개 통과, Console 오류 0건. 이 검증은 MCP 연결 부재로 Unity CLI의 동일 Pipeline 명령을 사용했다.
