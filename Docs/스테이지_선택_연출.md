# 스테이지 선택 연출

## 방향

새 섬의 테마와 모델은 유지하면서, 잠금 상태를 색·형태·큰 문구로 함께 전달한다. 디펜스의 `DefenseRangeRing`과 `DefenseBossAura`에서 사용한 발광 테두리와 시간 기반 맥동을 참고했다. 전투 중 피격용 글리치는 장시간 반복하지 않고, 잠긴 섬을 누를 때 짧은 경고 반응으로 표현한다.

## 상태별 표현

| 상태 | 섬 | 안내 카드 | 클릭 |
|---|---|---|---|
| 봉인·미정화 | 어둡고 채도가 낮은 모델, 정지한 허브, 붉은 주황색 장벽·경고 띠, 밝은 받침의 자물쇠 | **미정화 · 봉인 중**, `N스테이지 정화 후 개방` | 자물쇠 흔들림·장벽 경고색, 선행 스테이지 안내 |
| 개방·미정화 | 다소 어둡고 따뜻한 모델, 황색 상태 링, 봉인 없음 | **개방 · 미정화**, `도전해서 오류를 정화하세요` | 섬 내부로 가까이 내려가며 디펜스 진입 |
| 정화 완료 | 밝아진 모델, 녹색 외곽광·정화 영역·천천히 상승하는 입자, 정화 완료 표식 | **정화 완료**, `오류 제거 완료 · 다시 도전` | 동일하게 재도전 |

UI는 uGUI Canvas와 Pretendard TextMeshPro로 표시한다. Canvas Scaler는 **Scale With Screen Size**, 기준 해상도 **1920×1080**, Match Width Or Height **0.5**다. 기존 맵 Canvas와 씬 전환 페이드 Canvas도 같은 기준을 적용한다. 상태 문구는 기준 해상도에서 33px, 조건은 24px로, 1280×720에서는 각각 약 22px·16px다. 섬과 안내 카드는 동일한 입장 동작을 제공한다.

자물쇠는 **붉은 주황색 아이콘 + 밝은 회청색 받침**으로 구성한다. 밝힌 부분은 받침 배경이며 아이콘의 붉은 주황색을 유지한다. 해제 중에는 걸쇠가 열리며 황금색으로 변한다. 카메라가 봉인을 보여줄 때는 배지를 1.75배 확대한다.

## 클리어 → 정화 → 길 연결 → 봉인 해제

1. 처음 클리어하면 해당 섬의 정화 이벤트를 기록하고, 다음 섬이 잠겨 있다면 봉인 해제도 기록한다. 맵 복귀 시 한 번 소비하며 개발용 `Z`도 동일하게 동작한다.
2. 클리어한 섬에 낮은 각도로 가까이 내려간다. 카메라가 위로 상승하는 동안 녹색 스캔이 모델을 훑고, 어두운 모델이 밝게 변하며 정화 영역과 입자가 나타난다. **정화 완료** 표식을 보여준다.
3. 카메라가 높은 각도로 올라가 두 섬과 길을 보여준다. 백색·황금색 에너지가 실제 도로·연결 다리를 따라 이동한다. 카메라는 길의 에너지를 낮은 각도에서 추적한다.
4. 도착 직전 다음 섬으로 가까이 접근한다. 자물쇠 배지가 확대되어 열리고, 장벽이 아래에서 위로 해체되며 황금색 입자·파동이 퍼진다.
5. 개방된 섬을 잠깐 보여준 뒤 전체 지도 구도로 복귀한다. **새로 열린 섬은 미정화 상태**를 유지하고 클리어한 섬만 녹색 정화 표시를 갖는다. 전체 연출은 약 8초다.

진행 판정은 즉시 반영하되, 화면에서는 정화 전→정화 후와 봉인 전→봉인 해제를 순서대로 보여준다. 연출 중 중복 입력을 막고 이미 클리어한 섬은 반복 정화하지 않는다. 마지막 섬도 정화 연출을 재생하고 전체 정화 완료를 표시한다.

## 카메라

- 진입 시 0.85초 동안 전체 섬 구도로 부드럽게 안착한다.
- 선택 시 1.5초 동안 완만한 곡선 경로로 접근한다. 이동과 시선의 목표점을 함께 보간하고, 시작·종료 속도를 낮춘다.
- 일반 입장도 낮은 각도로 가까이 내려가는 접근을 사용한다. 도착 FOV는 34°, 내려다보는 각도는 28°이며 테두리 전체보다 섬 내부를 크게 보여준다.
- 연출은 낮은 정화 근접(28°) → 위로 상승(46°) → 두 섬 부감(58°) → 길 추적(34°) → 봉인 근접(26°) → 개방 확인(40°) → 전체 보기(42°) 순서다. 주요 모델 중심 영역의 경계와 화면 비율을 기준으로 거리를 계산한다.
- 접근이 끝난 뒤 기존 0.35초 페이드로 디펜스에 진입한다. 진입 중 중복 선택을 막는다.
- 전체 보기에서는 화면 비율이 바뀌면 다시 맞춘다. 장벽은 모델 경계 계산에서 제외한다.

## 구현과 확인

- `StageLockVisual.cs`: 장벽 메시, 테두리, 맥동, 클릭 반응과 런타임 리소스 정리.
- `StageLockBarrier.shader`: URP 투명 홀로그램, 스캔선과 경고 띠. Resources에서 로드해 플레이어 빌드에도 포함한다.
- `StageIslandView.cs`: 잠금 색·허브 회전, 연출 오브젝트를 제외한 모델 경계.
- `StageMapHUD.cs`: 1920×1080 Canvas Scaler, 상태 카드·자물쇠·추천 안내, UI 버튼.
- `StageMapController.cs`: 입력·상태 표시 연결과 해금 연출 순서.
- `StageUnlockEffect.cs`: 도로를 따르는 에너지, 도착 입자와 파동.
- `StagePurificationVisual.cs`: 올라가는 정화 스캔과 정화 후 유지되는 녹색 영역·입자.
- `StageProgress.cs`: 처음 클리어했을 때만 해당 섬 정화와 다음 섬 봉인 해제 이벤트를 기록.
- `StageCameraController.cs`: 전체 보기와 모델 크기에 맞춘 접근.

`DevTest.PlayStageMap()` 실행 후 `Tests/Unity/StageMapPresentationCheck.cs`를 Unity MCP `run_script`로 실행한다. 저장 데이터는 쓰거나 삭제하지 않으며, 세션 미리보기 상태는 검사 후 복구한다. 잠금 반응·해금 전환·장벽 경계 제외와 3개 화면 비율의 카메라 경로를 확인한다. 실제 진입은 섬 선택 → 접근 → 페이드 → Defense 순서로 별도 확인한다.

입력 검사는 새 Stage Play 세션에서 `Tests/Unity/StageMapInputCheck.cs`의 `StageMapInputCheck.Begin`을 `run_script`로 실행하고, `Temp/StageSelection/input-check.txt`를 확인한다. 명령이 반환된 뒤 게임 프레임이 진행되면서 검사한다. 임시 입력 설정과 마우스는 끝나면 복구한다.

2026-11-02 확인: Unity 컴파일·셰이더 오류 없음. 세 섬 × 세 화면 비율 × 21개 이동 지점(189개)에서 선택한 섬이 화면 안에 유지됨. 입력 이벤트로 잠긴 섬 클릭 차단·선행 조건 안내·상태 카드 선택·카메라 완료 후 페이드와 Defense 진입 통과.

해금 검사는 Stage Play에서 `Tests/Unity/StageUnlockCheck.cs`의 `StageUnlockCheck.Begin`을 실행한 뒤 `Temp/StageSelection/unlock-check.txt`를 확인한다. 저장 데이터를 수정하지 않고 세션 미리보기만 사용해 정화→길 이동→봉인 해제의 순서, 정화 후 남는 녹색 영역, 마지막 섬 정화, 입장 차단과 중복 재생 방지를 검사한다. `purification-sweep.png`, `purified-overview.png`, `unlock-route.png`, `unlock-open.png`에 장면을 남긴다.

추가 검증 완료: 모든 맵/페이드 Canvas Scaler의 1920×1080 기준, 3개 화면 비율의 해금 경로·접근·복귀 구도, 씬 재진입 시 한 번만 재생, 실제 UI 버튼 입력, 두 구간(1→2·2→3) 해금과 이펙트 정리. 도로 위 에너지는 섬 기준 높이 0.48에서 이동해 부유하는 도로 표면에 가리지 않도록 했다.

정화 개편 검증: 정화 스캔이 회로 이동보다 먼저 완료되고, 다음 섬이 열린 뒤에도 미정화로 남는지 확인했다. 정화된 섬의 녹색 영역 유지·마지막 섬 단독 정화·밝은 자물쇠 받침과 붉은 주황색 아이콘·카메라 상승 구도·3개 화면 비율의 근접 중심 영역·189개 입장 이동 지점을 확인했다.
