## 1. 한 줄 요약

기획 대본 정리, 구현 설계, 튜토리얼이 기대는 게임 규칙 변경, **인터페이스·뼈대(§3)** 까지 끝났다. **튜토리얼 진행 로직(Director 연결)과 1-1·1-2 데이터, 씬 배선은 아직이다.** 튜토리얼은 지금 Defense 씬에서 연결 해제된 상태다.

## 3. 인터페이스·뼈대

W2(진행 로직)와 W3(UI·씬)가 동시에 작업할 수 있도록 계약을 코드로 고정했다. 이름은 반드시 아래 상수를 쓴다.

### 3-1. 공용 이름 — `Tutorial/TutorialSignals.cs`

| 클래스 | 내용 |
|---|---|
| `TutorialSignals` | 신호 이름: `TargetClicked`, `RobotPlaced`, `EditorOpened`, `EditorClosed`, `BattleStarted`, `PreviewHit`(게임이 보냄) / `FirstKill`, `Leak`, `WaveCleared`, `ProgramMatches`(감시기가 만듦) / `SystemSpeaker = "시스템"` |
| `TutorialKeys` | 대상 키: `Battle.Start`, `Battle.Develop`, `Battle.DeploymentArea`, `Robot.Selected`, `Editor.ProgramDropZone`, `Editor.BlockPalette`, `Editor.Close`, `Editor.RestoreAutomatic`, `Editor.Hint`(신규), `Editor.Preview`(신규), `RobotButton(i)` |

### 3-2. 데이터 — `Tutorial/TutorialSequence.cs` (asset 입력 칸)

| 필드 | 용도 |
|---|---|
| `TutorialText.speaker` | 대화창 하나마다 발화자. `시스템`이면 경고 배너 |
| `TutorialStep.trigger` | 이 신호가 올 때까지 단계를 숨기고 대기(`FirstKill`, `WaveCleared`, `EditorClosed` 등) |
| `TutorialStep.expectedCode` | `ProgramMatches` 판정용 정답 Python |
| `TutorialStep.pointerKey` | 화살표를 띄울 대상 키 |
| `TutorialStep.pointerDelay` | 이 시간(초) 안에 완료하지 못하면 화살표 표시(1-2 힌트 = 60) |
| `TutorialStep.hintCode` | 힌트 버튼에 보여 줄 코드. 비우면 힌트 버튼 숨김 |
| `TutorialStep.closeEditor` / `clearProgram` | 단계 진입 시 편집기 닫기 / 교육 로봇 코드 비우기 |

기존 `TutorialSequence.speakerName`은 `speaker`가 비었을 때의 대체값으로 남겨 두었다(옛 경로 호환). W1에서 지운다.

### 3-3. 동작하는 부품

| 파일 | 공개 API | 상태 |
|---|---|---|
| `Tutorial/TutorialWatcher.cs` (순수 C#) | `Poll(sim, expectedCode)` → 지난 호출 이후 생긴 신호 목록. `TeachingRobot(sim)` = 이 스테이지에서 처음 배치한 전사. `Matches(program, expected)` = 머리줄·들여쓰기·빈 줄 무시 비교 | 구현·검사 완료 |
| `Tutorial/TutorialPointer.cs` | `Show(Rect)`, `Hide()`, `IsVisible` — 대상 위에서 위아래로 움직이는 화살표 | 구현 완료, 프리팹 없음 |
| `Tutorial/TutorialSystemAlert.cs` | `Show(string)`, `Hide()`, `IsShowing` — 배너 + 경고음, 1.5초 후 페이드 | 구현 완료, 씬 배치 없음 |
| `TutorialInputBridge.TryGetArea(key, out Rect)` | 대상의 화면 사각형(스포트라이트 기준). 화살표 위치용 | 구현 완료 |
| `TutorialDialogueView.Show(..., speakerName)` | 발화자를 대사마다 받음. `TutorialDirector`가 `TutorialText.speaker`를 넘김 | 구현 완료 |
| `DefenseCodeEditor.SetHint(string)` | 힌트 버튼 표시·내용 설정. 버튼 클릭 시 `Editor.Hint` 허락 확인 후 팝업 토글, `TargetClicked` 보고 | 구현 완료. 버튼·팝업 참조는 **선택 항목**(씬에 연결 전에는 아무 일도 안 함) |
| `DefenseAttackPreview` | 미리보기 적중 시 `Editor.Preview` / `PreviewHit` 보고 | 구현 완료 |

### 3-4. W2가 `TutorialDirector`에 해야 할 일

1. 매 프레임 `watcher.Poll(battle.Simulation, 현재 단계.expectedCode)`를 호출하고, 결과 신호를 현재 단계의 `completionSignal`·`trigger`와 비교한다. 감시기는 웨이브 시작 전부터 계속 호출해야 한다(첫 호출 시점의 처치·누출 수를 기준으로 삼음).
2. `trigger`가 있는 단계는 신호가 올 때까지 대화창을 숨긴다.
3. 발화자가 `TutorialSignals.SystemSpeaker`면 `TutorialSystemAlert.Show(text)`, 끝나면 자동 진행.
4. 단계 진입 시 `closeEditor` → `DefenseCodeEditor.Close(false)`, `clearProgram` → 교육 로봇 코드 비우기, `hintCode` → `SetHint`, 단계 종료 시 `SetHint(null)`.
5. `pointerKey`가 있으면 `pointerDelay` 뒤 `bridge.TryGetArea` → `TutorialPointer.Show`, 단계가 바뀌면 `Hide`.
6. 대상 소실 검사는 행동을 기다리는 단계에만 적용.
7. `StageOneTutorial` 위임 분기 삭제(W1과 함께).

### 3-5. W3가 씬에서 해야 할 일

1. 스포트라이트 아래에 `TutorialPointer`(가운데 앵커, 화살표 이미지) 배치.
2. `TutorialSystemAlert`: 기존 부팅 오버레이(`boot`·`bootFade`)와 경고음(`warningSource`)을 재사용해 연결, 문구용 TMP 추가.
3. 코드 편집기 '비우기' 오른쪽에 힌트 버튼·팝업·문구 추가 후 `DefenseCodeEditor`에 연결.
4. `TutorialInputBridge.targets`에 `Editor.Hint`, `Editor.Preview` 키 추가.
5. 위 참조를 `TutorialDirector`에 넘길 필드는 W2와 합의해 추가.

## 7. 알아 둘 점

- **대본은 원문 그대로다.** 대본 문서에서 `[ID]`와 `▶` 줄을 빼면 기획 원본과 같다(줄 단위 비교로 확인). 승인된 수정은 1-2 B05의 `.distance(get_my_pos())` 1건뿐이다. 문장을 고치고 싶으면 기획 승인을 먼저 받는다.
- **튜토리얼은 연결 해제 상태다.** Defense 씬의 `DefenseBattle.tutorial`이 비어 있고 `TutorialSystem`·`TutorialOverlay`가 꺼져 있다. 다시 연결하면 지금은 옛 `StageOneTutorial`이 동작하므로, W1 전에 연결하지 않는다.
- **`Docs/튜토리얼.md`는 옛 시나리오 문서다.** W1 때 새 구조 설명으로 교체.
- **함수 실행 횟수는 웨이브마다 초기화된다.** 보상 수령 시 프로그램을 새로 만든다(`ResetPrograms`). 코드 내용은 유지된다.
- **베기(`slash`)는 범위 공격이다.** 사거리 안 앞쪽 적을 모두 맞힌다. 적이 겹치면 5회보다 적게 써도 된다.
- **질 수 없는 구간이다.** 기지 12, 적 2마리라 전부 새도 통과한다. 학습 확인은 프로그램 일치 판정이 맡는다.
- **미리보기는 실제 전투와 한도가 다르다.** 미리보기는 무제한, 실제 전투는 5회. 로봇 정보창은 실제 기준(`함수 n/5회`)을 보여 준다.
- **회수 잠금은 Stage 1 웨이브 1·2만**이다. 개발용 시작(`PlayerFlow` 아님)에는 걸리지 않는다.
- **씬 파일 편집은 Unity에서.** 이번 작업은 Unity 연결 없이 해서 씬·프리팹을 건드리지 않았다.
