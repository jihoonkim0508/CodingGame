2026-10-23. 기준 원본은 [최신 Stage 1 대본](flow_stage1/tutorial_stage1_대본.md)과 해당 문서가 참조하는 [임시 변경 기록](임시변경점.md)이다. 2026-10-15 인계서는 과거 스냅샷이다.

## 이어받은 지점과 방향

작업 전 시퀀스는 1-1~1-4 네 개였다. 1-4 종료 시 전사 두 대가 각각 아래 조건 코드를 갖는다. 1-5와 Stage 2에는 튜토리얼 시퀀스가 없었다. 기존 Stage 2 보급은 2-1에 for, 2-4에 elif/else를 지급했으나, 의도한 조건 복습→반복→반복+조건 순서에 맞춰 이번 구간만 수정했다.

기존 대사 1-1~1-4와 최신 연출(흑백 도입, 시안 집중, 빨간 사거리, 코드 미리보기, 드래그 시연, 자유 작성 시 대사 숨김)은 유지한다. 코드로 스탯을 바꾸지 않는다. 전사와 slash, get_my_pos, enemy.distance, my_attack_range를 계속 사용한다.

## 학습 구성

| 웨이브 | 직접 할 일 | 정답 |
|---|---|---|
| 1-5 | 두 로봇의 기존 조건 코드 점검, 보스 전투 | 조건 코드 |
| 2-1 | 새 스테이지에 전사 배치, 조건 코드 재작성 | 조건 코드 |
| 2-2 | for 시작 위치·안쪽 연결 학습, 적 탐색과 공격 반복 | 5회 반복, 조건 없음 |
| 2-3 | 반복 횟수를 10으로 변경, 반복마다 대상 갱신 | 10회 반복, 조건 없음 |
| 2-4 | 반복 안에서 거리 계산·조건 검사 | 10회 반복 안에 조건 코드 |
| 2-5 | 두 번째 전사 배치, 각 로봇의 반복+조건 코드 완성 | 두 로봇 모두 2-4 코드 |

조건 코드:

```python
enemy = get_nearest_enemy()
enemy_distance = enemy.distance(get_my_pos())
attack_range = my_attack_range()
if enemy_distance <= attack_range:
    slash(enemy)
```

2-2/2-3은 `for i in range(5):` 또는 `range(10)` 안에 `enemy = get_nearest_enemy()`와 `slash(enemy)`를 연결한다. 2-4/2-5는 위 조건 코드 전체를 `for i in range(10):` 안에 연결한다.

후속 대본은 [tutorial_stage2_대본.md](flow_stage2/tutorial_stage2_대본.md)에 있다. 기획 원문이 없는 구간을 새로 작성한 것이며, 기존 대본과 구분해 관리한다.

## 진행과 보급

정답 전에는 닫기·ESC를 막는다. 힌트 버튼에 정답을 표시하고 60초 뒤 화살표를 띄운다. 실제 블록 조립은 플레이어가 한다. 첫 공격/웨이브 종료 신호를 기다리고 보상 수령까지 안내한다. 이미 정답인 코드는 자동 인정한다.

2-1과 2-5에 전사 한 대와 조건 코드 한 벌(변수 선언 3, 적 탐색 1, 변수 4, 위치 1, 사거리 1, if 1, 비교 1, slash 1)을 지급한다. 2-2와 2-5에 for 1, 숫자 1을 추가 지급한다. 1-5와 2-1~2-5의 종료 보상은 숫자 1이다. 2-1 종료 보상에 for를 주지 않아 2-2 준비 때 처음 반복문이 해금된다.

Stage 2는 기존 오류 코드 2/3/4/4/6마리, 출현 간격 0.4초, 제한시간 120초다. 간격을 좁혀 유한 반복이 적 사이의 긴 공백에 소진되는 부담을 줄인다. 기존 스케일링·공격 타이밍·코어 생존 통과 규칙은 유지한다. 1-5 보스 편성은 기존 값이다.

## 구현과 재생성

- `TutorialSequenceBuilder`의 partial 파일 `TutorialContinuationBuilder.cs`가 후속 6개 시퀀스와 보급·편성을 만든다. Director 런타임은 기존 것을 사용한다.
- 메뉴 **Tools > Develop > Stage 1~2 튜토리얼 asset 다시 만들기**. Defense 씬을 연 Edit Mode에서 실행한다. 기존 Stage 1 메뉴도 같은 전체 재생성을 실행하므로 후속 연결을 지우지 않는다.
- Stage1 폴더에 1-5, Stage2 폴더에 2-1~2-5 asset을 생성하고 씬에 총 10개를 연결한다.
- `TutorialAnswers.Parse`는 for와 숫자·중첩 if를 지원한다.
- 반복문 정답 판정은 변수 이름 변경은 허용하되 순서·중첩을 검사한다. 적 탐색·거리 계산이 반복 밖인 코드는 통과하지 않는다. 기존 Stage 1 판정 호환은 유지한다.
- 개발 API `DevTest.JumpTutorial(stage, wave, step)`, `TutorialSections(stage, wave)` 추가. 예: `DevTest.JumpTutorial(2, 4, 0)`. 기존 두 인자 JumpTutorial은 Stage 1 호환용이다. 중간 진입 시 해당 스테이지 앞 웨이브의 로봇과 코드를 복원한다.
- 스테이지 선택을 통한 실제 새 스테이지 진입은 새 세션이다. 개발 도구의 `ContinueCampaign`는 기존 세션을 유지하므로 연속 QA는 Stage 1 종료 뒤 `PlayDefense(2,1,true,true)`로 실제 새 세션 진입을 재현한다.

## 검증

- Unity 컴파일 오류 없음.
- `dotnet run --project Tests/Tutorial/Tutorial.Check.csproj`: 정답 파싱·변수명 변경·반복 횟수·중첩 오류 거부 20개 통과.
- `dotnet run --project Tests/BlockCoding/BlockCoding.Check.csproj`: 통과.
- 후속 Play Mode 검사는 `DevTest.PlayDefense(1,5,true,true)` 후 `Tests/Unity/TutorialContinuationCheck.cs`의 `Start`를 MCP run_script로 실행한다. 결과는 `TestResults/tutorial-continuation.txt`. 백그라운드 실행을 켜고 실제 UI 진입점·재고 제한을 사용한다. 블록 로드는 검사 편의를 위한 API 호출이며 마우스 드래그 QA는 별도다.
- 기존 Defense 전체 검사는 원거리 공격 즉시 피해를 기대하는 `Check.cs:91`에서 실패한다. 최신 공격 지연 변경(임시변경점 §20)과 맞지 않는 기존 검사이며 이번 범위에서 전투 규칙을 되돌리지 않았다.
